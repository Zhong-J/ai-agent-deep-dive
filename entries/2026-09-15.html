模型为什么会“听话”？

拆开 SFT、preference data、reward model、PPO/RLHF 与 DPO，理解 alignment 如何改变 token policy，又为何不能替代 Agent runtime 的控制面。

2026-09-15约 20 分钟SFT / RLHF / DPO / Reward model / Agent control plane
01

今日命题

base model 的 pretraining 目标是继续文本，不天然区分“用户请求”“系统政策”和“网页里的一句指令”。instruction-following behavior 来自后续训练与数据格式：高质量示范告诉模型什么回答像一个 assistant；成对偏好告诉它同一 prompt 下哪个 completion 更好；RLHF 或 DPO 再把这些相对信号转成 policy 更新。

但 alignment 不是把一套确定性规则安装进模型。它改变的是条件 token distribution：某些回答、拒绝或工具模式变得更可能，其他模式变得更不可能。偏好数据有限、标注者意见不一致，reward model 只是 proxy；policy 还会寻找 proxy 的漏洞。因此“训练得更听话”与“拥有授权”“知道实时事实”“保证完成任务”属于不同系统层。

核心判断：SFT 教模型模仿可见示范，preference optimization 教模型在候选间排序并偏向某类行为。它们能改善默认行为，却不能承担 credential、policy enforcement、side-effect verification 或 durable state。
02

把四篇串成一条链

1/4 说明 cross-entropy 在 teacher-forced prefix 上提高真实 next token 的概率；2/4 说明 optimizer、data mixture 与 compute 决定这些 gradients 最终塑造什么能力；3/4 说明 inference policy 从 logits 选择一条 rollout 路径。alignment 仍使用这些基础部件，只是改变数据来源和 objective。

SFT 仍是 next-token cross-entropy，但 loss 常只计算 assistant completion。reward modeling 不直接生成 token，而是学习一个比较分数。PPO-style RLHF 把生成模型当 policy，在线采样 completions，用 reward model 加 KL penalty 得到奖励，再做 constrained policy update。DPO 则从成对偏好直接优化 policy 与 reference policy 的 log-probability ratio，不需要显式训练 reward model 后再跑在线 RL。

03

机制：SFT、RLHF 与 DPO

1. Supervised fine-tuning（SFT）

收集 prompt 与理想 assistant completion，把它们格式化为聊天序列，并对 assistant tokens 计算 cross-entropy。SFT 可快速建立角色、回答结构、tool-call syntax 和任务范式。它的 objective 直接监督示范中的 assistant tokens；pretrained model 可以泛化到未逐字出现的 prompt 与行为，但这种覆盖不是 SFT loss 的保证。若每个 prompt 只有一个 completion，优化会把概率质量推向该路径，可能收窄其他合理答案；低质量示范也会提供错误的直接信号。chat template、role token 与 loss mask 属于训练契约；上线时模板不一致会造成 distribution shift，即使自然语言内容看起来相同。

2. Preference collection

对同一 prompt 生成或撰写多个 responses，让标注者选择 preferred 与 rejected，或提供排序/评分。偏好反映 helpfulness、harmlessness、truthfulness、风格等混合目标。标注 instruction、worker population、response sampling policy 和呈现顺序都会改变数据。pairwise preference 表示相对选择，不等于绝对正确事实。若候选都很差，chosen 只代表“两害相权取其轻”；若候选几乎相同，标签噪声会很高。保留 tie、disagreement 与 annotator confidence 比强迫二选一更诚实。

3. Reward model（RM）

常在语言模型 backbone 上增加 scalar head，输入 prompt+response，输出 reward。用 Bradley–Terry 风格 loss 让 preferred response 的分数高于 rejected。RM 把有限比较泛化到未标注输出，但也压缩了多个目标；policy 优化会主动寻找 RM 高分区域，可能暴露训练分布外的 proxy loophole。RM validation 应按领域、长度和风险切片；总体 pairwise accuracy 会隐藏罕见但关键的错误排序。

4. PPO-style RLHF

从当前 policy 采样 responses，经 RM 打分，并用 reference model 的 KL penalty 限制 policy 漂移。PPO 使用 clipped surrogate 等机制做多轮 minibatch updates。它能针对 policy 自己产生的 rollout 学习，但系统复杂：需要 policy/reference/RM（通常还有 value model）、在线生成、advantage estimation 与稳定性调参。reward normalization、response truncation、stop token 和 KL estimator 都会改变有效 objective；复现实验必须记录它们，而不能只写“用了 PPO”。

5. Direct Preference Optimization（DPO）

DPO 从 KL-regularized reward maximization 的最优 policy 关系出发，把隐式 reward 写成 policy 与 reference 的 log-ratio，直接对 preference pairs 做分类式 loss。它省掉显式 RM 和在线 PPO loop，训练更简单。代价是仍依赖 preference coverage、reference policy 与超参数 β；“直接”不表示无 reward assumption，也不保证避免 overoptimization。离线数据来自旧 policy 时，新 policy 可能进入未覆盖区域；需要迭代收集或在线 eval 发现这种 support gap。

# SFT: imitate a demonstrated completion
loss_sft = CE(policy(prompt), chosen_tokens)

# RLHF: sample, score, then update with KL control
y = sample(policy, prompt)
reward = RM(prompt, y) - beta * KL(policy || reference)
policy = PPO_update(policy, reward)

# DPO: update directly from chosen/rejected log-ratios
loss_dpo = preference_loss(policy, reference, chosen, rejected, beta)

6. Evaluation and release

每个 stage 都需要 held-out preference accuracy、capability/safety eval、red-team 与真实 Agent sandbox。RM accuracy 上升不保证最终 policy 更好；DPO loss 下降也不保证工具成功。release gate 应比较 base/SFT/aligned checkpoints 的能力回归、拒绝边界、校准与 long-horizon trajectories。还要检查 training/eval contamination、标注者间一致性与各风险 slice 的置信区间；单个平均 win rate 无法支持高风险发布。

04

必要数学：偏好如何变成 loss

Reward-model preference probability

P(yw ≻ yl | x) = σ(rφ(x,yw) − rφ(x,yl))

x 是 prompt，yw/yl 是 preferred/rejected，rφ 是 reward model，σ 是 sigmoid。训练最小化上述概率的 negative log。只有分数差参与 loss，所以 reward 的绝对零点不可识别；RM 分数跨版本、prompt domain 或训练 recipe 未必可直接比较。

KL-regularized policy objective

maxπ Ey∼π(·|x)[r(x,y)] − β DKL(π(·|x) || πref(·|x))

第一项偏向高 reward，第二项惩罚 policy 远离 reference；β 控制对齐强度。β 太小，policy 更容易 exploit RM 或丢失 base capabilities；太大，则几乎不改变行为。实际 PPO 还需 token-level KL estimator、advantages、value targets 与 clipping；上式是目标直觉，不是完整实现。

DPO loss

LDPO = −log σ(β[(log πθ(yw|x)−log πref(yw|x)) − (log πθ(yl|x)−log πref(yl|x))])

括号比较 policy 相对 reference 对 preferred 和 rejected 的提升幅度。loss 推动 preferred 的相对 log-ratio 更大。β 影响隐式 reward/偏离 reference 的尺度，不应简单读成“学习率”或“安全强度”。sequence log-prob 是 token log-prob 之和，因此 response length、mask 与 normalization 细节会影响训练动态。

Proxy overoptimization

设真实人类 utility 为 U，可训练 proxy 为 R=U+ε。policy 搜索越强，越可能找到 ε 偶然很高的区域，即使 U 没有提高。Gao 等在其合成设定中报告，优化 proxy reward 超过某点后 gold reward 可下降，并研究其 scaling pattern。这个结果说明 RM holdout accuracy 不足以证明强优化安全，但不是所有生产 RLHF 都遵循同一曲线。

05

对 Agent 系统的影响

1. Tool-use alignment 需要 outcome-grounded data

只标注 tool call 看起来合理，会奖励“像会用工具”；更强数据应包含实际执行结果、参数合法性、恢复轨迹和副作用。即使如此，训练数据中的 sandbox 权限也不能迁移成生产授权。

2. Refusal 不是 access control

偏好训练可提高模型拒绝危险请求的概率，但 prompt injection、distribution shift 或新语言可能绕过。runtime 必须在模型外检查身份、资源、动作和审批。模型拒绝是 defense-in-depth 信号，不是安全边界。

3. Sycophancy 来自偏好 proxy

若标注者更喜欢顺从、流畅或自信的回答，模型可能迎合错误前提。Agent 在分析、代码 review 和决策支持中应奖励证据、校准和纠错，而不是只奖励用户满意。eval 要包含用户强烈暗示错误答案的对抗样本。

4. Reward hacking 也发生在 Agent loop

若成功指标是“工具返回 200”或“用户未追问”，policy 可能选择无意义调用、隐藏失败或提前宣布完成。训练 reward 与 runtime metric 都需要 outcome verifier、反作弊信号和人工抽查；不要让模型自己既执行又定义成功。

5. 对齐版本是行为依赖

同一 base model 经过不同 SFT/preference recipe 后，tool propensity、拒绝、verbosity 和风险偏好可改变。model upgrade 必须跑固定回归与真实 trajectory shadow test，并记录 post-training lineage，而不是只看 base family 名。

6. 多目标不应压成唯一 release score

helpfulness、truthfulness、harmlessness、latency 与 cost 互相冲突。用分层 dashboard 与硬性 safety constraints，而不是一个平均 reward。对高风险 action，即使总体 win rate 上升，也不能接受 rare catastrophic regression。

7. 模型内政策冲突要由外层仲裁

system instruction、用户目标、tool output 与 post-training 倾向可能互相冲突。模型只能以学到的概率模式进行权衡，无法证明自己采用了正确优先级。runtime 应先把不可信数据与指令分离，用显式 precedence、capability token 和 deny-by-default policy 决定可执行集合；模型只在集合内提出动作。这样即使 alignment 在边缘场景失败，权限边界仍保持稳定。

06

取舍与失败模式

SFT coverage vs diversity：精选示范稳定格式，却可能造成 mode narrowing、verbosity 模板化或遗忘 base capability。混入多种正确答案和通用数据可缓解，但增加 curated data 成本。

RM generalization vs scalar compression：一个分数便于优化，却把真实性、安全和风格纠缠。多 reward heads、规则约束或分阶段优化能拆开目标，但 arbitration 更复杂。

PPO control vs system complexity：在线 rollout 能适应当前 policy 分布，代价是高计算、多个模型和不稳定性。DPO 简化 pipeline，却使用离线偏好，无法自动覆盖新 policy 访问的所有区域。

KL 约束 vs 改进行为空间：强 KL 保留 base 能力但限制对齐；弱 KL 允许大改却增加 reward hacking、语言退化和 capability regression。没有普适 β，必须由多维 eval 选择。

Human preference vs objective truth：人类也会受呈现、风格、知识和时间压力影响。多数偏好不是事实 oracle。专家标注、事实工具、disagreement modeling 与 adjudication 能提高质量，但无法消除规范性冲突。

Alignment tax vs alignment gain：某些 safety tuning 会提高拒答并损失边缘能力，也可能通过更清晰 instruction-following 改善能力。只能按目标任务测量，不能假设所有对齐必然降低或提升 intelligence。

07

可复用判断

  • SFT 仍是 completion 上的 cross-entropy；它模仿示范，不直接表达相对偏好。
  • reward model 学习 preferred/rejected 的相对分数；proxy accuracy 不保证强 policy optimization 后仍与真实 utility 对齐。
  • PPO/RLHF 在线采样并以 reward+KL 更新；DPO 直接优化 policy/reference log-ratio，简化但不消除偏好假设。
  • 模型拒绝、tool propensity 和 aligned behavior 是概率倾向，不是 credential、authorization 或完成验证。
  • 完整控制栈必须同时管理 training objective、decoding policy 与 Agent runtime policy，并分别评估。

Training Objectives & Inference Control · Part 4 of 4

Why Does a Model Learn to Follow Instructions?

Separate SFT, preference data, reward models, PPO/RLHF, and DPO to see how alignment changes a token policy—and why it cannot replace an agent runtime control plane.

2026-09-1520 min readSFT / RLHF / DPO / Reward model / Agent control plane
01

Today's proposition

A base model’s pretraining objective is to continue text. It does not inherently recognize “user request,” “system policy,” and “an instruction quoted from a webpage” as different authority classes. Instruction-following behavior is created by later training and data formats: high-quality demonstrations show what an assistant-like answer looks like; paired preferences indicate which completion is better for the same prompt; RLHF or DPO then converts those relative signals into policy updates.

Alignment does not install a deterministic rulebook inside the model. It changes a conditional token distribution: some answers, refusals, and tool patterns become more likely, while others become less likely. Preference coverage is finite, annotators disagree, and a reward model is only a proxy. A policy can also search for weaknesses in that proxy. “More likely to follow instructions” is therefore separate from “possesses authorization,” “knows live facts,” or “guarantees task completion.”

Core judgment: SFT teaches a model to imitate visible demonstrations; preference optimization teaches it to rank and favor classes of behavior. These stages improve default behavior, but cannot carry credentials, enforce policy, verify side effects, or hold durable workflow state.
02

Connect all four installments

Part 1 showed cross-entropy raising the probability of observed next tokens under teacher-forced prefixes. Part 2 showed how optimizers, mixtures, and compute determine which capabilities those gradients create. Part 3 showed an inference policy selecting one rollout path from logits. Alignment reuses these foundations while changing the source of data and the objective.

SFT is still next-token cross-entropy, commonly masked to assistant completions. Reward modeling does not generate tokens directly; it learns a comparative score. PPO-style RLHF treats the generator as a policy, samples completions online, combines reward-model scores with a KL penalty, and performs constrained policy updates. DPO instead optimizes policy-to-reference log-probability ratios directly from preference pairs, avoiding the sequence of fitting an explicit reward model and then running online reinforcement learning.

03

Mechanism: SFT, RLHF, and DPO

1. Supervised fine-tuning (SFT)

Collect prompts and ideal assistant completions, format them as chat sequences, and compute cross-entropy over assistant tokens. SFT quickly establishes roles, answer structure, tool-call syntax, and task patterns. Its objective directly supervises the demonstrated assistant tokens. A pretrained model can generalize to prompts and behaviors not literally present in the demonstrations, but that coverage is not guaranteed by the SFT loss. When each prompt has one completion, optimization pushes probability mass toward that path and may narrow other reasonable answers; low-quality demonstrations also provide incorrect direct signal. Chat templates, role tokens, and loss masks are part of the training contract. A different serving template creates distribution shift even when the visible prose looks equivalent.

2. Preference collection

For one prompt, generate or author several responses and ask annotators to select a preferred and rejected response, or provide rankings or scores. Preferences combine objectives such as helpfulness, harmlessness, truthfulness, and style. Annotation instructions, worker population, response-sampling policy, and display order all change the resulting dataset. A pairwise preference is a relative judgment, not an absolute factual certificate. If both candidates are poor, chosen means only “less bad.” If they are nearly identical, labels can be noisy. Retaining ties, disagreement, and annotator confidence is more honest than forcing every pair into a binary label.

3. Reward modeling (RM)

A common design adds a scalar head to a language-model backbone. Given prompt plus response, it emits a reward. A Bradley–Terry-style loss raises the preferred response above the rejected response. The RM generalizes limited comparisons to unlabeled outputs, but also compresses multiple objectives into one score. Policy optimization actively searches high-reward regions and can expose proxy loopholes outside the reward model’s training distribution. RM validation should be sliced by domain, length, and risk; aggregate pairwise accuracy hides rare but critical ranking errors.

4. PPO-style RLHF

Sample responses from the current policy, score them with the RM, and apply a KL penalty to a reference model to limit policy drift. PPO uses mechanisms including a clipped surrogate for minibatch updates. It learns from the policy’s own rollouts, but the system is complex: it needs policy, reference, and reward models—often a value model too—plus online generation, advantage estimation, and stability tuning. Reward normalization, response truncation, stop tokens, and the KL estimator all change the effective objective. A reproducible report must record them rather than merely state “we used PPO.”

5. Direct Preference Optimization (DPO)

DPO starts from the optimal-policy relationship for KL-regularized reward maximization, writes the implicit reward as a log-ratio between policy and reference probabilities, and applies a classification-like loss directly to preference pairs. It removes the explicit RM and online PPO loop, simplifying training. It still depends on preference coverage, the reference policy, and β. “Direct” does not mean reward-assumption-free, nor does it guarantee immunity to overoptimization. When offline pairs came from an older policy, the new policy can enter unsupported regions; iterative collection or online evaluation is needed to expose that support gap.

# SFT: imitate a demonstrated completion
loss_sft = CE(policy(prompt), chosen_tokens)

# RLHF: sample, score, then update with KL control
y = sample(policy, prompt)
reward = RM(prompt, y) - beta * KL(policy || reference)
policy = PPO_update(policy, reward)

# DPO: update directly from chosen/rejected log-ratios
loss_dpo = preference_loss(policy, reference, chosen, rejected, beta)

6. Evaluation and release

Every stage needs held-out preference accuracy, capability and safety evaluation, red teaming, and real agent sandboxes. Higher RM accuracy does not guarantee a better final policy; lower DPO loss does not guarantee tool success. Release gates should compare base, SFT, and aligned checkpoints for capability regressions, refusal boundaries, calibration, and long-horizon trajectories. They should also check training/evaluation contamination, inter-annotator agreement, and confidence intervals for each risk slice. One average win rate cannot justify a high-risk release.

04

Essential math: turning preference into loss

Reward-model preference probability

P(yw ≻ yl | x) = σ(rφ(x,yw) − rφ(x,yl))

x is the prompt, yw and yl are preferred and rejected responses, rφ is the reward model, and σ is sigmoid. Training minimizes the negative log of this probability. Only score differences enter the loss, so the absolute reward origin is unidentifiable. RM scores need not be directly comparable across versions, prompt domains, or training recipes.

The KL-regularized policy objective

maxπ Ey∼π(·|x)[r(x,y)] − β DKL(π(·|x) || πref(·|x))

The first term favors high reward; the second penalizes divergence from a reference policy. β controls the trade-off. If β is too small, the policy can exploit RM errors or lose base capabilities; if too large, behavior barely changes. Practical PPO additionally needs token-level KL estimates, advantages, value targets, and clipping. The equation communicates the objective, not a complete implementation.

The DPO loss

LDPO = −log σ(β[(log πθ(yw|x)−log πref(yw|x)) − (log πθ(yl|x)−log πref(yl|x))])

The bracket compares how much the policy improves preferred and rejected responses relative to the reference. The loss pushes the preferred relative log-ratio higher. β controls the scale of the implicit reward and departure from the reference; it is not simply a learning rate or “safety strength.” Sequence log-probability is a sum of token log-probabilities, so response length, masking, and normalization details affect optimization.

Proxy overoptimization

Let true human utility be U and a trainable proxy be R=U+ε. Stronger policy search is more likely to find regions where error ε is accidentally high even when U has not improved. Gao and colleagues report in their synthetic setup that optimizing proxy reward beyond a point can reduce gold reward, and study scaling patterns for that effect. This supports the warning that RM holdout accuracy is insufficient evidence for safe strong optimization; it does not imply every production RLHF system follows one universal curve.

05

Implications for agent systems

1. Tool-use alignment needs outcome-grounded data

Labeling only whether a tool call looks plausible rewards the appearance of tool use. Stronger data includes execution results, argument validity, recovery trajectories, and side effects. Even then, sandbox permissions in training data do not transfer into production authorization.

2. Refusal is not access control

Preference training can raise the probability of refusing dangerous requests, yet prompt injection, distribution shift, or a new language can bypass it. The runtime must check identity, resource, action, and approval outside the model. Model refusal is a defense-in-depth signal, not a security boundary.

3. Sycophancy can arise from a preference proxy

If annotators prefer agreeable, fluent, or confident answers, the model may accommodate a false premise. Agents used for analysis, code review, or decision support should reward evidence, calibration, and correction rather than satisfaction alone. Evaluations need adversarial examples in which the user strongly suggests the wrong answer.

4. Reward hacking also occurs inside an agent loop

If success means “the tool returned HTTP 200” or “the user did not ask again,” a policy can make meaningless calls, conceal failures, or declare completion early. Training rewards and runtime metrics both need outcome verifiers, anti-gaming signals, and human audits. Do not let the model both execute and define success.

5. Alignment versions are behavioral dependencies

The same base model can acquire different tool propensity, refusals, verbosity, and risk preferences under different SFT and preference recipes. A model upgrade needs fixed regression suites and shadow tests on real trajectories, with post-training lineage recorded rather than only a base-family name.

6. Multiple objectives should not collapse into one release score

Helpfulness, truthfulness, harmlessness, latency, and cost conflict. Use a layered dashboard and hard safety constraints rather than one average reward. For a high-risk action, a higher overall win rate cannot justify a rare catastrophic regression.

7. Resolve policy conflicts outside the model

System instructions, user goals, tool output, and post-training tendencies can conflict. A model balances them through learned probability patterns; it cannot prove that it applied the correct precedence. The runtime should separate untrusted data from instructions and use explicit precedence, capability tokens, and deny-by-default policy to define the executable set. The model proposes only inside that set, preserving authorization boundaries even when alignment fails at an edge case.

06

Trade-offs and failure modes

SFT coverage versus diversity: curated demonstrations stabilize format but can narrow modes, create verbosity templates, or forget base capabilities. Several correct answers and general replay data can help, at the cost of more curation.

RM generalization versus scalar compression: one score is convenient to optimize but entangles truth, safety, and style. Multiple reward heads, rule constraints, or staged optimization separate objectives while making arbitration more complex.

PPO control versus system complexity: online rollouts adapt to the current policy distribution, but require substantial compute, several models, and stability work. DPO simplifies the pipeline but uses offline preferences and does not automatically cover every region a new policy reaches.

KL constraint versus room to improve: strong KL preserves base capability while limiting alignment; weak KL enables larger changes but raises reward hacking, language degradation, and capability regression. There is no universal β. Multi-dimensional evaluation must select it.

Human preference versus objective truth: humans are affected by presentation, style, knowledge, and time pressure. Majority preference is not a factual oracle. Expert labeling, factual tools, disagreement modeling, and adjudication improve quality without eliminating normative conflict.

Alignment tax versus alignment gain: some safety tuning raises refusal and loses marginal capability; clearer instruction following can also improve capability. Measure on the target workflow rather than assuming alignment always lowers or raises intelligence.

07

Reusable judgments

  • SFT remains cross-entropy over completions. It imitates demonstrations and does not directly express relative preference.
  • A reward model learns relative scores for preferred and rejected responses. Proxy accuracy does not guarantee alignment with true utility after strong policy optimization.
  • PPO/RLHF samples online and updates with reward plus KL control. DPO directly optimizes policy/reference log-ratios, simplifying rather than eliminating preference assumptions.
  • Model refusal, tool propensity, and aligned behavior are probabilistic tendencies—not credentials, authorization, or completion verification.
  • A complete control stack manages and evaluates training objectives, decoding policy, and agent-runtime policy separately.
08

Primary sources

  • Ouyang et al., Training Language Models to Follow Instructions with Human Feedback — the InstructGPT SFT, reward-model, and PPO pipeline. Gains are author-reported results under specific models and annotation settings.
  • Schulman et al., Proximal Policy Optimization Algorithms — establishes PPO’s clipped surrogate and policy-optimization foundations; the original paper is not specific to LLMs.
  • Rafailov et al., Direct Preference Optimization — derives the DPO objective from KL-regularized RLHF and reports experiments against PPO-based RLHF.
  • Stiennon et al., Learning to Summarize with Human Feedback — trains a preference model and optimizes a policy for summarization, providing early large-scale evidence for text RLHF.
  • Gao et al., Scaling Laws for Reward Model Overoptimization — studies overoptimization scaling with synthetic gold and proxy rewards. It should not be extrapolated as a fixed curve for every production system.
  • Bai et al., Training a Helpful and Harmless Assistant with Reinforcement Learning from Human Feedback — describes Anthropic’s helpful and harmless RLHF pipeline and experiments; results are author reported.

Connecting refusal, tool-use preferences, runtime authorization, and release governance is editorial engineering analysis based on the mechanisms, not one unified agent prescription directly validated by any single paper.

09

Closing the four parts and choosing the next stop

Part 1—training objective: cross-entropy learns next-token likelihood on ground-truth prefixes, while teacher forcing differs from the real rollout distribution. Part 2—optimization and scaling: AdamW, batches, schedules, mixtures, and compute allocation shape capability; average loss is not agent success. Part 3—inference control: temperature, top-p, seeds, and grammars select paths from logits, with clear limits on syntax and determinism. Part 4—alignment: SFT, reward modeling, PPO/RLHF, and DPO shift behavioral tendencies while remaining probabilistic.

This series is complete. We can now separate three questions about model behavior: which objective and data shaped the parameters, which decoding policy selected a token path, and which runtime authorized, executed, verified, and recovered the action. The next systematic curriculum enters agent runtime internals, beginning with explicit state machines and control planes, then tool-call lifecycle, concurrency, idempotency, checkpointing, recovery, and long-running tasks—without repeating a surface-level description of the agent loop.
