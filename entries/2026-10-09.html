一个任务该交给哪个模型？路由器凭什么知道？

从 capability profiles 与校准误差出发，设计 cascade、升级、ensemble disagreement、成本质量前沿与 route verification。

2026-10-09约 20 分钟Model routing / Calibration / Cascades / Ensembles / Cost-quality tradeoff
01

今日命题

多模型路由器看似只做一项选择：把请求送往便宜模型还是强模型。真正的决策却是：给定任务类型、可用证据、工具与权限、风险、延迟和预算，哪条执行路线能以可接受代价达到经验证的正确结果？强模型在某些任务上的平均分高，不意味着它在每个步骤都值得调用；小模型对某些短任务很稳，也不意味着它能安全处理未经见过的财务写入或长上下文冲突。

路由器不能把模型自报的 confidence 当可靠概率，也不能用“回答流畅”替代验证。它必须维护随模型版本、任务分布和工具环境变化的 capability profile；对容易的步骤使用便宜路线，对不确定或高损失步骤升级；无法在预算内满足质量与安全约束时，明确 abstain 或交人工。Ensemble 只在错误有足够独立性、分歧有可判定意义时才值得成本。

核心判断：路由不是“模型排行榜”。它是一条受 task contract 约束的 sequential decision policy：观察信号、分配预算、选择下一步，并让独立 verifier 决定是否停止。
02

从 multi-agent ownership 到 model route ownership

1/4 已说明多个 Agent 共享任务时必须有 canonical state、delegation contract、single-writer ownership 和 global verifier。一个 child task 在执行中切换模型，同样不能绕开这些边界。Route 绑定 taskId、inputSnapshot、allowed tools、policy version 和 budget；“升级模型”是同一 logical task 的新 attempt 或新 decision，不是新建一个不受约束的任务。若第一次模型已经发出副作用，下一次模型不能靠重做调用“复核”它，必须查 effect ledger 或让 observer 验证。

模型能力画像也不是静态产品简介。它至少按 task class 记录：结构化抽取、工具选择、长上下文证据使用、代码修改、多语言、拒答、视觉/计算机操作；并标注数据域、长度、风险、模型版本、采样设置、工具 catalog 与 verifier。一个模型在公开 benchmark 擅长代码，不证明它在你当前 repo、schema 和权限策略上有相同表现。Profile 来自带 provenance 的离线 eval、shadow traffic 和受控 canary。

这样 router 负责选择，而 runtime 保持唯一状态所有者。候选模型的回答是 proposals，verifier 的 evidence 和 verdict 才影响完成；路由日志则记录“为何在这里花费一次更贵的调用”。

03

机制：可审计的 cascade 与升级协议

1. 声明任务与损失

Admission 把目标编译为 task class、required claims、数据/工具能力、risk tier、deadline、token/tool/sandbox budget 和 human escalation。对只读分类和外部付款，错误损失函数不同；同一 confidence threshold 不应通用。若候选路线缺必需 modality、tool contract 或隔离级别，直接排除，不进入价格比较。

2. 建带版本的 capability matrix

每个候选模型在代表性、时间切分的任务上测 verified success、错误类型、拒答、延迟分布、输入/输出 token、tool selection、context length、cost。结果保留 dataset、prompt、model、tool catalog、sampling 和 verifier 版本。漂移检测按 task slice 做，避免全局平均掩盖某个 tenant 或语言退化。

3. 预路由用可见特征

输入特征包括长度、语言、modality、预计 context、工具需求、结构化约束、风险和剩余预算。不能把未来正确答案或 verifier 后验结果作为在线特征。低成本 classifier 可选候选路线，但 classifier 自身版本和失误也进入 eval；路由器不能成为不可解释的黑箱。

4. 先用便宜可逆步骤

小模型可做抽取、候选检索、草拟 plan 等无副作用工作。输出必须符合 schema，带 source refs 和 uncertainty evidence。可检查的信号包括 parse/contract failure、证据缺口、工具冲突、引用无法回源、两个独立抽取不一致；“我有 95% 信心”本身不是已校准概率。

5. 校准升级 gate

在保留时间分层的验证集上，将 gate score 映射为实际错误频率，并按 domain、language、risk、length 做 reliability diagram 或分桶。若验证集外分布漂移，校准不再保证有效；gate 应保守升级或 abstain。高风险路线可硬性要求强模型/独立 observer，即使分数看起来很好。

6. Cascade 的状态传递

升级时传递原任务、source evidence、失败理由和预算，不把便宜模型的结论当事实，也不把它的 rationale 当更高 authority。强模型读取同一 input snapshot；若需要新证据，先经 context/tool policy 获取。cheap attempt 的调用成本计入总账，升级不是免费重来。

7. Ensemble 与 disagreement

对高不确定、可离线验证的 decision，可以让不同模型或独立 prompt 生成候选，然后比较结构化 claims、证据和 action。简单多数投票只在错误足够不相关时有益；若模型共享训练数据和相同错误来源，三票可能是同一个错误的复制。分歧触发 targeted evidence retrieval、强 verifier 或人工，而不是盲目平均自然语言答案。

8. Stop rule 由 verifier 决定

模型输出不是 terminal verdict。schema、policy、tool result 和 required claim verifier 均通过且无 unresolved effect，才停止；否则按错误类型 repair、升级或 unknown。被验证的低风险结果无需继续调用强模型，节约成本；未验证的高风险结果不能因预算将尽而宣称完成。

9. Route identity 与回滚

每次 route 保存 policyVersion、capabilityProfileVersion、modelId/version、prompt/decoder、tool catalog、input snapshot、budget reservation、gate signals、升级原因和 verifier。Canary 发现某 slice 退化时回滚 route snapshot；进行中的任务绑定原 route，除非显式迁移。所谓“同一个模型名称”若后端权重/设置变了，也应视为新版本。

10. 评测与运营

离线使用 paired cases 比较 always-small、always-strong、cascade 和 ensemble，并以 cost per verified outcome、terminal p95/p99、abstention、unsafe action、repair rate 作指标。Shadow 用真实请求比较 route decision 而不执行替代 effect，canary 按 risk/tenant 分层。监控 calibration drift、gate false negative、升级比例、fallback 原因和 route-specific incident；安全违规独立于平均质量。

04

必要数学：升级阈值、校准与成本前沿

Expected loss gate

便宜 route 的错误概率估计为 p，错误损失为 L，升级额外成本为 ΔC，强路线把错误率降为 p'。若 (p−p')L>ΔC，升级有正的期望价值。成本与损失需归一化到同一单位；高风险 effect 的 L 大，阈值自然更严格。这个式子不允许用平均损失抵消零容忍授权违规。

Selective risk

设 gate 只让 score≥τ 的 case 直接通过，coverage 为 c(τ)=P(score≥τ)，通过 case 的错误率为 r(τ)=P(error | score≥τ)。调整 τ 会在直通比例和错误率之间取舍。工程上画 risk-coverage curve，并在每个 task slice 检查；只报总体 accuracy 会掩盖被放行的高风险尾部。

Cascade cost

初始模型成本 C_s，升级概率 q，强模型增量成本 C_l，gate/verifier 成本 C_v，则每任务期望成本约 E[C]=C_s+q·C_l+C_v。实际还计 repair、工具和人工。若 q 接近 1，cascade 可能比直接强模型更贵；若 cheap attempt 改善证据，强模型的后续成本也可能下降。必须在 verified outcomes 上测量。

Calibration

预测分数 p̂=0.8 的样本组若真实成功率约 0.8 才算该区间校准；校准不等于 discrimination，也不会自动跨分布保持。对高风险 gate 使用保守置信上界与时间切分验证，而非直接相信模型文字 confidence。

05

对 Agent 系统的影响

能力：专用模型可处理抽取、视觉或代码，强通用模型处理复杂规划；同一 task 可跨模型，但共享 task identity、evidence 与 budget。Route 由所需能力决定，非仅价格。

可靠性：升级理由、gate signal、失败类型和 verifier verdict 都进入 trace。Router 出错可按 task slice 归因；模型版本漂移可触发 profile 失效和回滚。

安全：路由不授予新权限。所有候选模型只获得同一 task contract 允许的 tool/data view；高风险 route 的 approval、sandbox 和 independent verification 保持。模型切换不能绕过 policy。

经济性：比较 cost per verified outcome、terminal tail latency 和 human review，而非单次 token 单价。Cascade 的 cheap attempt 若经常升级或引发 repair，会吞掉节省。

06

设计取舍与失败模式

  • 模型自报 confidence：语言流畅或数字自报不等于校准；以有 verdict 的 held-out cases 校准 gate。
  • 公开榜单直用：领域、长度、工具、权限不同；建立本地 task slices 和 profile version。
  • 强模型兜底所有问题：升级比例过高导致 cascade 比直连更贵；比较 CPVO 与尾延迟。
  • 多数投票即真相：共享证据缺口造成相关错误；比较 claims 与来源，分歧时补证据。
  • cheap attempt 先写入：升级时重复副作用；可逆步骤先行，effect ledger 保护。
  • router 看后验标签：离线分数泄漏到线上特征；按 decision time 构造 features。
  • 路由后安全降级：换模型时丢 approval/sandbox/verifier；task contract 全程固定。
  • 一条全局阈值：少数语言/tenant/risk slice 被平均掩盖；按 slice 校准与监控。
07

可复用的技术判断

  • 模型路由是 task contract 约束的 sequential decision，profile 必须按版本和场景评测。
  • 先做可逆、可验证的便宜工作；用校准后的错误信号决定升级、复核或 abstain。
  • 升级继承同一 snapshot、权限、预算与 effect ledger；模型结论不自动变事实。
  • Ensemble 只有在错误差异和证据裁决有价值时才采用；分歧触发补证据。
  • 以 verified success、risk-coverage、CPVO 和 terminal tail latency 比较 routes，安全门保持独立。

Which Model Should Handle This Task, and How Can the Router Know?

Start with capability profiles and calibrated error, then design cascades, escalation, ensemble disagreement, cost-quality frontiers, and route verification.

2026-10-0920 min readModel routing / Calibration / Cascades / Ensembles / Cost-quality tradeoff
01

Today's proposition

A multi-model router seems to choose between a cheap model and a strong one. The real decision is which execution path can reach a verified correct outcome at acceptable cost, given task type, available evidence, tools and permissions, risk, latency, and budget. A stronger model's higher average score does not make it worth using at every step. A smaller model's reliable performance on short tasks does not make it safe for an unfamiliar financial write or a long-context conflict.

The router cannot treat a model's self-reported confidence as a reliable probability or use fluent prose as verification. It maintains capability profiles that change with model version, task distribution, and tool environment. Cheap routes handle easy steps; uncertain or high-loss steps escalate. If no route can satisfy quality and safety within budget, the system abstains or asks a human. Ensembles justify their cost only when errors are sufficiently independent and disagreement has a meaningful resolution rule.

Core judgment: routing is not a model leaderboard. It is a sequential decision policy constrained by a task contract: observe signals, allocate budget, choose the next step, and let an independent verifier decide when to stop.
02

From multi-agent ownership to route ownership

Part 1 established canonical state, delegation contracts, single-writer ownership, and a global verifier for cooperating agents. Switching models inside a child task must preserve those boundaries. A route binds task ID, input snapshot, allowed tools, policy version, and budget. Escalating a model is a new attempt or decision within the same logical task, not a new unconstrained task. If the first model already caused a side effect, a second model cannot “double-check” by repeating it; the system consults the effect ledger or an observer.

A capability profile is not static marketing material. At minimum it distinguishes structured extraction, tool selection, long-context evidence use, code modification, multilingual work, abstention, and visual or computer operation. Each estimate is tagged with data domain, input length, risk class, model version, sampling settings, tool catalog, and verifier. A public coding benchmark does not prove equal performance in your repository, schema, and permission policy. Profiles come from provenance-bearing offline evaluations, shadow traffic, and controlled canaries.

The router chooses; the runtime remains the single state owner. Model outputs are proposals. Verifier evidence and verdicts decide completion. A route trace records why a more expensive call was purchased at a particular point.

03

Mechanism: an auditable cascade and escalation protocol

1. Declare the task and loss

Admission compiles the goal into task class, required claims, data and tool capabilities, risk tier, deadline, token, tool and sandbox budgets, and human escalation. Read-only classification and an external payment have different loss functions; one confidence threshold cannot serve both. Routes lacking a required modality, tool contract, or isolation tier are excluded before price comparison.

2. Build a versioned capability matrix

Measure each candidate model on representative temporally split tasks: verified success, error classes, abstention, latency distribution, input and output tokens, tool selection, context length, and cost. Retain dataset, prompt, model, tool catalog, sampling, and verifier versions. Track drift by task slice so a global average cannot hide regression in one language or tenant.

3. Route with observable features

Input features include length, language, modality, expected context, tool needs, structural constraints, risk, and remaining budget. Future correct answers and post-verification outcomes are not online features. A cheap classifier may choose candidate routes, but its own version and mistakes enter evaluation; the router is not an unaccountable black box.

4. Begin with reversible cheap work

A small model can extract, retrieve candidates, or draft a plan without side effects. Output has a schema, source references, and uncertainty evidence. Checkable signals include parse and contract failure, evidence gaps, tool conflict, broken citations, and disagreement between independent extractions. “I am 95% confident” is not by itself a calibrated probability.

5. Calibrate escalation gates

On a held-out, time-separated validation set, map gate scores to actual error frequencies. Inspect reliability by domain, language, risk, and input length. Calibration may fail after distribution shift; the gate then escalates conservatively or abstains. A high-risk route can require a stronger model and independent observer regardless of a favorable score.

6. Transfer state through a cascade

Escalation passes the original task, source evidence, failure reasons, and remaining budget. The cheap model's conclusion is not a fact and its rationale gains no authority. The stronger model reads the same input snapshot and obtains new evidence only through context and tool policy. The initial attempt remains on the cost ledger; escalation is not a free restart.

7. Use ensembles for meaningful disagreement

For uncertain decisions that can be verified, different models or independent prompts may produce candidates. Compare structured claims, evidence, and actions. Majority vote helps only when errors are sufficiently uncorrelated. Shared training data and common evidence failures can make three votes copies of one mistake. Disagreement calls for targeted retrieval, a stronger verifier, or human review rather than averaging natural-language answers.

8. Let verifiers define the stop rule

A model output is not a terminal verdict. Stop only when schema, policy, tool result, and required claim checks pass with no unresolved effect. Otherwise repair, escalate, or mark unknown by error class. A verified low-risk result needs no expensive follow-up call. A high-risk result cannot become complete merely because the budget is almost exhausted.

9. Version routes and rollbacks

Every route records policy version, capability-profile version, model identity and version, prompt and decoder, tool catalog, input snapshot, budget reservation, gate signals, escalation reason, and verifier. A canary regression in one slice rolls back the route snapshot. Running tasks retain their captured route unless explicitly migrated. If model weights or settings change behind the same display name, treat that as a new version.

10. Evaluate and operate

Use paired offline cases to compare always-small, always-strong, cascade, and ensemble paths on cost per verified outcome, terminal p95 and p99, abstention, unsafe action, and repair rate. Shadow real traffic to compare routing decisions without alternative effects, then canary by risk and tenant. Monitor calibration drift, gate false negatives, escalation rate, fallback reasons, and route-specific incidents. Safety violations are separate from average quality.

04

Essential mathematics: escalation thresholds, calibration, and cost frontiers

Expected-loss gate

Let the cheap route's estimated error probability be p, loss from error be L, additional escalation cost be ΔC, and stronger-route error probability be p'. Escalation has positive expected value when (p−p')L>ΔC. Cost and loss need common units. High-impact effects raise L and tighten the gate. This equation never permits average loss to offset zero-tolerance authorization violations.

Selective risk

If a gate accepts cases with score at least τ, coverage is c(τ)=P(score≥τ), while error among accepted cases is r(τ)=P(error | score≥τ). Moving τ trades direct completion against risk. Plot a risk-coverage curve for every task slice. Overall accuracy can hide the high-risk tail among admitted cases.

Cascade cost

For initial-model cost C_s, escalation probability q, additional strong-model cost C_l, and gate or verifier cost C_v, expected cost is approximately E[C]=C_s+q·C_l+C_v. Real accounting adds repair, tools, and human review. When q approaches one, a cascade may cost more than directly using the strong model. If the first attempt improves evidence, the second call may cost less. Measure against verified outcomes.

Calibration

A group receiving predicted score 0.8 is calibrated in that interval only if its observed success rate is near 0.8. Calibration differs from discrimination and does not automatically survive distribution shift. High-risk gates use conservative confidence bounds and time-separated validation instead of trusting the model's verbal confidence.

05

Implications for agent systems

Capability: specialized models may handle extraction, vision, or code while a stronger general model handles complex planning. One task may cross models while keeping the same identity, evidence, and budget. Required capability drives routing alongside price.

Reliability: escalation reasons, gate signals, error classes, and verifier verdicts enter traces. Router failures can be attributed by task slice. Model-version drift can invalidate a capability profile and trigger rollback.

Security: routing grants no new authority. Candidate models receive only the data and tools permitted by the same task contract. Approval, sandboxing, and independent verification remain in high-risk routes. Switching models cannot bypass policy.

Economics: compare cost per verified outcome, terminal tail latency, and human review rather than price per token. A cheap attempt that often escalates or causes repairs can erase its nominal saving.

06

Trade-offs and failure modes

  • Model-reported confidence: fluent language or a self-assigned number is not calibration. Fit gates on held-out cases with verdicts.
  • Public leaderboard routing: domain, length, tools, and permissions differ. Build local task slices and profile versions.
  • Strong fallback for everything: high escalation rate can make a cascade costlier than a direct strong route. Compare verified-outcome cost and tails.
  • Majority vote is truth: shared evidence gaps produce correlated errors. Compare claims and sources and seek new evidence on disagreement.
  • Cheap attempt writes first: escalation may duplicate effects. Begin with reversible steps and protect writes through the effect ledger.
  • Router sees future labels: offline metrics leak into online features. Construct features at decision time.
  • Safety degrades after routing: model switching drops approval, sandbox, or verifier. Keep the task contract fixed throughout.
  • One global threshold: minority languages, tenants, or risk slices disappear in averages. Calibrate and monitor per slice.
07

Reusable technical judgments

  • Model routing is a sequential decision constrained by a task contract; profiles are evaluated by version and scenario.
  • Start with reversible, verifiable cheap work. Use calibrated error signals to escalate, review, or abstain.
  • Escalation inherits the same snapshot, authority, budget, and effect ledger. Model conclusions do not become facts automatically.
  • Use ensembles only when error diversity and evidence-based arbitration justify them; disagreement triggers more evidence.
  • Compare routes on verified success, risk-coverage, cost per verified outcome, and terminal tail latency, with separate safety gates.

09

What is established and where we continue

Established today: each route binds task, input, policy, and budget snapshots, while capability profiles are evaluated by task slice and version. After reversible cheap work, a calibrated gate chooses direct acceptance, stronger-model escalation, ensemble review, or abstention. A verifier remains the sole stop rule. Costs include every attempt, repair, and human review.
