Agent 在脑中试了十步，为什么第三步就可能偏离现实？

01

今日命题

用户让 Agent 把一个项目的交付日期顺延、改会议室、通知团队。Agent 在内部‘试跑’十步：改日期后房间应空闲，发消息后大家应收到。它真正执行到第三步，会议室已被别人抢订；若继续照原计划发送‘房间已确定’，长计划反而放大了一个早期错误。规划中的未来是模型生成的假设轨迹，环境里的下一次观察才是新证据。

昨天完成 World State & Partial Observability：belief 表示当前可能状态，主动查询选择能改变行动的证据，未知高风险结果应停下。今天开始 Agent Model-Based Planning Internals 1/2，问一个不同的问题：若要在行动前比较多条未来路径，rollout 实际模拟什么、规划深度为何既有价值又有偏差、何时必须只执行第一步再重规划？下篇再讨论有限搜索预算怎样分配到候选、如何用风险约束与独立评测决定是否部署，而不把模型想象当完成证明。

核心判断：规划可指导选择，不能提前提交未观测到的状态；执行闭环必须在真实反馈后重新定根。
02

从 belief 到虚拟未来，先标明谁在说话

昨天的 belief 可同时包含‘房间仍空闲’与‘已被别人预订’，且概率或候选集合不应被模型随口改写。规划器从这些可能状态出发，尝试候选动作，再用 transition model 预测后继状态、可见观察和收益。这个内部过程常被叫 rollout 或 imagination。它产生的是 model-predicted 节点；真实 API、截图和权威数据库给出的是 observed 节点。两者需要不同标记和写入权限。若在上下文里都写成‘房间已空闲’，后续模型无法辨认哪个是推测。

ReAct 中的 action→observation 是与外部环境交互后的轨迹；Tree of Thoughts 搜索多个文字‘思路’，可帮助组织推理，却不自动拥有可执行环境模型。PlaNet、MuZero、DreamerV3 的作者研究在学到的动力学/潜在状态上做规划或想象；论文报告的控制与游戏结果来自特定实验环境。业务 Agent 可以借用‘预测—比较—执行—重观测’结构，但绝不能由这些论文推断它已学会日历、权限和消息系统的真实转移规则。

这里也承接更早的 runtime 安全边界：动作 proposal 的合法性、权限、幂等与后置条件由外层系统决定。一个模型可在沙盒里模拟‘发送通知’后如何改变团队状态，但模拟节点不能产生真实收件人回执，更不能证明对方已读。真实工具调用应绑定当前对象版本与授权，并把结果送回 belief；预测轨迹保留为决策依据而非事实层。

03

机制：模拟多步，只执行一步

1. 给模型一份可检查的起点

输入不是一段‘任务大概进展顺利’的摘要，而是当前 belief、目标、硬约束、未决工具状态、可用动作及其前提。对每个候选动作，模型至少预测可能后继状态、可能观察、成本与失败分支，并标记模型版本和假设。高风险动作若缺授权，连模拟可行动集合也应标为不可执行；它可用于风险分析，但不能因为模拟得分高而进入执行队列。

2. 展开树，而不是写一条必然未来

改日期后房间可能空闲，也可能被抢订；预订成功后通知可能送达、失败或回执未知。一个合理 rollout 保留分支，而非只写‘改日期→订房→发消息→完成’。分支可由明确的工具合同、历史测量或学习型 world model 生成；不知道转移分布时用候选集合和 unknown，比伪造小数点后两位的概率好。搜索会偏好看起来收益高的路径，但模型可能对某类罕见失败系统性乐观。

3. 区分目标评分与真实终态

规划节点可以估计完成任务的价值、延迟、调用成本和错误代价；这些是决策分数，不是外部 verifier。MuZero 的作者展示用学到的模型与搜索选择动作，PlaNet 与 Dreamer 系列展示潜在动力学规划/想象的路线；它们并未验证你的业务消息已送达。评分器还可能奖励‘容易预测的路径’而非真正好的路径，所以要把安全硬约束与终态定义放在模型分数之外。

4. 执行第一步，观察后重新定根

选中计划后，broker 只提交当前获授权的一步。例如先改交付日期，等待真实工具回执，再重新读取会议室状态；若预订失败，就从新 belief 规划替代，而不是沿旧分支通知团队‘已订到 R’。这叫 receding-horizon 或 model-predictive 式控制的工程直觉：向前看多步，真正执行少量，然后用新观察修正。若第一步结果未知，先按上一篇的主动查询策略求证；不能假装路径仍在原分支。

5. 控制模拟误差进入现实的通道

预测可能错在动作后状态、观察可见性、其他参与者行为或工具业务语义。为了防止‘想象记忆’污染，trace 将每个节点标记 imagined/observed/verified，绑定 parent belief、model version、action proposal 和真实 observation ID。真实已派发动作的状态预测与随后 observed 证据才可推进 live belief；想象分支不能，只有权威后置条件可把 effect 标为 committed。模拟工具要无生产凭据；否则所谓‘试跑’可能真发出邮件。旧分支在重观测不一致时被废弃，不允许被后续摘要改写为已发生事实。

6. 找到必须缩短 horizon 的信号

环境变化快、模型对转移不熟、多个外部主体竞争、不可逆动作多或观察成本低时，长 rollout 价值下降，应短看并频繁复核。稳定、可模拟、动作成本高而观察昂贵的环境可容纳更长 horizon。不能只用固定步数：记录预测与实际的 first divergence、关键分支覆盖、回滚需求、p95/p99 任务时长和每个 verified outcome 成本。下一篇会讨论如何把有限搜索算力投到重要分支，并比较模型规划与无模型 baseline。

04

必要数学：看多远、分多少叉、错在哪里

一个长度 H 的模拟路径可用 G_H=E_model[Σ_{t=0}^{H−1}γ^t r_t+γ^H V(s_H)] 评分。H 是规划步数，r_t 是模型预测在第 t 步的收益或负成本，γ∈[0,1] 折扣远期项，V(s_H) 是叶节点后续价值估计；E_model 表明期望由所用模型的模拟分布计算。公式不是任务真实收益：若模型错判会议室可用或把‘请求已接收’当‘已发送’，G_H 会系统性偏高。高风险约束先过滤动作，不能拿一个巨大的 r_t 抵消越权。

若每个节点平均考虑 B 个候选动作，完整展开 H 层约有 B^H 条叶路径；B=4、H=5 时是 1024 条叶路径，尚未算内部节点或每次模型调用。剪枝、采样、缓存和价值函数可减少实际计算，但也可能丢掉低概率高损失分支。因此深度既消耗成本又改变风险覆盖，不是免费‘多想几步’。

作一个谨慎的误差界：若在计划实际可能访问的每一步历史上，发生一次关键模型预测错误的条件概率都不超过 ε，则由 union bound，P(前 H 步至少一次关键预测错)≤min(1,Hε)。这里‘关键错误’要预先定义为会改变后续动作或安全判断的模型偏差，且每步上界须经与环境对照验证；不要求错误独立。ε=0.05、H=10 时上界 0.5，只说明长 horizon 的保证会变松，不是实测有一半计划失败。随机环境中一条采样未来和真实路径不同，不自动算模型错；应比较预测分布或可核查的条件事件。重观测能让后续计划重新定根，从而不必一口气承受完整 H 步的模型偏差。

05

对 Agent 系统的落地影响

运行时应把 plan graph 存成派生制品：root belief 版本、模型/工具 schema 版本、候选 action ID、每条 predicted transition 的假设、分支价值和不可执行原因。真实 event log 另存 dispatch、回执、观察与 verifier verdict。一次重规划产生新 graph，旧 graph 可审计但不能继续驱动副作用；不要把想象节点拼进 memory index 作为“发生过”的经验。使用模拟工具时隔离凭据与网络出口，明确 simulation=true，不让研究沙盒隐式连上生产。

计划评估应分层。先测 one-step predictive calibration：在同类任务上，模型对下一状态/可见观察的分布是否与真实轨迹接近；再测 branch selection：关键失败分支是否被保留；最后测 closed-loop verified outcome、越权或重复副作用、首个偏离点、尾延迟和成本。离线 logged trajectories 对未执行动作缺反事实真值，不可把‘没发生的分支’当已验证；可控模拟环境只能覆盖其建模的变化，生产仍要小流量监控。

固定深度的 planner 并不总比反应式 Agent 好。若工具可靠、动作短、观察便宜，简单的 observe→act→verify 可能更快更稳；若一个昂贵动作会锁死后续选择，有限 lookahead 可避免明显坏路径。模型路由可让便宜模型提出候选、强模型或 verifier 检查关键分支，但规划层的额外 token 和延迟必须按每个安全 verified outcome 计，而不是按单次模型调用价格宣传。

06

取舍与失败模式

  • 长计划等于可靠：只要环境变动或模型偏差存在，深度可能累积虚假前提；每步重观测。
  • 文字思路树就是世界模型：多条推理可探索方案，却不提供真实状态转移或工具回执。
  • rollout 的高分就是业务完成：分数只在模型假设下有效；权威终态需外部 verifier。
  • 只模拟最可能分支：低概率高损失或其他参与者竞争可能被剪掉；关键风险单列。
  • 一条预测错就证明模型无用：随机环境允许不同真实轨迹；测分布校准与决策质量。
  • 计划写入 memory：想象分支不是事实，需与观察事件分库、分权限、分标签。
  • 模拟工具可直接复用生产凭据：一次‘试跑’就可能产生真副作用；隔离执行环境。

长 horizon 适合可预测且动作代价高的场景，短 horizon 适合变化快、可轻易观测的场景。真正要优化的是带安全硬门的闭环完成，不是图上看起来有多少层。模型若不知道环境规律，最好的下一步可能是先观察，而不是生成更长的计划。

07

可复用的技术判断

  • rollout 是模型条件下的想象轨迹；observed 与 verified 节点必须另记。
  • 规划深度增加前瞻，也放大分支计算与模型误差，不能机械设越深越好。
  • 每次只执行当前获授权的一步，真实反馈后更新 belief、废弃旧分支并重定根。
  • 随机世界中一次采样未来与现实不同，不自动证明模型错；评估分布与决策后果。
  • 以闭环 verified outcome、关键风险、尾延迟和成本比较 planner 与反应式 baseline。

An Agent Simulated Ten Steps. Why Can Reality Diverge at Step Three?

Separate imagined rollouts, horizon depth, branching cost, and receding-horizon replanning; predicted consequences are candidates, not observations.

2026-11-0320 min readModel-based planning / Rollout / Planning horizon / Replanning / World model / Model error
01

Today's proposition

A user asks an agent to move a project deadline, change the meeting room, and notify the team. The agent 'tries' ten steps internally: after the date change the room should be free; after sending, everyone should receive the update. At the real third step, someone else has already booked the room. Continuing the original plan and announcing that the room is confirmed magnifies one early error. An imagined future in a plan is a model-generated trajectory; the next observation from the environment is new evidence.

Yesterday completed World State & Partial Observability: belief represents current possibilities, active queries seek evidence that changes action, and an unknown high-risk outcome should stop. Agent Model-Based Planning Internals begins with a different question. To compare future paths before acting, what does a rollout actually simulate, why is a deeper horizon both useful and biased, and why execute only the first step before replanning? Part 2 will allocate a finite search budget among candidates and examine risk constraints and independent evaluation, without treating imagined outcomes as completion proof.

Core judgment: planning guides selection but cannot commit unobserved state in advance; execution must re-root on real feedback.
02

From belief to imagined futures: label the source

Yesterday's belief may contain both 'room still free' and 'someone else booked it.' Those probabilities or candidate states should not be rewritten by model narration. A planner starts from possible states, tries candidate actions, and uses a transition model to predict successor states, possible observations, and value. This internal process is a rollout or imagination. Its nodes are model-predicted. An actual API, screenshot, or authoritative database produces observed nodes. The two need different labels and write permissions. If both are serialized as 'room is free,' the next model call cannot tell conjecture from evidence.

ReAct's action-to-observation trajectory interacts with an external environment. Tree of Thoughts searches multiple textual thought paths and can organize reasoning, but a thought tree is not automatically an executable environment model. PlaNet, MuZero, and DreamerV3 study planning or imagination over learned dynamics or latent states; their reported control and game results belong to particular experimental settings. A business agent can borrow the predict–compare–execute–reobserve pattern. The papers do not show that it learned the real transition rules of calendars, authorization, and messaging systems.

This also inherits the runtime safety boundary. The outer system determines whether an action proposal is legal, authorized, idempotent, and verified. A model may simulate how 'send notification' might change the team's state, but a simulated node cannot produce a real recipient receipt or prove anyone read the message. A real tool call binds to current object version and authority, then sends its result back into belief. The prediction remains decision support, not a fact layer.

03

Mechanism: simulate many steps, execute one

1. Give the planner an inspectable starting point

Do not feed it a vague summary that 'the task seems to be going well.' Supply current belief, goal, hard constraints, unresolved tool outcomes, available actions, and their preconditions. For each candidate action the model predicts possible successor states, observable results, cost, and failure branches, tagged with model version and assumptions. A high-risk action without authority remains non-executable even inside the action catalog. It may be examined as a risk scenario, but cannot enter the execution queue merely because its simulated score is high.

2. Branch rather than write one inevitable future

After a deadline change, the room might be free or taken by a competitor. After booking, a notification might be delivered, fail, or have an unknown receipt. A useful rollout retains branches instead of writing 'change date → book room → send message → done.' Branches may come from explicit tool contracts, measured history, or a learned world model. When the transition distribution is unknown, a set of possibilities and an unknown label are more honest than invented two-decimal probabilities. Search may favor high-scoring paths while the model is systematically optimistic about rare failures.

3. Separate plan scores from real terminal state

A planning node can estimate task value, latency, call cost, and error cost. These are decision scores, not an external verifier. MuZero's authors show action selection by search over a learned model; PlaNet and the Dreamer line study latent dynamics for planning or imagination. They do not prove that a message in your business system reached its recipient. A scorer may also reward paths that are easy to predict rather than truly good. Keep hard safety constraints and terminal-state definitions outside model score optimization.

4. Execute the first action and re-root on observation

After choosing a plan, the broker commits only one currently authorized step. Change the delivery date, await the actual tool receipt, then reread room availability. If booking fails, plan from the new belief instead of following the old branch and telling the team 'R is booked.' This is the engineering intuition of receding-horizon or model-predictive control: look ahead several steps, execute a small prefix, then correct with feedback. If the first effect is unknown, use Part 2 of the previous series' active-query strategy. Do not pretend the path remains on its original branch.

5. Prevent simulation error from entering reality

Prediction can fail on post-action state, visibility of an observation, other actors, or tool semantics. To prevent imagined memory contamination, tag each trace node imagined, observed, or verified, with parent belief, model version, action proposal, and actual observation ID. Only transitions from real dispatched actions and subsequent observed evidence can advance the live belief; imagined branches cannot. Only authoritative postconditions can mark an effect committed. Simulated tools must lack production credentials; otherwise a 'dry run' could really send mail. Expire an old branch when feedback conflicts with it; a later summary must not rewrite that branch as something that happened.

6. Recognize when to shorten the horizon

Long rollouts lose value when the environment changes quickly, the model has weak transition knowledge, external actors compete, irreversible actions are frequent, or observation is cheap. Such settings favor short lookahead and frequent checks. A stable, simulatable environment with costly actions and expensive observations can support a longer horizon. Do not choose depth from a fixed step count alone. Track first divergence between predicted and observed states, coverage of critical branches, rollback need, p95 and p99 task duration, and cost per verified outcome. Part 2 will allocate finite search compute to important branches and compare model planning with a model-free baseline.

04

Essential mathematics: depth, branching, and model error

One simulated path of horizon H can be scored by G_H=E_model[Σ_{t=0}^{H−1}γ^t r_t+γ^H V(s_H)]. H is planning depth; r_t is model-predicted reward or negative cost at step t; γ∈[0,1] discounts distant terms; and V(s_H) estimates value after the leaf state. E_model says the expectation is under the simulation model, not reality. The formula is not a verified task outcome. If the model predicts a room is free when it is occupied, or treats 'request accepted' as 'message delivered,' G_H is biased upward. Filter high-risk actions through hard constraints first; a large r_t cannot compensate for missing authority.

With B candidate actions considered at each node, a full tree of depth H has roughly B^H leaf paths. At B=4 and H=5 that is 1,024 leaves, before internal nodes or model calls. Pruning, sampling, caching, and leaf-value estimates reduce actual computation, but may discard a low-probability, high-loss branch. Depth therefore changes both cost and risk coverage; it is not free 'extra thinking.'

For a careful error illustration, suppose that along every history the plan could visit, the conditional probability of a critical model prediction error at each step is at most ε. A union bound gives P(at least one critical prediction error in H steps)≤min(1,Hε). Define critical error beforehand as a model deviation that changes a later action or safety judgment, and validate the per-step bound against the environment. Independence is not required. At ε=0.05 and H=10 the bound is 0.5. That means the guarantee gets loose with depth, not that half of actual plans fail. In a stochastic environment, one sampled future differing from the realized path is not automatically model error; compare predicted distributions or checkable conditional events. Real reobservation lets the next plan re-root rather than inheriting the entire H-step model bias.

05

What this changes in an agent system

Store a plan graph as a derived artifact: root-belief version, model and tool-schema versions, candidate action IDs, assumptions behind each predicted transition, branch value, and reasons a branch is non-executable. Keep real dispatches, receipts, observations, and verifier verdicts in a separate event log. Replanning creates a new graph. The old graph remains auditable but may not keep driving effects; imagined nodes must not be indexed as events that happened. Isolate credentials and network egress for simulated tools, label simulation explicitly, and prevent a research sandbox from silently reaching production.

Evaluate planning in layers. First test one-step predictive calibration: on comparable tasks, do distributions over next state and observable results resemble real trajectories? Then test branch selection: are critical failure branches retained? Finally test closed-loop verified outcome, unauthorized or duplicate effects, first divergence, tail latency, and cost. Offline logged trajectories have no counterfactual ground truth for actions that were never taken; do not call those unexecuted branches verified. A controlled simulator covers only changes it models. Production still requires small-scope monitoring.

A fixed-depth planner is not always better than a reactive agent. With reliable tools, short actions, and cheap observations, observe → act → verify can be faster and safer. If one costly action locks out later options, limited lookahead can avoid obvious bad paths. Routing can let a cheaper model propose candidates and a stronger model or verifier inspect critical branches. Count the extra planning tokens and latency per safe verified outcome, not only the price of one model call.

06

Trade-offs and failure modes

  • A long plan is reliable: changing environments and model bias compound false premises. Reobserve after execution.
  • A tree of text thoughts is a world model: multiple reasoning paths explore ideas but supply neither real transitions nor tool receipts.
  • A high rollout score means the business task completed: the score is conditional on model assumptions. An external verifier checks reality.
  • Simulate only the likeliest branch: pruning may miss a rare severe loss or a competitor's action. Track critical risks separately.
  • One wrong sampled future proves the model useless: stochastic worlds allow multiple realized paths. Evaluate distribution calibration and decisions.
  • Write plans into memory as facts: imagined branches are not events. Separate storage, permissions, and labels.
  • Reuse production credentials for simulated tools: a dry run can create a real effect. Isolate execution.

Long horizons favor predictable environments with costly actions; short horizons favor fast-changing worlds with cheap observations. Optimize safe closed-loop completion, not the number of layers in a plan diagram. If the model does not know the environment's dynamics, observing again may be better than generating a longer plan.

07

Reusable technical judgments

  • A rollout is an imagined trajectory conditional on a model. Observed and verified nodes belong to separate records.
  • Deeper planning adds lookahead but expands branching compute and model error; depth is not automatically better.
  • Execute only the currently authorized step, then update belief, discard obsolete branches, and re-root on real feedback.
  • In a stochastic world, one sampled future differing from reality does not itself prove model error. Test distributions and decision outcomes.
  • Compare a planner with a reactive baseline on closed-loop verified outcomes, critical risk, tail latency, and cost.
08

Primary sources and evidence tiers

  • PlaNet: Learning Latent Dynamics for Planning from Pixels — the authors study pixel-based latent dynamics for planning; reported results belong to their control settings.
  • MuZero — the authors report action selection with search over a learned model, not business-API commitment semantics.
  • DreamerV3 — the authors report imagined trajectories in a latent world model for behavior learning, not a production guarantee for every agent.
  • Tree of Thoughts — the authors study search over textual thoughts, distinct from a verifiable environment model.
  • ReAct — the authors study interleaved reasoning, action, and observation; real tool postconditions remain an outer-system concern.

Links and titles were checked on 2026-11-03. Plan graphs, imagined/observed/verified labels, risk gates, and the Hε teaching bound are editorial engineering analysis. The papers do not define one shared agent runtime.

09

Established and next starting point

Established today: from a sourced world-state belief, a model-based rollout branches over possible consequences and scores candidate actions. Predicted nodes are a derived plan graph, not entries in a fact ledger. Larger H exposes distant consequences but grows B^H branch cost and critical prediction-error risk. The outer broker executes only the authorized first step; a real observation updates belief, expires the old branch, and re-roots planning. Textual thought search and a calibrated environment model are not the same thing.

Still unresolved: under a finite compute budget, which branches should expand and which low-probability, high-loss paths must be retained? When is model planning better than a reactive baseline? How can offline logs evaluate a planner without counterfactual outcomes for actions never taken, and how should safety release gates avoid an average-score disguise?
