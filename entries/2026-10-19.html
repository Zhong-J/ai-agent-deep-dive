4 bit 模型为什么不一定更快，也不一定更省？

把权重、激活与 KV cache 分成三本账，拆解 scale、outlier、kernel、带宽与 Agent 质量回归。

2026-10-19约 20 分钟Quantization / W4A16 / W8A8 / KV cache / Outliers / Agent evaluation
01

今日命题

一个 4-bit checkpoint 的文件比 16-bit 小约四倍，团队便宣布 Agent 推理成本也会降四倍。这一步推论漏掉三件事：推理时搬运的不只有权重，还有每层的激活与不断增长的 KV cache；低位整数运算能否直接由当前硬件和 kernel 执行，决定压缩是否变成速度；数值误差可能改变一次工具参数，放大为多轮修复或错误动作。位宽是存储表示，不是端到端性能合同。

昨天的 speculative decoding 保留目标采样分布，却用 draft 与核验减少 target 的串行步骤。量化走另一条路：用近似的低精度表示减少驻留和内存传输。它通常改变模型计算，不能套用昨天的‘分布精确’证明。今天把 weight、activation 和 KV 分开，解释量化尺度与 outlier 怎样进入矩阵乘、attention 与服务成本；再给出一个 Agent 任务级验收方法。

核心判断：只有同时说清量化对象、计算路径、误差预算和负载形态，‘4 bit 更省’才是可检验的工程命题。
02

承接 prefill、decode 与 Agent 成本账本

先把三种张量摆正。权重 W 是请求之间共享的模型参数；在 decode 阶段，每生成一个 token 都要用到大量权重，低 batch、内存带宽受限时压缩有机会减少搬运。激活 X 是当前请求在层间流动的中间值；prefill 处理许多 token，矩阵乘计算量大，只有权重和激活的表示能被支持的低精度 GEMM 利用，才可能获得预期吞吐。KV 是按层、会话、历史 token 累积的 attention 状态；它随上下文和并发增长，即使权重已装进显存，长 Agent trace 仍可能被 KV 容量、读写带宽与调度卡住。

这与此前 KV、long context 和 MoE 的结论连在一起：瓶颈随阶段和 batch 变化。Agent 常有短结构化输出、长检索片段、工具返回的大日志和反复 prefill；‘单个长回答 tokens/s’不能代表它。量化还不同于缓存裁剪：KV 低位表示仍保留历史 token 的近似信息，丢弃或摘要则改变可访问的内容。两者质量风险不同，不能合并成一个‘上下文优化’数字。

03

机制：三本账与真实算子路径

1. 先选择量化单位，再编码

对一组浮点数，找 scale 和 zero point，把连续值映射到有限整数格点；读取时再近似还原。per-tensor 一组共用尺度，元数据便宜却容易被少数大值撑宽范围；per-channel、per-group 各自定尺度，可减少局部误差，但尺度、zero point 与解包操作也占字节和算力。4-bit 两个值装一字节只是原始 payload；真实权重还要加尺度、对齐、某些保留高精度的层，并可能为 kernel 布局重排。

2. 权重量化的两种常见执行形态

W4A16 通常把权重存为 4-bit，激活保留 16-bit；执行时 kernel 按块读、解包、乘尺度，再与高精度激活相乘累加。它主要减少权重驻留和带宽，并不自动成为原生 4-bit 乘法。GPTQ 用近似二阶误差信息逐步补偿权重量化，AWQ 用激活感知的通道重要性保护显著权重；两者是不同的误差控制策略，不是‘4-bit 必然无损’的证据。是否快要看 fused kernel、设备支持、batch、shape 与解包代价。

3. 激活量化要面对运行时 outlier

W8A8 让权重和激活进入 8-bit 矩阵乘路径，但激活随输入变化；一个极大的通道值会迫使共享尺度变大，把大多数小值压到粗格点。LLM.int8() 把 outlier 相关计算留在较高精度路径；SmoothQuant 用等价的通道缩放把量化难度从激活迁到较容易静态处理的权重。‘等价’指缩放前的浮点矩阵乘可代数抵消，不代表缩放后低位舍入无误差。静态校准集若没有长工具日志、中文、代码和罕见 JSON，线上误差可能与离线样本不同。

4. KV 是独立、增长中的账

每层 attention 保存旧 token 的 K 与 V。KV 量化可在写入或读取时缩放、打包并在 attention kernel 内使用或反量化；粒度和访问布局决定额外读取与计算。KIVI 报告 key 更适合 per-channel、value 更适合 per-token 的非对称低位策略，这是该论文的观察与方案，不是所有架构的普适定律。低位 KV 可能增加可并发会话或延长可驻留上下文，但 attention logits 的小误差会改变检索位置；长距离证据、否定词和工具日志应单独验收。

5. 最后看系统是否真的走低位 kernel

检查 profiler 与部署制品：权重是在显存里始终压缩，还是每步先还原成 FP16 大矩阵？激活量化是否引入许多单独 kernel launch？KV 解包是否抵消带宽收益？CPU offload、跨卡搬运、batch 下降或未融合的 dequant，都可能让‘更小’反而更慢。不要从文件大小推断运行时路径。

04

必要数学：误差与容量怎么算

用对称 b-bit 量化作最小模型：q=clip(round(x/s),−2^(b−1),2^(b−1)−1)，x̂=sq。x 是原数值，s 是该组的正尺度，q 是存储整数，x̂ 是恢复值；clip 限住 b-bit 范围。未饱和时舍入误差至多约 s/2，超出范围则会饱和，误差可远大于 s/2。per-group 缩小局部 s，却增加尺度元数据。若 Ŵ=W+ΔW、X̂=X+ΔX，则一层乘积误差近似 ΔY≈ΔW·X+W·ΔX，还有较小的 ΔW·ΔX 交叉项；这说明权重与激活一起压缩时，误差不一定简单相加，且高幅值激活会放大权重误差。

容量也要分账。忽略 metadata，7B 个权重的 FP16 原始载荷约 7×10⁹×2=14 GB，4-bit 约 3.5 GB；真实部署更大。KV 原始载荷可估为 M_KV≈2·L·T·H_kv·d_head·b/8 字节：2 对应 K/V，L 层，T 个历史 token，H_kv 个 KV heads，每头 d_head 维，b 位。举例 L=32、T=32,768、H_kv=8、d_head=128、b=16 时约 4.29 GB 每条序列；理想 4-bit 原始载荷约 1.07 GB，尚未计入尺度、碎片和临时 buffer。GQA 的 H_kv 小于 query heads，因此不能用 query-head 数粗算。

工程意义是先测瓶颈：decode 若由权重带宽支配，W4A16 可能有效；长上下文、高并发若由 KV 容量支配，压权重未必提高并发；prefill 若算力支配，只有匹配硬件的低精度计算路径才可能显著获益。所有数字都是说明账本的示例，不是某个模型或 GPU 的实测速度。

05

对 Agent 系统的影响与验收

用同一 base checkpoint、同一 prompt、采样规则、工具 schema 与硬件，比较 FP16/BF16 基线与候选量化路线。先按 prefill、decode、attention、CPU/GPU 搬运拆 latency，记录 TTFT、ITL、p50/p99、tokens/s、显存峰值、最大稳定并发和能耗或账单；再按任务终态算 每个经验证正确结果的总成本。模型侧快 20%，若 JSON 修复、工具重试或人工复核增长，Agent 侧仍可能亏。

质量切片至少要有：短结构化 tool call 的 schema/参数精确率；长工具日志里带否定或版本冲突的证据定位；代码生成与执行测试；多语言；长会话中早期约束的保持。比较输出时不要只看通用 perplexity：平均 token loss 可能几乎不变，却在一个低频工具名或权限相关否定词上翻转。对有副作用的动作，继续由外层 broker 做授权与前置条件检查；量化误差既不能放宽权限，也不必被误称为 prompt injection。

逐步上量时把配置记入 trace：每层位宽、group size、scale 策略、KV 方案、kernel 版本、batch、prompt 长度、设备与模型版本。这样回归可定位到数值路径，且能复测长尾任务。谨慎把权重、激活和 KV 的改动分阶段 A/B；同时改三项会使归因困难。

06

取舍与失败模式

  • 只看 checkpoint 大小：漏掉尺度、临时 buffer、未量化层、KV 和设备搬运；以运行时 profiler 及稳定并发为准。
  • 位宽越低必越快：缺少 fused kernel、解包开销或 batch 改变时可以更慢；按 shape 和 prefill/decode 分开测。
  • 校准集只用短英文聊天：outlier 与长工具日志分布可能不同；按生产任务切片选校准和回归数据。
  • 把 W4A16、W8A8、KV4 混称‘4-bit 模型’：压缩对象、可执行算子和误差传播都不同；名称须写明 W/A/KV 位宽。
  • 以平均 perplexity 放行工具 Agent：稀有 token 的错可能是不可逆外部动作；验证最终任务与权限边界。
  • 认为 KV4 等于四倍上下文：metadata、碎片、attention kernel、并发和质量门槛限制可用长度。

没有普适最优组合。带宽受限、算力受限、KV 容量受限和质量受限的服务，需要不同配置；即使同一模型，负载变化也会改变最优点。

07

可复用的技术判断

  • 权重、激活和 KV 是三本不同的账；先找运行时瓶颈，再选择压缩对象。
  • scale 粒度决定误差与元数据；outlier、饱和和解包路径决定低位表示能否变成可靠速度。
  • W4A16 主要压权重，W8A8 需要受支持的低精矩阵乘，KV 低位主要针对随序列与并发增长的缓存。
  • 量化是近似计算，不继承 speculative decoding 的目标分布精确保留性质。
  • 以 Agent 切片的 verified outcome、尾延迟和总成本验收，不能只报模型文件大小或平均 tokens/s。

Why Can a 4-Bit Model Be Neither Faster Nor Cheaper?

Keep separate ledgers for weights, activations, and KV cache; trace scales, outliers, kernels, bandwidth, and agent-quality regressions.

2026-10-1920 min readQuantization / W4A16 / W8A8 / KV cache / Outliers / Agent evaluation
01

Today's proposition

A team sees that a 4-bit checkpoint occupies about one quarter of its 16-bit counterpart and announces a fourfold reduction in agent inference cost. Three missing ledgers invalidate that inference. Inference moves activations and a growing KV cache as well as weights. Whether low-bit arithmetic maps to a real hardware kernel determines whether compression becomes speed. Numerical errors can change one tool argument and turn into repair turns or a wrong external action. Bit width describes a representation, not an end-to-end performance contract.

Yesterday's speculative decoding used drafting and verification to reduce serial target steps while preserving a specified target sampling distribution. Quantization attacks another bottleneck: approximate low-precision representations reduce residency and memory movement. It generally changes the computation, so yesterday's exact-distribution proof does not carry over. Today we separate weights, activations, and KV, follow scales and outliers into matrix multiplication and attention, and end with an agent-task acceptance protocol.

Core judgment: '4 bit is cheaper' is testable only after specifying the quantized object, actual compute path, error budget, and workload.
02

Connecting prefill, decode, and agent cost ledgers

First name the tensors. Weights W are shared model parameters across requests. During decode, each new token consumes a great deal of weight data; at low batch, memory bandwidth can dominate, so compressed weights may reduce traffic. Activations X are the intermediate values flowing between layers for the current request. Prefill processes many tokens and performs substantial matrix multiplication. The expected throughput benefit arrives only when the representations of weights and activations map to a supported low-precision GEMM. KV is attention state accumulated for each layer, session, and historical token. It grows with context and concurrency. A model can fit comfortably in device memory while long agent traces still hit KV capacity, bandwidth, or scheduler limits.

This extends earlier lessons on KV, long context, and MoE: the bottleneck moves with phase and batch. Agents often emit short structured actions, ingest long retrieved passages and tool logs, and repeatedly prefill after tool results. A tokens-per-second number for one long answer is not a workload profile. Nor is quantizing KV the same as discarding or summarizing history. Low-bit KV retains an approximation of each stored token; eviction and summarization remove or rewrite accessible information. Their failure modes require separate evaluation.

03

Mechanism: three ledgers and the actual operator path

1. Choose the quantization unit before encoding

Given floating-point values, choose a scale and zero point, map continuous values to a finite integer grid, and approximately restore them when used. A per-tensor scale has little metadata but a few large values can stretch its range. Per-channel or per-group scales can reduce local error, yet scales, zero points, and unpacking consume bytes and compute. Packing two 4-bit values into a byte describes raw payload only. Real weights add scale metadata, alignment, sometimes higher-precision layers, and layouts tailored to a particular kernel.

2. Two common weight paths

In W4A16, weights are commonly stored in four bits while activations remain 16-bit. A kernel reads packed blocks, unpacks and rescales them, then multiplies and accumulates with high-precision activations. This can save weight residency and bandwidth without implying native 4-bit multiplication. GPTQ uses approximate second-order error information to compensate weight quantization; AWQ uses activation-aware channel saliency to protect important weights. These are different error-control strategies, not proof that four bits are lossless. Fused kernels, device support, batch size, tensor shape, and unpacking cost determine speed.

3. Activation quantization faces runtime outliers

W8A8 makes both operands candidates for an 8-bit matrix multiply, but activations depend on the input. A very large value in one channel can expand a shared scale and coarsen the grid for most ordinary values. LLM.int8() retains higher-precision computation for outlier-related channels. SmoothQuant applies reciprocal channel scaling to move difficulty from dynamic activations to statically handled weights. The unquantized matrix product is algebraically invariant under that scaling; rounding after quantization is not exact. A calibration set missing long tool logs, Chinese, code, and rare JSON can understate deployment error.

4. KV is its own growing ledger

Attention stores keys and values for historical tokens at every layer. A KV scheme scales and packs data at write or read time, then consumes packed values within an attention kernel or dequantizes them. Granularity and layout determine extra reads and compute. KIVI reports that key cache benefits from per-channel treatment while value cache favors per-token treatment in its evaluated setting. That is the paper's observation and design, not a universal rule for every architecture. Low-bit KV may permit more resident sessions or longer resident contexts, while small errors in attention logits can shift which evidence receives attention. Long-range evidence, negations, and tool logs merit separate checks.

5. Inspect the actual low-bit operator path

Use deployment artifacts and a profiler. Do compressed weights remain compressed in device memory, or are they rebuilt as an FP16 matrix each step? Does activation quantization add many separate kernel launches? Does KV unpacking erase the bandwidth saving? CPU offload, cross-device transfers, reduced batching, and unfused dequantization can make the smaller checkpoint slower. File size alone does not reveal the runtime path.

04

Essential mathematics: error and capacity

A minimal symmetric b-bit quantizer is q=clip(round(x/s),−2^(b−1),2^(b−1)−1), with x̂=sq. Here x is the original floating value, s is a positive scale for a chosen group, q is the stored integer, and x̂ is its reconstructed value. The clip bounds q to the signed b-bit range. Without saturation, rounding error is at most roughly s/2. Once a value lies beyond the representable range, saturation can make error much larger. Smaller per-group ranges can reduce local s, at the cost of more scale metadata. If quantized operands are Ŵ=W+ΔW and X̂=X+ΔX, the product error is approximately ΔY≈ΔW·X+W·ΔX, plus the second-order ΔW·ΔX term. This explains why jointly quantizing weights and activations is not simply the sum of two isolated errors: a large activation can amplify weight error.

Capacity requires a separate ledger. Ignoring metadata, seven billion FP16 weights occupy about 7×10⁹×2=14 GB of raw payload; four-bit payload is about 3.5 GB. A deployed model needs more. Raw KV payload is approximately M_KV≈2·L·T·H_kv·d_head·b/8 bytes. The factor two is keys and values; L counts layers, T historical tokens, H_kv KV heads, d_head dimensions per head, and b bits per element. With L=32, T=32,768, H_kv=8, d_head=128, and b=16, the result is about 4.29 GB per sequence. Ideal four-bit payload is about 1.07 GB before scales, fragmentation, and temporary buffers. In grouped-query attention H_kv is smaller than the query-head count; substituting query heads overstates KV size.

The engineering implication is to identify the bottleneck first. A low-batch decode dominated by weight bandwidth may benefit from W4A16. A long-context, high-concurrency service limited by KV residency may not gain concurrency merely by shrinking weights. A compute-bound prefill needs a supported low-precision arithmetic path. These figures illustrate accounting, not measured speed for a particular checkpoint or GPU.

05

Agent implications and an acceptance protocol

Compare an FP16 or BF16 baseline against candidate quantization routes using the same base checkpoint, prompts, sampling policy, tool schemas, and hardware. First break latency into prefill, decode, attention, and CPU/GPU transfers. Record time to first token, inter-token latency, p50 and p99, throughput, peak device memory, maximum stable concurrency, and energy or billing where measurable. Then compute total cost per verified correct agent outcome. A model-side speed gain can be erased by more JSON repair, tool retries, or human review.

Quality slices should include short structured tool calls with exact schema and argument checks; evidence localization inside long tool logs containing negation or version conflicts; code generation with executable tests; multiple languages; and retention of early constraints in long sessions. Generic perplexity is insufficient. Average token loss may barely move while a rare tool name or permission-relevant negation flips. External actions still go through the runtime's authorization broker and precondition checks. Quantization error does not relax authority, and a wrong answer caused by rounding should not automatically be mislabeled prompt injection.

For a staged release, place the numeric configuration in each trace: per-layer bit width, group size, scale policy, KV scheme, kernel version, batch, prompt length, device, and model version. This lets regressions be attributed to a numerical path and makes tail tasks reproducible. Roll out weight, activation, and KV changes in distinct experiments where possible; changing all three at once obscures causality.

06

Trade-offs and failure modes

  • Checkpoint size as the only metric: scale metadata, temporary buffers, unquantized layers, KV, and transfers remain. Inspect runtime profiles and stable concurrency.
  • Lower bits must be faster: missing fused kernels, unpacking, or changed batching can reverse speed. Measure by shape and separately for prefill and decode.
  • Calibration on short English chat alone: outliers and long tool-log distributions may differ. Build calibration and regression sets from deployment slices.
  • Call W4A16, W8A8, and KV4 the same '4-bit model': they compress different objects, exercise different operators, and propagate error differently. State W/A/KV widths explicitly.
  • Release a tool agent on mean perplexity: one rare-token mistake can cause an irreversible action. Verify terminal tasks and authority boundaries.
  • Assume KV4 gives four times the usable context: metadata, fragmentation, attention kernels, concurrency, and quality thresholds limit usable length.

There is no universal winning configuration. Bandwidth-bound, compute-bound, KV-capacity-bound, and quality-bound services need different settings. Even the same checkpoint can move to a different optimum when workload mix changes.

07

Reusable technical judgments

  • Weights, activations, and KV are separate ledgers; identify the runtime bottleneck before choosing what to compress.
  • Scale granularity trades error for metadata. Outliers, saturation, and unpacking determine whether low-bit storage becomes reliable speed.
  • W4A16 primarily shrinks weights; W8A8 needs supported low-precision matrix multiply; low-bit KV addresses a cache that grows with sequence and concurrency.
  • Quantization is approximate computation and does not inherit speculative decoding's exact target-distribution guarantee.
  • Accept on agent-slice verified outcomes, tail latency, and total cost, not checkpoint size or mean tokens per second alone.

Primary sources and evidence tiers

  • LLM.int8() — the authors study transformer outlier channels and a mixed-precision route.
  • SmoothQuant — the authors propose equivalent scaling that shifts activation quantization difficulty toward weights and report experiments on their models and hardware.
  • GPTQ — the authors develop post-training weight quantization using approximate second-order information.
  • AWQ — the authors present activation-aware protection of salient weights and a deployment scheme; performance is author-reported.
  • KIVI — the authors report different key/value granularity observations and a low-bit KV design.
  • PagedAttention / vLLM — the authors analyze KV residency and fragmentation in serving; cited only as cache-accounting background here.

The seven-billion-weight and KV-capacity numbers are worked examples from the displayed formulas. Agent acceptance slices, authority boundaries, and release gates are editorial engineering inferences, not universally proven product effects of these papers.

09

Established and next starting point

Established today: speculative decoding still has draft, target, and KV costs. Quantization changes residency, bandwidth, and approximation error through distinct weight, activation, and KV paths.
