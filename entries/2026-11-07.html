Multi-Agent Evidence Coordination Internals · 第 1/2 篇

多派一个 Agent，什么时候真的多一份证据？

把多执行者分派从“多开几个角色”变成按证据边界、权限和边际信息价值决策。先解决谁去查、查什么、何时停止加人；下一篇再处理证据合并与冲突裁决。

01

今日命题

一个协调器遇到线上故障，派出三个 Agent：“分析日志”“分析日志”“独立复核日志”。三份摘要都说配置变更是根因，于是它报告“三方一致”。但三名 worker 可能读了同一段被截断的日志、同一份故障猜测，甚至互相看到了对方结论。增加执行者数量，并没有增加独立证据；它可能只把一个错误包装成更强的共识。

今日命题：分派单位应是可核验的证据问题和输入边界，而不是 persona 或 worker 数量。选择下一名 worker 时，比较它在当前证据下能改变决策的边际价值、耗时、成本、权限暴露和相关错误。协作系统需要明确哪些结果可共享、哪些独立调查应先隔离，以及什么时候新 worker 只会复制已有答案。

本文承接昨天的 option 结果合同：每个子任务仍有启动条件、最小权限、typed outcome 和权威后置条件。但今天不复述 10 月 8 日关于 task store、lease、fencing、CAS 与集成器的多 Agent 运行时架构。我们聚焦信息如何被分配与获得；下一篇才讨论这些证据如何合并、冲突如何裁决。

判断标准：“三个 Agent 同意”只是三次输出。只有来源、观察路径和错误机制足够分离，而且每条主张都可追溯，才可能构成更强的证据。
02

从任务图到证据问题

前文已经有 parent、子 option、依赖图与 typed result。它们说明怎样安全运行多个任务，却没有替协调器回答“值得派谁”。若故障目标是“确认 10:00 后搜索失败率上升的原因”，先把最终主张拆成可反驳问题：失败是否与配置变更同窗？错误码是否先于变更出现？是否只影响某租户或某部署环？一条用户影响时间线能否与服务日志对齐？这些问题决定证据路线，不由 Agent 角色名决定。

Contract Net 早期研究把 manager 公告任务、候选执行者投标、授予合同作为分布式任务分配协议。其价值在于分派是显式决定：执行者能力、负载和可用资源会影响承接。但在 LLM Agent 系统里，worker 自报“我擅长调查”不是可靠投标。协调器必须使用可观察的历史成功率、工具可达性、数据新鲜度、成本和权限作为选择依据，并为每个任务设输出证据合同。

LLM self-consistency 与多 Agent debate 论文都报告了特定任务中的增益，但它们研究的是采样推理路径或相互辩论，并不证明“同模型、同检索结果的三个 worker”有独立误差。尤其在业务事实核验中，多份推理链不能替代一个权威日志事件。本文把论文结果当机制线索，不把作者实验转写成通用生产性能保证。

03

按证据边界分派的内部流程

1. 将目标编译成需要裁决的主张

parent 先记录目标版本和可接受结论：例如“配置 X 是故障的主要触发因素”，或“目前证据不足”。然后列出能支持或推翻它的观测，而不是先列“研究员 A/B/C”。日志时间线可检验先后关系，配置审计检验变更内容和部署范围，用户影响数据检验是否真的对应同一症状。每个证据问题写明精度、时间窗、实体、反例、可接受来源及缺失时该如何 abstain。这样 worker 不会为了交作业而把无法读取的证据填成猜测。

2. 形成 candidate worker 与资源矩阵

对每个问题，协调器列候选执行者和可用工具。矩阵至少包含：是否能访问权威源、对该源的权限范围、该类型任务的历史校准、预计成本和耗时、与现有 worker 共享了哪些输入与模型、是否会产生外部写入。若两个 worker 只有名字不同，却读取同一缓存摘要并使用同一工具路径，它们的边际信息可能接近零。为了降低共同原因错误，可让一名 worker 查原始日志，另一名查配置审计；但“不同模型”也不自动保证独立，若数据源同错，换模型仍会同错。

3. 写出可执行的 delegation contract

合同包含 claimId、taskId、intent/version、证据问题、输入快照与允许访问的 source IDs、工具 scope、预算、deadline、输出 schema、反例要求和失败语义。一个实用结果结构是 {claim, supportRefs, refuteRefs, coverage, uncertainty, sourceVersions, status}。status 可以是 supported、refuted、inconclusive、blocked、source_unavailable；不能把“查不到日志”编码成“未发现异常”。coverage 说明查了哪段时间、哪些租户或机器。worker 的解释写在 narrative，证据链接仍可单独核验。

4. 控制共享时机，保留独立调查

所有 worker 可共享任务目标、时间窗、定义和安全约束，这是公平的公共 brief。初始假设和其他 worker 的中间结论若过早广播，会产生 anchoring：大家随后检索相同关键词，忽略竞争解释。因此只在提交第一次 evidence packet 后，或协调器明确要求反驳时，开放对方结论。隔离不意味着隐瞒已发生的真实副作用；执行状态、取消和权限撤销仍要立即进入 canonical control state。我们隔离的是可诱导答案的分析内容，而非安全控制事件。

5. 采用逐步分派，而非固定 fan-out

先派高信息量、低风险的路线。例如日志时间线与配置审计可并行；若二者均显示变更之前已有错误，就暂停“配置致因”的确信，追加一条独立的发布/依赖状态路线，而不是再派三名 worker 摘要相同日志。若第一条权威观测已经排除某假设，继续复制该路线浪费预算；若证据覆盖有缺口，新增 worker 应专门填缺口。协调器每轮更新“哪些主张已被支持、被反驳或仍未知”，按缺口选下一任务。

6. 结果先进入 append-only evidence store

worker 只提交带来源和输入版本的 evidence packet，不直接改最终结论。Store 用 eventId 去重，并保留原始引用、采集时间、查询参数、权限上下文和不可用原因。协调器可以读取简短摘要决定是否追加调查；最终归因由证据门判断。一个 worker 的自然语言判断“高度确定”不能把另一个 worker 的反证覆盖掉。更不能让被调查的外部文档通过 prompt injection 改写分派策略或扩大 worker 的工具权限。

04

边际信息与相关错误

分派第 i 个 worker 时，最关键的量不是它能否生成答案，而是当前证据 E 下新增证据 eᵢ 可能降低多少决策损失。可用一个概念性的净价值写法：

Δᵢ(E) = 𝔼[L(a(E), θ) − L(a(E∪eᵢ), θ) | E] − Cᵢ − λTᵢ − Rᵢ

a(E) 是基于已有证据 E 的行动；θ 是未知真实状态；L 是错误决策的损失；Cᵢ 是模型、工具与审查成本；Tᵢ 是延迟，λ 将延迟换成业务损失；Rᵢ 是权限暴露和外部副作用风险。第一项代表新增证据的期望纠错价值。真实系统通常无法精确算出 θ 或期望值，应以历史同类任务、离线回放和保守区间校准；不要把模型自报 confidence 直接当概率。若上界仍不抵成本，就不该派这名 worker。

“人多力量大”的统计直觉依赖误差不完全相关。假设 n 个等方差估计的误差方差为 σ²，任意两者误差相关系数同为 ρ，则平均估计的误差方差为：

Var(mean error) = (σ²/n) × [1 + (n−1)ρ]

n 是 worker 数，σ² 是单个误差方差，ρ 表示共同错误程度。ρ=0 时方差随 1/n 缩小；ρ=1 时平均没有降方差。可把有效独立数量写成 n_eff=n/[1+(n−1)ρ]：四个 worker 若 ρ=0.6，n_eff≈1.43。这个式子是等相关连续估计的示意模型，不能直接把 LLM 的二元对错、来源质量或辩论表现塞进去算“真实准确率”。其工程含义是：先辨认共同数据源、共享初始假设和相同检索路径，再考虑增加人数。

前文讲过 critical path，这里不重复“更多并行不一定更快”的公式。更细的停止门是比较新增 worker 的边际价值与全部成本；若当前缺口是权威数据库访问失败，派更多无法访问它的 Agent 不会减少这个缺口。

05

对 Agent 系统的影响

能力与延迟

合理的 fan-out 能覆盖单个 worker 很难同时查看的独立证据面：服务日志、配置审计、用户影响。它也可能缩短取证时间，但关键收益是减少共同盲点，而非“同时思考的人更多”。调度器应允许先并行两条独立只读路线，再根据结果条件性追加；固定派五人会对简单案例浪费成本，对难题又可能全查错方向。

权限与数据治理

证据角色自然形成权限边界：读日志者不必拿发布权限，查配置者不必读取用户原文。把所有数据复制进公共上下文虽便于协作，却扩大敏感信息暴露，并让 worker 更容易共享同一错误叙事。公共 brief 可以包含目标定义与约束；原始数据仍由有权限的 worker 查询，提交最小引用与可授权的摘要。

可观察性与路由学习

每次分派记录候选与未选择原因、预期信息增益区间、实际覆盖、来源重叠、成本、延迟和最终裁决。长期可比较：某证据路线是否经常改变最终决策？worker 在某类任务上是可靠反驳者，还是只复述现有假设？这种数据支持调度改进，但必须避免只用“与最终多数一致”训练路由器；多数本身可能同源且错。

06

取舍与失败模式

独立性与共享上下文：完全隔离会让 worker 重复搜索、遗漏重要公共约束；过早分享结论又制造 anchoring 和 groupthink。共享目标、定义、时间窗和安全限制，延迟分享可争议假设；首次提交后再进行针对性互相质询。若实时安全事件发生，控制消息仍立即传播。

能力投标与自评偏差：Contract Net 式投标适合显式分配，但 LLM 自报能做什么不等于实测能力。候选筛选应以权限、工具可达和历史校准为硬门，自报计划只是次级信号。一个 worker 即使能写出漂亮的调查路线，也可能没有读取关键 source 的能力。

多样性与质量：强行使用不同模型、不同 persona，可能把低质量答案混进决策。真正有用的多样性是观察来源、查询方法、失败机制和可检验反例的差异。反过来，若两个 worker 对同一权威事件的独立解析不一致，也有价值：它暴露 schema 或解释问题，但不等于两份独立事实。

成本与停止：若新增证据只会微调措辞而不会改变用户行动，继续 fan-out 没有价值。若错误归因的代价很高，追加高成本权威核验可能值得。一个系统性失败模式是把预算耗尽后仍要求协调器给出单一确定答案；正确输出可能是明确的 inconclusive、尚缺何种证据、下一步由谁取得。

评测应包含共享错误源、被截断日志、错误初始假设、权限不足、证据延迟和真实反例。比较单 worker、固定 N worker 与条件分派策略的已核验决策质量、总成本、延迟和错误自信率，并按故障类型分层。论文中的 benchmark 增益仅作为研究报告；上线阈值须由本系统的实际损失和权限边界确定。

07

可以带走的判断

  1. 把问题拆成可核验的证据路线，而不是把同一 prompt 发给多个“角色”。
  2. 分派前检查权威源可达性、权限、实际覆盖与共同错误来源；不同模型不自动等于独立证据。
  3. 先并行少量独立只读路线，再依据证据缺口有条件追加；边际价值不抵全部成本时停止。
  4. worker 输出保留支持、反证、覆盖与不可用原因；“查不到”绝不等于“未发现”。

When Does Another Agent Actually Add Evidence?

Turn multi-agent delegation from adding role labels into a decision about evidence boundaries, authority, and marginal information value. First decide who investigates what and when to stop adding workers; the next part handles evidence merging and conflict adjudication.

2026-11-0720 min readMulti-agent / Delegation / Evidence independence / Task allocation / Correlation
01

Today's proposition

A coordinator handling an outage sends three agents to “analyze the logs,” “analyze the logs,” and “independently review the logs.” All three summaries blame a configuration change. The coordinator reports three-way agreement. Yet the workers may have read the same truncated log excerpt, inherited the same initial hypothesis, or seen each other's conclusions. More executors have not necessarily produced more independent evidence; they may have repackaged one error as consensus.

Today's proposition: delegate verifiable evidence questions with explicit input boundaries, not personas or a desired number of workers. Select an additional worker by the marginal chance that its evidence changes the current decision, together with latency, cost, authority exposure, and correlated error. The system must specify which results can be shared immediately, which investigations should remain isolated until submission, and when adding another worker is likely to repeat an existing answer.

This builds on yesterday's option result contract: each subtask still has an initiation condition, narrow authority, a typed outcome, and authoritative postconditions. It does not repeat the October 8 discussion of task stores, leases, fencing, compare-and-swap, and integrators. Our unit today is the acquisition and allocation of information. The next part will address how submitted evidence is merged and how disagreements are adjudicated.

Working criterion: “three agents agree” describes three outputs. It becomes stronger evidence only when provenance, observation paths, and likely failure mechanisms are sufficiently distinct and each claim can be traced back to a checkable source.
02

From a task graph to evidence questions

We already have a parent, child options, a dependency graph, and typed results. Those structures explain how several tasks can run safely, but they do not tell the coordinator whom to assign. For the objective “determine why search failures rose after 10:00,” first express the final claim as falsifiable questions. Did the failure begin before or after a configuration change? Did the relevant error code appear before that change? Is the effect confined to a tenant or deployment ring? Does a user-impact timeline align with service logs? These questions define evidence routes; role labels do not.

The original Contract Net research used task announcements, bids from candidate contractors, and contract awards as an explicit distributed allocation protocol. The useful idea is that assignment is a decision informed by capability, load, and available resources. For LLM agents, however, a worker's self-description that it is “good at investigation” is not a trustworthy bid. A coordinator needs observed performance on similar tasks, tool reachability, data freshness, cost, and authority limits, plus an output evidence contract for each assignment.

Self-consistency and multi-agent debate papers report gains on particular benchmarks, but their results concern sampled reasoning paths or interactive debate. They do not establish that three workers using the same model and retrieved excerpt have independent errors. In a business investigation, multiple chains of reasoning cannot replace an authoritative log event. We use those papers as clues to mechanisms, not universal production-performance guarantees.

03

A delegation flow built around evidence boundaries

1. Compile the goal into claims that need adjudication

The parent records the goal version and acceptable conclusions, such as “configuration X was the main trigger” or “the evidence is insufficient.” It then lists observations that could support or falsify each claim, before naming researchers A, B, and C. A log timeline tests temporal order; configuration audit tests the actual change and rollout scope; user-impact data tests whether the same symptom affected real users. Each evidence question specifies entity, time window, granularity, counterexamples, acceptable sources, and when missing evidence requires abstention. This makes it harder for a worker to fill an inaccessible source with a guess simply to produce an answer.

2. Build a candidate-worker and resource matrix

For each question, the coordinator lists candidate executors and tools. The matrix includes access to an authoritative source, exact authority scope, historical calibration on this task type, expected cost and latency, shared inputs and model dependencies with existing workers, and whether the work can create an external write. Two workers with different names but the same cached summary and tool path may have almost zero marginal information. To reduce common-cause error, one can inspect raw logs while another examines a configuration audit. Merely switching models does not guarantee independence: if the source itself is wrong, different models can repeat the same error.

3. Issue an executable delegation contract

A contract identifies claimId, taskId, intent and plan version, the evidence question, input snapshot and allowed source IDs, tool scope, budget, deadline, output schema, counterexample requirement, and failure semantics. A useful result is {claim, supportRefs, refuteRefs, coverage, uncertainty, sourceVersions, status}. Status may be supported, refuted, inconclusive, blocked, or source_unavailable. “Could not read the logs” must not be encoded as “found no abnormality.” Coverage says which time interval, tenants, or machines were actually inspected. A narrative explanation helps a reader, but the referenced observations must remain independently checkable.

4. Control when workers see each other's conclusions

Workers may share the goal, time window, definitions, and safety constraints as a common brief. Broadcasting an initial hypothesis or another worker's interim conclusion too early can anchor the group: they search for the same terms and neglect competing explanations. Keep investigative conclusions isolated until the first evidence packet is submitted, or until a coordinator explicitly requests rebuttal. Isolation never means hiding real side effects. Execution status, cancellation, and revoked authority still enter canonical control state immediately. The isolation applies to analysis that can bias answers, not to safety-control events.

5. Delegate sequentially when evidence changes the question

Begin with high-information, low-risk routes. Log timeline and configuration audit can run concurrently. If both show errors preceding the change, pause confidence in the configuration hypothesis and request an independent release or dependency-state route instead of assigning three more workers to summarize the same logs. If one authoritative observation already rules out a hypothesis, repeating that route wastes budget. If coverage is missing, the next worker should target precisely the missing interval, population, or system boundary. After each packet, update which claims are supported, refuted, or unresolved, then choose the next task from the remaining gaps.

6. Put results into an append-only evidence store

A worker submits a sourced, versioned evidence packet; it does not edit the final conclusion directly. The store deduplicates by event ID and retains original references, collection time, query parameters, authority context, and reasons a source was unavailable. The coordinator reads a compact summary to decide whether to investigate further, while a later evidence gate decides the final attribution. One worker's natural-language statement of “high confidence” cannot overwrite another worker's refuting evidence. Nor may an external document being investigated use prompt injection to change the allocation policy or expand a worker's tool authority.

while budget_remains:
  gap = highest_impact_unresolved_claim()
  candidates = authorized_workers_for(gap)
  worker = argmax_expected_marginal_evidence(candidates, current_evidence)
  if worker is None or expected_gain(worker) <= full_cost(worker): break
  packet = dispatch_with_source_boundary(worker, gap)
  append_evidence(packet)
  update_coverage_and_dependencies(packet)

This pseudocode is an editorial scheduling sketch, not a published paper's algorithm. It deliberately permits an inconclusive outcome. If the budget is exhausted, an authoritative source is unavailable, or remaining sources are too dependent, “not verified” is safer than an invented multi-agent consensus.

04

Marginal information and correlated error

When assigning worker i, the important quantity is not whether it can produce an answer. It is the expected reduction in decision loss from its evidence eᵢ given the evidence E already collected. A conceptual net-value objective is:

Δᵢ(E) = 𝔼[L(a(E), θ) − L(a(E∪eᵢ), θ) | E] − Cᵢ − λTᵢ − Rᵢ

a(E) is the action chosen from existing evidence; θ is the unknown true state; L is the loss from a mistaken decision. Cᵢ is model, tool, and review cost; Tᵢ is latency; λ converts that latency into business loss; Rᵢ represents authority exposure and external-effect risk. The first term is the expected value of correcting a decision. A real system rarely knows θ or this expectation exactly. It can calibrate conservative ranges from similar historical tasks and offline replay. The model's self-reported confidence is not a probability estimate. If even an optimistic gain bound is below full cost, the worker should not be assigned.

The intuition that a group improves accuracy depends on errors being less than perfectly correlated. Suppose n estimates have equal error variance σ² and every pair has the same error correlation ρ. The variance of their mean error is:

Var(mean error) = (σ²/n) × [1 + (n−1)ρ]

Here n is the worker count, σ² the variance of one error, and ρ the degree of common error. At ρ=0, variance decreases as 1/n. At ρ=1, averaging gains nothing. An effective independent count is n_eff=n/[1+(n−1)ρ]. Four workers with ρ=0.6 have n_eff≈1.43. This is an illustration for equally correlated continuous estimates; it cannot be substituted directly for an LLM's binary correctness, source quality, or debate performance to compute a “true accuracy.” Its engineering message is to inspect shared data sources, initial hypotheses, and retrieval paths before paying for more agents.

We covered critical-path speed limits earlier and need not repeat them. The more relevant stopping gate here compares the marginal value of another worker with its full cost. If the present gap is failure to access an authoritative database, assigning additional agents that also cannot access it will not close the gap.

05

Implications for agent systems

Capability and latency

Useful fan-out covers genuinely different evidence surfaces that one worker may struggle to inspect together: service logs, configuration audit, and user impact. It may also reduce investigation time, but the central gain is fewer shared blind spots, not simply more simultaneous thinking. A scheduler can launch two independent read-only routes, then add a targeted route conditionally. A fixed five-worker policy wastes money on easy cases and may still send everyone down the wrong path on hard ones.

Authority and data governance

Evidence roles create natural authority boundaries. A log reader does not need deployment rights; a configuration investigator need not receive raw user text. Copying all data into a common prompt is convenient but broadens sensitive-data exposure and makes the workers more likely to inherit the same mistaken narrative. A common brief can contain the goal and constraints. Raw sources remain queried by authorized workers, who submit minimal references and appropriately scoped summaries.

Observability and routing improvement

For each assignment, record candidates, reasons for declining others, an expected information-gain range, actual coverage, source overlap, cost, latency, and the final adjudication. Over time, the system can ask whether a route often changes the final decision and whether a worker is a useful falsifier or merely restates the initial hypothesis. Such data can improve allocation, but training the router only on “agreement with the final majority” is dangerous: the majority may share one source and one error.

06

Trade-offs and failure modes

Independence versus shared context: complete isolation duplicates searches and can hide essential common constraints; premature sharing anchors workers to an early hypothesis. Share goals, definitions, time windows, and safety limits, but delay disputed conclusions until an initial packet is submitted. Then ask workers to challenge specific evidence. Real-time safety-control events still propagate immediately.

Capability bids and self-assessment bias: Contract Net-style bidding makes allocation explicit, but an LLM's assertion of competence is not measured capability. Permission, tool access, and calibrated historical results should be hard candidate gates; a proposed plan is only a secondary signal. A worker may write an excellent investigation outline yet be unable to read the decisive source.

Diversity versus quality: forcing different models or personas into a panel can add low-quality answers. Useful diversity concerns observation sources, query methods, failure mechanisms, and testable counterexamples. Conversely, if two workers interpret the same authoritative event differently, the disagreement is useful because it exposes a schema or interpretation problem. It still is not two independent facts.

Cost and stopping: if additional evidence can only change wording and not the user's action, continued fan-out has little value. If a wrong attribution carries severe loss, an expensive authoritative check may be worthwhile. A common failure is requiring a single definite answer after the budget runs out. The proper result may be inconclusive, with the missing evidence and the party who can obtain it identified explicitly.

Evaluate with shared erroneous sources, truncated logs, wrong initial hypotheses, inadequate permissions, delayed evidence, and real counterexamples. Compare a single worker, a fixed N-worker panel, and conditional allocation on verified decision quality, total cost, latency, and false-confidence rate, stratified by incident type. Benchmark gains in cited papers remain author-reported research results; rollout thresholds must reflect this system's actual losses and authority boundaries.

07

Reusable judgments

  1. Decompose a goal into verifiable evidence routes instead of sending the same prompt to several named roles.
  2. Before assignment, check authoritative-source reachability, authority, actual coverage, and common causes of error. A different model does not automatically add independent evidence.
  3. Run a few distinct read-only routes first, then add workers conditionally to fill evidence gaps; stop when marginal value does not cover full cost.
  4. Retain support, refutation, coverage, and unavailable-source reasons in every worker packet. “Could not inspect” never means “found no problem.”

09

Where this series stands

Established today: coordination across executors starts with information allocation. The parent compiles a goal into falsifiable claims and distinct source routes; worker contracts specify authority, coverage, counterexamples, and typed outcomes. Workers share a common brief but delay sharing conclusions that can anchor one another. The scheduler uses remaining evidence gaps and marginal net value to decide whether to add another worker. Correlated errors reduce the effective information in a larger panel.

Still open: when logs, audit records, and user-impact observations disagree, how should the coordinator align and merge them by provenance, time, entity, and authority? How can it distinguish a true contradiction from different coverage? When must a verifier abstain and escalate to a human, and what release gate should control a terminal attribution?
