声音、画面都对上了，Agent 为什么仍不该立刻行动？

时间关联之后仍要解决说话人归属、物体指代、证据依赖与授权；冲突时的正确动作可能是澄清。

01

今日命题

会议画面里有两个人，屏幕共享区也有两个叫 Alex 的联系人。音频里有人说‘把这个发给 Alex’，字幕重复同一句，指针恰好停在左侧联系人附近。所有信号时间上对齐，Agent 仍不知道：声音来自画面中谁、‘这个’是文件还是消息、Alex 是哪一个，以及说话者是否有发送权限。若把时间重合、字幕一致和指针位置当作三份独立证明，系统会非常自信地犯错。跨模态融合要把“候选解释”与“可执行决定”分开。

昨天的 1/2 建立 event time、available_at、clock mapping 和因果截止：只用当时可用的音视频，迟到帧不能追认旧动作。今天从这些时间合格的候选出发，处理来源可信度、可见说话人、物体指代、相互依赖的证据、澄清和工具提交。我们不再推 RTP 映射，也不重复视觉 patch 或语音 WER；最终要给 2/2 一个完整的 Agent runtime 合同。

02

时间合格只是候选，不是身份或指代

昨天的 evidence bundle 已有音频区间、候选帧、映射误差、available_at、UI observation 版本。它能排除‘晚到的 B 卡片被错配到说 A 时’这类时间错误，却无法说明同一帧中哪个人开口。可见嘴部运动可帮助 active speaker detection，但画外音、配音、摄像头关闭、多人同时说话和音视频回放都会破坏‘画面中有人张嘴＝授权用户在说话’的推断。AVA-ActiveSpeaker 与 TalkNet 的作者研究谁在画面中说话的识别任务；模型输出是感知假设，不是企业身份凭证。

同样，视觉 grounding 可以把短语关联到框或区域，却不保证用户说的‘这个’指那一区域。MDETR 等工作把语言与检测目标联合建模；它不替代会话中手势、屏幕所有权、滚动历史或工具参数的确认。ImageBind 展示跨模态 embedding 可以邻近，但邻近是语义相似，不是某个声音由某张脸发出、某个指针由发言人控制的因果证明。Agent 应将这些输出作为带来源和置信范围的边，而不是把它们压成一行‘用户要发给 Alex’。

旧的可靠性和工具专题已经给出授权原则：模型只能提议，broker 决定权限与副作用。跨模态输入扩大了提议的证据面，也扩大了低信任面。屏幕上的字幕可能来自 ASR、会议软件或网页文字；三者不是同一来源。即使字幕和音频完全一致，若字幕本来就由那段音频自动生成，就不能当作第二个独立证人。

03

机制：有来源的证据图与分层提交

1. 不抹平原始证据

从昨日时间合格的 bundle 建立节点：音频说话片段和 ASR 修订、可见人物 track、手势/指针轨迹、屏幕对象稳定 ID、字幕或 OCR，以及已认证会话主体。边分类型：时间重合、嘴型-语音匹配、语言指代、指针-对象几何、字幕派生关系。每条边保存来源、模型/预处理版本、支持证据和不确定度。不要把‘同一时间’边升级成‘同一人’，也不要把‘字幕文字’与原音频算成两个独立来源。

2. 对说话人归属保留未知

声源分离或 diarization 可区分音频中的说话轮次；active-speaker 模型可指出某时间窗内哪个可见人似在说话。两者合起来仍可能遇到画外人、镜头延迟、遮挡或合成声。系统应允许 speaker=unknown 和多候选，而不是强迫每个 turn 对应一张脸。显示姓名、声音相似或视频头像都不能替代登录会话的权限。若要执行高风险动作，独立身份与本轮参数确认必须来自授权通道。

3. 解指代时把候选与排除证据都放上桌

‘这个’的候选可以来自指针落点、手势方向、当前选中项、屏幕共享者的操作历史和语义上下文。每种线索的所有权不同：远端共享屏幕的指针不一定是说话人控制，自动字幕不是新指令，网页文本可能是低信任内容。若两个 Alex 均在画面里，语言模型即便偏好一个，也应记录第二候选与差异。通过稳定对象 ID 而非像素坐标绑定动作参数；如果对象在确认前变化，原提案失效。

4. 把冲突路由为澄清或安全降级

可设三条 runtime 路径：证据充分且动作只读，返回带不确定性的答案；候选冲突或关键参数缺失，追问‘你指文件还是消息？哪位 Alex？’；授权不成立或高风险状态未知，拒绝副作用并交人工或只读。追问要具体指出缺的字段，不能用笼统‘请再说一遍’增加用户负担。模型可建议问题，但外层策略决定哪些字段必须确认。迟到或修订的证据开启新 epoch；已经发出的工具不能因新分数变高就暗中重写历史。

5. 只有外层 broker 跨越提交边界

工具提案应包含 action ID、目标对象稳定 ID、收件人/内容、证据 bundle 版本、确认对象与授权主体。broker 复核当前 UI/业务状态、权限、幂等键和确认是否绑定这些参数；不通过即不执行。执行后用权威回执核验收件人和内容，而非让模型说‘已发送’就算完成。音视频融合负责提出与解释，不能把感知信心当 credential。网页、字幕或会议背景音中的‘忽略限制’仍是数据，不能改写工具政策。

6. 用同一测试集拆开三类错误

固定用户意图与工具状态，分别交换说话人、指针所有者、字幕来源和两个同名对象；再加入异步迟到。记录时间合格率、说话人归属、对象指代、澄清准确性、越权提案被拒、工具终态与残余副作用。一个系统可能会多问一次，却显著减少错误发送；也可能把所有场景都拒绝，安全但无用。评测需要同时量可执行覆盖率与已执行错误率，不能只报一个‘融合准确率’。

04

必要数学：依赖证据与选择性执行

令 c 是某个候选解释，例如‘用户指左侧 Alex’，E_a 是音频/转写证据，E_v 是画面、指针或字幕等其他观测。贝叶斯式 P(c|E_a,E_v)∝P(E_a,E_v|c)P(c) 只是说明：更新候选要考虑证据的联合似然与先验。若写成 P(E_a|c)P(E_v|c)，额外假设两路在给定 c 后条件独立。自动字幕来自同一音频、指针与截图来自同一共享屏幕时，这一假设常不成立；重复乘会把一条错证据算成两票。未校准的模型分数只能排序，不能直接宣称为概率或跨设备沿用阈值。

对预先标注的可行动会话数 N，令 X 为系统实际执行的数量，W 为其中对象、参数或权限错误的数量。定义 coverage=X/N 与 selective error=W/X（X>0 时）。coverage 衡量系统能否完成而非一律拒绝，selective error 衡量已执行动作的错误；两者都按说话人、同名对象、屏幕所有权与风险级切片。若 X=0，错误率不可定义，必须报告零覆盖，不能说‘零错误、安全上线’。安全硬门另报越权副作用数，不能用平均 coverage 抵消。

在已通过权限门的低风险候选中，可用简化损失比较执行与澄清：L_act=(1−p)·C_wrong+C_action，L_ask=C_ask。p 是经过校准、针对该候选的正确概率；C_wrong 是错动作代价，C_action 是执行本身代价，C_ask 是澄清路径的总预期代价，包含等待和后续可能执行的成本。若 L_act 高于 L_ask，就倾向追问。这里的代价是产品选择，不是论文通用常数；高风险越权动作不进入这个优化式，权限失败时无论 p 多高都禁止执行。

05

对 Agent 架构与验收的影响

数据契约应区分 observation、interpretation、authorization 与 action。observation 是带时间和来源的音频、帧、字幕、指针；interpretation 是候选说话人/物体/意图及反证；authorization 是独立会话凭据与参数绑定确认；action 是带幂等与终态核验的工具调用。让模型输出结构化候选和未决字段，broker 只接收通过复核的 action proposal。这样可以更换 active-speaker 或 grounding 模型而不把权限逻辑嵌进其 logits。

trace 要能重建‘当时系统知道什么’：bundle 版本、各证据来源、派生关系、候选与分数是否校准、澄清问题、用户确认、工具请求和权威回执。不要把说话人脸部或原声无限保存为排障捷径；存受控引用与必要时间片。字幕与 OCR 中的指令仍处于低信任层，不因为出现在 prompt 中就能改变开发者或用户授权。模型若误提议危险动作，broker 拒绝与最终无副作用要分别计数。

上线评测应采用同一批会话的反事实配对：只换发言人但保持字幕、只换指针所有者、把两个 Alex 对调、让字幕滞后或让共享画面出现提示注入。比较正确归属、澄清的针对性、执行覆盖、已执行错误、未授权工具拒绝、终态和 p95/p99 决策延迟。通过改进模型分数得到的少问一次，若同时增加错发，未必是进步。服务还需有‘只读/需确认/可执行’风险开关；在证据不足或模型更新后切回安全路径。

06

取舍与失败模式

  • 时间同步即同一说话人：旁白、画外音、重叠说话和嘴型误匹配仍存在；归属可为 unknown。
  • 字幕与音频一致算双证据：字幕可能由该音频生成；保留派生关系，避免重复计权。
  • 指针靠近目标就代表发言人选中：共享屏幕操作者可能是另一人；记录控制权与当前对象 ID。
  • 最高分候选必选：两个候选接近时追问具体缺失字段，不强行执行。
  • 高置信度可越过权限：模型分数只影响解释，broker 的身份与工具政策是硬门。
  • 一律拒绝最安全：零错发也可能零完成；同时报告覆盖率、错误率和澄清成本。
  • 确认后对象不会变化：列表可重排或工具已提交；执行前查当前状态，超时后核对终态。

证据图提高可审计性，却增加 token、延迟和状态管理。可只向模型提供与当前问题有关的候选与摘要，把完整来源链留在 runtime；但摘要不能隐藏反证。更少澄清让对话流畅，却会把模糊成本转嫁为错发或越权。风险高时，多一步精确确认通常比一次漂亮的猜测便宜。

07

可复用的技术判断

  • 时间对齐只产生候选关联；说话人、物体指代与授权是不同边界。
  • 保留证据的来源和派生关系，不能把自动字幕与原音频当独立两票。
  • 模型分数需校准才可解释为概率；最高分仍可能需要针对性澄清。
  • 先绑定对象、参数与确认，再由 broker 复核当前状态和权限，最后核验工具终态。
  • 同时报告执行覆盖与已执行错误；零执行不能伪装成零风险的成功。
08

一手资料与证据等级

  • AVA-ActiveSpeaker — 作者提出音视频 active-speaker 数据集与任务；可见说话检测不等于身份认证。
  • Is Someone Speaking? / TalkNet — 作者研究长时上下文的音视频说话人检测；结果属其评测设置。
  • MDETR — 作者研究文本调制的目标检测与跨模态定位；不证明真实会话指代或授权。
  • ImageBind — 作者研究共享跨模态 embedding；语义邻近不是因果或权限证明。
  • Indirect Prompt Injection — 作者展示低信任内容影响 LLM 应用；本文仅把信任边界用于字幕、网页和背景音的工程分析。

09

两篇综合与下一段路线

本系列已讲完：1/2 将音频与视频的采集、到达和可用时刻分开，映到有不确定度的共同轴；event-time 对齐与因果截止只让当时可见证据进入候选。2/2 把时间合格证据做成有来源的关联图：说话人、字幕、指针与物体指代都可保持未知或冲突；模型只提解释，澄清绑定对象和参数，外层 broker 复核权限、当前状态并核验工具终态。完整链路是‘时序采集 → 因果候选 → 有来源的融合/反证 → 澄清或拒绝 → 授权工具 → 权威结果’。

仍需持续验证：场景和参与者会变，字幕、ASR、视觉模型、设备延迟与共享屏幕控制权也会漂移。上线后的异常要能回溯到当时可用证据，而非用事后完整视频改写决策记录；系列完结不表示某个部署已安全。

The Sound and Picture Align. Why Shouldn't the Agent Act Yet?

Temporal alignment leaves speaker attribution, referent resolution, dependent evidence, and authorization unresolved; clarification can be the right action.

2026-10-3120 min readMultimodal fusion / Active speaker / Reference resolution / Provenance / Abstention / Tool commit
01

Today's proposition

Two people appear in a meeting video while a shared screen shows two contacts named Alex. Someone says, 'Send this to Alex.' A caption repeats the sentence and the pointer happens to rest near the left contact. Every signal aligns in time. The agent still does not know who spoke, whether 'this' means a file or a message, which Alex is intended, or whether the speaker has permission to send. Treating temporal coincidence, caption agreement, and pointer position as three independent proofs produces confident failure. Multimodal fusion must separate candidate interpretations from executable decisions.

Part 1 established event time, available_at, clock mapping, and a causal deadline: use only audiovisual evidence available at decision time; late frames cannot retroactively authorize an old action. Today begins with temporally eligible candidates and handles provenance, visible-speaker attribution, object reference, dependent evidence, clarification, and tool commitment. We do not repeat RTP mapping, visual patches, or speech word error rate. The goal is a complete runtime contract for this two-part series.

02

Temporal eligibility is a candidate filter, not identity or reference

Part 1's evidence bundle contains audio intervals, candidate frames, mapping error, available_at, and UI observation versions. It excludes a temporal error such as pairing a late card B frame with the earlier utterance about A. It cannot say which person in one frame spoke. Visible mouth motion can aid active-speaker detection, but voice-over, dubbing, camera-off participants, overlapping speech, and replay defeat the leap from 'someone's mouth moved' to 'the authorized user spoke.' AVA-ActiveSpeaker and TalkNet investigate the perceptual task of who is visibly speaking. Their outputs are hypotheses, not enterprise identity credentials.

Visual grounding can associate a phrase with a box or region, but it does not prove that the user's 'this' refers to that region. MDETR jointly models text and detection targets; it does not replace conversational gesture, screen ownership, scroll history, or tool-parameter confirmation. ImageBind shows that cross-modal embeddings can be close, but semantic proximity is not causal proof that a voice came from a face or that a pointer was controlled by the speaker. The agent should retain those outputs as provenance-bearing, uncertain edges rather than compress them into 'the user wants to send to Alex.'

Earlier reliability and tool lessons established the authority boundary: a model proposes, a broker decides permissions and effects. Multimodal input broadens the evidence for a proposal and the lower-trust surface. A caption may come from ASR, meeting software, or text on a webpage; those are not interchangeable sources. Even perfect caption-audio agreement is not a second independent witness when the caption was generated from that very audio.

03

Mechanism: a provenance graph and staged commitment

1. Preserve raw evidence distinctions

Build nodes from Part 1's temporally eligible bundle: speech segments and ASR revisions, visible person tracks, gesture or pointer trajectories, stable screen-object IDs, captions or OCR, and the authenticated session principal. Type the edges: temporal overlap, lip-to-speech match, linguistic reference, pointer-to-object geometry, and caption derivation. Every edge retains source, model and preprocessing version, supporting observations, and uncertainty. Never promote a 'same time' edge to 'same person,' or count caption text derived from audio as a second independent source.

2. Preserve unknown speaker attribution

Audio diarization or source separation may distinguish turns in sound. An active-speaker model may identify which visible person appears to be talking in a time window. Together they still encounter off-screen speech, camera delay, occlusion, and synthetic voices. Permit speaker=unknown and multiple candidates rather than forcing each turn onto one face. A display name, familiar voice, or video avatar does not replace permission from an authenticated session. For high-risk effects, independent identity and fresh parameter-bound confirmation must arrive through an authorized channel.

3. Resolve references with both support and disconfirming evidence

Candidates for 'this' may come from pointer location, gesture direction, selected item, the screen sharer's interaction history, and linguistic context. Ownership differs. A pointer on a remotely shared screen may not be controlled by the speaker; an auto-caption is not a fresh instruction; webpage text may be lower-trust content. If two people named Alex appear, the model's preference for one does not erase the other. Retain the runner-up and the discriminating features. Bind action parameters to stable object IDs rather than pixels. If an object changes before confirmation, expire the proposal.

4. Route conflict to clarification or safe downgrade

The runtime can have three paths. With sufficient evidence and a read-only task, answer with appropriate uncertainty. With conflicting candidates or a missing critical parameter, ask 'Do you mean the file or the message? Which Alex?' If authorization fails or a high-risk state is unknown, withhold the effect and use a human or read-only path. A clarification question should identify the missing field, not repeatedly ask the user to say everything again. The model may suggest a question, but outer policy determines which fields require confirmation. Late or revised evidence starts a new epoch; it cannot silently rewrite the history of a tool already sent.

5. Only the outer broker crosses the commit boundary

A tool proposal includes action ID, stable target-object ID, recipient and content, evidence-bundle version, confirmation subject, and authenticated principal. The broker rechecks current UI or business state, authority, idempotency key, and whether confirmation binds those exact parameters. If a check fails, it does not execute. After execution, verify recipient and content against an authoritative receipt rather than accepting the model's 'sent' narration. Audiovisual fusion proposes and explains; perceptual confidence is not a credential. 'Ignore restrictions' inside a webpage, caption, or background meeting audio remains data and cannot rewrite tool policy.

6. Separate three failure families on one corpus

Hold user intent and tool state fixed while changing speaker, pointer owner, caption provenance, and two same-name objects; add asynchronous late arrival. Record temporal eligibility, speaker attribution, object reference, clarification quality, refusal of unauthorized proposals, tool terminal state, and residual side effects. One system may ask an extra question but dramatically reduce wrong recipients. Another may refuse every task: safe in one sense, useless in another. Evaluation must report both executable coverage and error among executed actions, not a single 'fusion accuracy' number.

04

Essential mathematics: dependent evidence and selective execution

Let c be a candidate interpretation such as 'the user means the Alex on the left,' E_a audio or transcript evidence, and E_v other observations such as video, pointer, or captions. Bayes' rule gives P(c|E_a,E_v)∝P(E_a,E_v|c)P(c): updating a candidate depends on joint evidence likelihood and prior. Replacing the joint likelihood with P(E_a|c)P(E_v|c) additionally assumes conditional independence given c. An automatic caption derived from the same audio, or a pointer and screenshot from one shared screen, often violate that assumption. Multiplication then counts one bad observation twice and creates false confidence. Uncalibrated model scores rank candidates; they are not probabilities and do not justify a universal threshold across devices.

For N pre-labeled eligible conversations, let X be the number on which the system executes and W the number of those executions with a wrong object, parameter, or authority. Define coverage=X/N and selective error=W/X when X is positive. Coverage detects a system that refuses everything; selective error describes mistakes among actions it did take. Slice both by speaker configuration, same-name objects, screen ownership, and risk. If X is zero, the error rate is undefined. Report zero coverage rather than 'zero errors, safe to ship.' Count unauthorized external effects as an independent hard gate; mean coverage cannot offset one.

Within low-risk candidates that already pass the permission gate, compare execution with clarification using a simple loss model: L_act=(1−p)·C_wrong+C_action and L_ask=C_ask. Here p is a calibrated probability that the candidate is correct; C_wrong is the cost of a wrong action, C_action the cost of executing, and C_ask the expected total cost of the clarification path, including delay and any later execution. Prefer asking when L_act exceeds L_ask. These costs are product choices, not universal constants from a paper. An unauthorized high-risk action is never entered into this optimization: failed authority blocks execution regardless of p.

05

Implications for agent architecture and acceptance

The data contract should separate observation, interpretation, authorization, and action. Observation contains timed and sourced audio, frames, captions, and pointer traces. Interpretation contains candidate speakers, objects, and intents plus disconfirming evidence. Authorization comes from independent session credentials and confirmation tied to exact parameters. Action is a tool call with idempotency and authoritative outcome verification. Ask the model for structured candidates and unresolved fields; the broker accepts only a proposal that passes its checks. Active-speaker or grounding models can then change without burying permission logic inside their logits.

A trace should reconstruct what the system knew at the time: bundle version, evidence provenance and derivation, candidates and whether scores were calibrated, clarification question, user confirmation, tool request, and authoritative receipt. Do not retain faces or raw voices indefinitely as a debugging shortcut; use controlled references and necessary intervals. Instructions inside captions or OCR stay lower-trust data. Their appearance in a prompt does not modify developer rules or user authority. Count an unsafe model proposal, broker refusal, and absence of external side effect separately.

Use counterfactual pairs from the same conversation set in acceptance: swap the speaker while keeping the caption, change pointer ownership, exchange two Alex contacts, delay the caption, or place a prompt injection on the shared screen. Compare correct attribution, targeted clarification, execution coverage, error among executed actions, refusal of unauthorized tools, final state, and p95 or p99 decision latency. Fewer questions due to a model-score change are not progress if wrong sends increase. Keep a risk switch among read-only, confirmation-required, and effectful modes; fall back when evidence is thin or a model update changes behavior.

06

Trade-offs and failure modes

  • Synchronized means same speaker: narration, off-screen speech, overlap, and mistaken lip matching remain. Attribution may be unknown.
  • Caption plus audio equals two witnesses: the caption may derive from that audio. Preserve derivation to avoid double counting.
  • Pointer proximity means speaker selection: another person may control the shared screen. Record control and stable object ID.
  • Always choose the top score: when candidates are close, ask for the missing field rather than force execution.
  • High confidence overrides authority: model scores affect interpretation; identity and tool policy at the broker are hard gates.
  • Reject everything to be safe: zero wrong sends can come with zero useful completion. Report coverage, errors, and clarification cost together.
  • An object stays fixed after confirmation: lists reorder and tools may commit. Check current state before action and authoritative outcome after timeout.

A provenance graph improves auditability but adds tokens, latency, and state. Give the model only candidates and summaries relevant to the question, leaving the full derivation chain in the runtime; the summary must not hide disconfirming evidence. Fewer clarification turns make dialogue smooth, but transfer ambiguity cost into wrong recipients or unauthorized effects. Under high risk, one precise confirmation is often cheaper than a polished guess.

07

Reusable technical judgments

  • Temporal alignment creates candidate association only; speaker, object reference, and authorization are separate boundaries.
  • Keep evidence provenance and derivation. An auto-caption and its source audio are not independent votes.
  • Model scores require calibration before they can be probabilities; the highest score may still warrant targeted clarification.
  • Bind object, parameters, and confirmation; let a broker recheck current state and authority, then verify the tool outcome.
  • Report execution coverage and error among executed actions together. Zero execution is not a success disguised as zero risk.
08

Primary sources and evidence tiers

  • AVA-ActiveSpeaker — the authors introduce an audiovisual active-speaker dataset and task; detecting visible speech is not authentication.
  • Is Someone Speaking? / TalkNet — the authors study longer-term audiovisual active-speaker features; results belong to their evaluation setup.
  • MDETR — the authors study text-modulated detection and cross-modal grounding, not authorization or live conversational reference.
  • ImageBind — the authors study a shared cross-modal embedding; semantic proximity is neither causal proof nor a permission grant.
  • Indirect Prompt Injection — the authors demonstrate low-trust content influencing LLM applications. We apply the trust-boundary idea to captions, webpages, and background audio as engineering analysis.

Links and titles were checked on 2026-10-31. The provenance graph, selective-execution metrics, loss model, and broker gate are editorial designs. These papers do not jointly define one production agent protocol.

09

Series synthesis and the next path

This series is complete: Part 1 separated audio and video capture, arrival, and availability time and mapped them to a common axis with uncertainty. Event-time alignment and a causal deadline admit only evidence visible then into candidate sets. Part 2 turns temporally eligible evidence into a provenance graph: speaker, caption, pointer, and object reference may remain unknown or conflicting. The model proposes interpretations. Clarification binds object and parameters; an outer broker checks authority and current state and verifies the tool outcome. The full path is temporal capture → causal candidates → sourced fusion and disconfirmation → clarification or refusal → authorized tool → authoritative result.

Continuing operational concern: scenes and participants change. Captions, ASR, visual models, device delay, and screen-control ownership drift. Production anomalies must be reconstructable from evidence available at the time, not rewritten using complete video found later. Completing a series does not certify one deployment as safe.

Next starting point: the systematic path can examine an agent's updateable world state: which observations become durable facts, when they expire, and when new evidence overturns or requires re-verification. Today's candidate associations should not silently harden into permanent memory.
