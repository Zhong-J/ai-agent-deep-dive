Context 与 Memory 系统 · 第 2/4 篇

摘要会撒谎：Agent 如何安全压缩长历史？

从 lossless history 到 working state、rolling summary 与 hierarchical summary，设计可回源、可重算且有 error budget 的压缩协议。

2026-09-22约 20 分钟Context compression / Summarization / State abstraction / Provenance / Error budget
01

今日命题

长运行 Agent 必须压缩历史，但任何摘要都是 lossy transform。它会选择什么重要、合并相似事件、删除重复细节，并用新措辞重写原文。危险不在于它偶尔少一句，而在于摘要常被下一轮模型当成事实：一次遗漏的否定词、过期约束或未决副作用，会在后续反复 summary-of-summary 中变成稳定但错误的 working reality。

安全设计不能要求摘要“绝不出错”。它要把不可丢的 control state 从自由文本中抽离，让摘要只服务检索与推理；每个 summary 声明覆盖的 event range、生成器版本、source references 与已知 omissions；遇到高风险决策、冲突或低 confidence 时，runtime 回到原始 event/artifact 重建，而不是继续相信压缩文本。

核心判断：compression 的 correctness contract 不是“读起来像原对话”，而是：invariants 保真、provenance 可追、信息损失可度量、派生视图可丢弃重算。原始 history 是事实层；summary 是有版本的 cache。
02

承接四层边界：只压缩该压缩的层

1/4 已把 event log、working state、retrieval index 与 durable records 分开。这个边界直接决定压缩方式：event log 可以归档、分段和索引，但不应被 summary 替换；working state 由 typed reducer 更新，不应让模型从摘要猜 open calls、deadline 或 approval；durable record 通过 supersession/versioning 演化；只有供模型消费的 transcript view 与导航性 memory 可以有损压缩。

因此“达到 80% context 后做一次摘要”太粗。它把 token pressure 当作唯一触发条件，却忽略语义边界：tool transaction 未完成、审批范围尚未确定、两份来源冲突时，恰恰不能把它们揉成一个顺畅段落。正确触发器还包括 episode 结束、state checkpoint、topic shift、artifact 完成和风险等级变化。

压缩也不是单方向删除。摘要首先是目录：告诉 assembler 哪个时间段发生了什么、哪些 source 需要在当前任务中展开。只要保留 source span 与 stable record ID，系统就能按需 rehydrate 原文，把小 context window 与大持久历史连接起来。

03

机制：三层压缩与可逆引用

1. 先抽取 invariant lane

每次压缩前，runtime 从 typed state 读取必须精确保留的字段：goal、hard constraints、授权范围、open operations、unresolved outcomes、deadlines、accepted artifact IDs、用户明确决定。这些字段由 schema/reducer 管理，summary 只能引用，不能改写。若摘要说“部署完成”而 state 仍是 verification_pending，assembler 必须以 state 为准并显式暴露矛盾。

2. 按 episode 建 rolling summary

episode 是语义闭合单元，如一次调查、一个 tool transaction 或一轮审批。summary record 包含 summaryId、source event range、artifact refs、createdAt、generator model/prompt version、covered facts、open questions、decisions、discarded categories 和 confidence。增量更新读取“旧 summary + 新 episode”，但隔若干轮必须从原 source 重建，阻断误差无限继承。

3. 构建 hierarchical summary tree

当 rolling summaries 仍太多时，按项目阶段或 topic 生成父节点。父摘要不复制全部子摘要，而是保存时间范围、主题、关键转折、active child pointers 与检索关键词。树允许 coarse-to-fine retrieval：先选相关阶段，再展开 episode，最后必要时读取 event/artifact。不同层使用独立版本，重算一个叶子只使祖先节点 stale，不改写源。

4. 定义 summary contract

prompt 要求结构化输出而非一段漂亮散文：confirmed facts 必须带 refs；decisions 区分 proposed/approved/executed/verified；open loops 永不因“没有新消息”而消失；negative constraints 和数字原样引用；uncertainty 不能被补全。validator 检查所有 refs 落在 source range、关键 state 字段被提及、没有陌生 entity，并把失败摘要丢弃。

5. Context assembly 选择摘要还是原文

低风险 continuation 可读 working state + 最新 rolling summary。涉及付款、权限、发布、法律措辞或冲突事实时，policy 强制 rehydrate 引用 span。若 summary confidence 低、source 已更新、父子摘要不一致或问题询问精确原话，assembler 也展开 source。summary 的 token savings 从不覆盖 risk policy。

6. 新信息到达时 invalidate

事件追加后，所有覆盖该 range 或引用被 supersede record 的 summary 标为 stale。后台可异步重算；在重算前，assembler 不得把 stale summary 当 active fact。对删除请求，先 tombstone 原记录，再使所有摘要、embedding 与 cache 派生项失效；不能只在下一次摘要中“忘掉”。

7. 保存 compression manifest

manifest 记录每个 source span 去向：verbatim reserved、typed-state represented、summary represented、pointer only 或 intentionally dropped，并写 drop reason。它让离线评测能回答“关键事实在哪一层丢失”，也让事故调查知道当时模型究竟看到了摘要还是原文。

compress(events, state):
  invariants = projectTypedState(state)
  episode = closeSemanticUnit(events)
  summary = summarizeWithRefs(episode)
  if !validate(summary, episode, invariants): reject(summary)
  persist(summary, manifest, sourceVersion)

assemble(decision):
  nodes = retrieveSummaryTree(decision)
  return riskPolicy.requiresSource(decision, nodes)
    ? rehydrate(nodes.sourceRefs) : nodes
04

必要数学：压缩率、误差预算与重建成本

压缩率不是单独目标

设 source 长度为 L tokens，summary 长度为 l，则压缩率 ρ=L/l。ρ=20 表示 20:1，但不说明保留了什么。对一组 required invariants I，定义加权保真度 F=Σwᵢ·preserved(i)/Σwᵢ；authorization、未决副作用等高风险项的权重远高于寒暄。工程目标是满足 F 的阈值后最大化 ρ，而不是先追求最短摘要。

递归摘要的误差会复合

若每一层对某关键事实的独立保留概率为 q，经过 k 次 summary-of-summary 后保留概率理想化为 qᵏ。即使 q=0.98，10 层后也只有约 0.817。现实错误还相关，可能更差。这个公式不是模型质量估计，而是说明为何必须限制递归深度、周期性从 source rebuild，并让 invariant 绕过有损链路。

何时值得 rehydrate

设展开 source 的额外 token/latency 成本为 Cᵣ，不展开导致错误的概率为 pₑ，错误业务损失为 Lₑ，则当 pₑ·Lₑ > Cᵣ 时应展开。虽然单位通常需货币化或归一化，这个期望损失框架解释了为何同一摘要在闲聊中可接受，在付款或权限变更前却必须回源。

05

对 Agent 系统的影响

Context latency 变成可控曲线

rolling summary 把每步输入从随总历史线性增长，变成由 working state、recent window 和少量 summary nodes 决定。稳定 prefix 还提高 prompt/KV cache 命中。但后台 summarization、validation 与 rehydration 会增加异步工作量；系统应分别记录 source tokens、summary tokens、rehydrated tokens、cache hit 与 time-to-first-token。

状态正确性不依赖语言模型文风

open calls、deadline、approval 和 artifact digest 位于 typed lane 后，换 summarizer 或改变语言不会改变控制状态。摘要可以更短、更适合特定模型，却不能把 proposed 变成 approved。这个边界也使模型迁移更安全：新模型只重建派生 summary，不迁移事实。

审计从“看 prompt”升级为 lineage

一次错误决定可以沿 context manifest 追到 summary node，再追到 source span 和 generator version。团队可以问：事实根本没被召回，还是被压缩丢失？摘要包含了它，还是 serialization 截断？模型看到后仍误用？这些是不同 defect owner 与修复路径。

用户可控的遗忘成为可能

当 summary 被视作 derived cache，删除源记录就能通过 lineage 找到所有派生节点并 invalidate。若摘要是唯一保存层，系统反而无法证明敏感信息是否已被彻底移除，也无法在删除非敏感片段后准确重算剩余内容。

06

设计取舍与失败模式

  • Rolling summary drift：每次只读旧摘要会把早期误差永久化；定期 source rebuild，并设最大 generation depth。
  • 漂亮但不保真：流畅段落会消除 proposed/verified、before/after、not/now 等差异；结构化字段和引用验证优先于可读性。
  • 切分边界错误：在 tool call 与 result 之间关闭 episode，会留下半个因果链；episode closure 由状态机事件而非固定 token 数决定。
  • 摘要成为 prompt injection 放大器：summarizer 可能把外部恶意指令重写成无来源建议；输出必须保持 trust label，且摘要不能产生 instruction authority。
  • 父节点过期：叶子更新而祖先仍 active，会召回旧结论；用 dependency version 或 Merkle-like child digest 标 stale。
  • 原文永不删除：可回源不等于无限保留。retention、legal hold、用户删除与加密策略作用在 source 层，摘要随 lineage 失效。
  • validation 自证：用同一模型“总结后再问是否正确”相关性过高；关键 invariant 用 deterministic checks，事实一致性可用不同模型或抽样人工复核。
  • 只测 ROUGE：词面重合不等于 Agent correctness；应测试 open-loop retention、constraint fidelity、temporal ordering、source attribution 与 downstream decision。
07

可复用的技术判断

  • raw history 是可回放事实层，summary 是可丢弃重算的派生 cache；两者不能互换。
  • hard constraints、授权、open effects 与 deadline 进入 typed invariant lane，绕过有损摘要。
  • rolling summary 按语义 episode 更新；hierarchical summary 用于导航，必要时沿 source refs rehydrate。
  • 摘要必须携带覆盖范围、generator version、source refs、confidence 和 omissions，并在源更新/删除时 invalidate。
  • 压缩质量不是最短文本或 ROUGE，而是 invariant fidelity、lineage、downstream decision 与受风险控制的 token savings。

Summaries Lie: How Can an Agent Compress Long History Safely?

Move from lossless history to working state, rolling summaries, and hierarchical summaries with reversible references, recomputation, and an explicit error budget.

2026-09-2220 min readContext compression / Summarization / State abstraction / Provenance / Error budget
01

Today's proposition

A long-running agent must compress history, but every summary is a lossy transform. It decides what matters, merges similar events, removes repetition, and rewrites source language. The danger is not merely omitting an occasional sentence. A summary is often treated as fact by the next model call: a dropped negation, expired constraint, or unresolved side effect can become stable but false working reality through repeated summaries of summaries.

A safe design cannot require summaries never to fail. It removes non-negotiable control state from free text and uses summaries only for navigation and reasoning. Each summary declares its event range, generator version, source references, and known omissions. High-risk decisions, conflicts, or low confidence cause the runtime to return to original events or artifacts and rebuild, rather than continuing to trust compressed prose.

Core judgment: the correctness contract for compression is not “sounds like the conversation.” Invariants remain faithful, provenance remains traceable, information loss is measurable, and derived views are disposable and recomputable. Raw history is the fact layer; a summary is a versioned cache.
02

Continue the four-layer model: compress only the right layer

Part 1 separated the event log, working state, retrieval index, and durable records. That boundary directly determines compression. The event log may be archived, segmented, and indexed, but a summary does not replace it. Typed reducers update working state; a model must not infer open calls, deadlines, or approval from prose. Durable records evolve through versions and supersession. Only the transcript view and navigational memory presented to the model should undergo lossy compression.

Therefore, “summarize when context reaches eighty percent” is too crude. It treats token pressure as the only trigger while ignoring semantic boundaries. An incomplete tool transaction, unsettled approval scope, or conflict between sources is exactly where a fluent paragraph must not merge distinctions. Better triggers include episode completion, state checkpoint, topic shift, artifact completion, and a change in risk level.

Compression is not one-way deletion. A summary is first an index: it tells the assembler what happened during a time range and which source spans should be expanded for the present task. Stable record IDs and source spans let the system rehydrate originals on demand, connecting a small context window to a large durable history.

03

Mechanism: three compression layers with reversible references

1. Extract an invariant lane first

Before compression, the runtime reads fields that require exact preservation from typed state: goal, hard constraints, authorization scope, open operations, unresolved outcomes, deadlines, accepted artifact IDs, and explicit user decisions. Schemas and reducers own these fields. A summary may reference them but cannot rewrite them. If prose says deployment completed while state remains verification pending, the assembler follows state and exposes the conflict.

2. Build rolling summaries by episode

An episode is a semantically closed unit such as an investigation, tool transaction, or approval round. Its summary record contains an ID, source event range, artifact references, creation time, generator model and prompt version, covered facts, open questions, decisions, discarded categories, and confidence. Incremental updates may read an old summary plus a new episode, but periodic reconstruction from source prevents inherited error from growing without bound.

3. Build a hierarchical summary tree

When rolling summaries become numerous, create parent nodes by project phase or topic. A parent does not copy every child; it stores time range, themes, pivotal changes, active child pointers, and retrieval terms. The tree enables coarse-to-fine retrieval: choose a phase, expand an episode, and finally read an event or artifact when needed. Layers version independently. Recomputing a leaf marks ancestors stale but never rewrites source.

4. Define a summary contract

Request structured output rather than elegant prose. Confirmed facts carry references. Decisions distinguish proposed, approved, executed, and verified. Open loops never disappear merely because no new event mentioned them. Negative constraints and numbers remain verbatim. Uncertainty is not filled in. A validator checks that references belong to the source range, critical state fields appear, and no unknown entity was invented; failed summaries are discarded.

5. Choose summary or source during assembly

A low-risk continuation may use working state plus the latest rolling summary. Payments, permissions, releases, legal text, and conflicting facts trigger policy-mandated rehydration. The assembler also expands source when confidence is low, a source changed, parent and child disagree, or the question asks for exact wording. Token savings from a summary never override risk policy.

6. Invalidate when new information arrives

After an event append, summaries covering that range or referencing a superseded record become stale. Background work may recompute them asynchronously; until then, the assembler cannot treat them as active fact. A deletion request first tombstones source, then invalidates summaries, embeddings, and cache derivatives. Merely omitting the item from the next summary is not deletion.

7. Persist a compression manifest

The manifest records the disposition of every source span: reserved verbatim, represented in typed state, represented by summary, retained as pointer only, or intentionally dropped with a reason. Offline evaluation can locate the layer where a decisive fact disappeared. Incident review can also determine whether the model saw source, a summary, or neither.

04

Essential mathematics: compression ratio, error budget, and rebuild cost

Compression ratio is not the sole objective

Let source length be L tokens and summary length be l. The compression ratio is ρ=L/l. A ratio of twenty means twenty-to-one, but says nothing about what survived. For required invariants I, define weighted fidelity as F=Σwᵢ·preserved(i)/Σwᵢ. Authorization and unresolved effects receive much higher weights than greetings. The engineering objective is to maximize ρ only after meeting a fidelity threshold, not to minimize prose first.

Recursive summarization compounds error

If each layer independently preserves a critical fact with probability q, then after k summary-of-summary layers the idealized survival probability is qᵏ. Even q=0.98 yields only about 0.817 after ten layers. Real errors are correlated and may be worse. This is not an estimate of a particular model; it demonstrates why systems limit recursion depth, periodically rebuild from source, and route invariants around the lossy chain.

When is rehydration worth its cost?

Let the extra token and latency cost of source expansion be Cᵣ, the probability of error without expansion be pₑ, and business loss from error be Lₑ. Rehydrate when pₑ·Lₑ > Cᵣ. Units must be monetized or normalized in practice, but the expected-loss frame explains why one summary can be acceptable for casual conversation and unacceptable before a payment or permission change.

05

Implications for agent systems

Context latency becomes a controlled curve

Rolling summaries change per-step input from linear growth with total history to a function of working state, a recent window, and a few summary nodes. A stable prefix also improves prompt or KV-cache reuse. Background summarization, validation, and rehydration add asynchronous work, so systems should separately record source tokens, summary tokens, rehydrated tokens, cache hits, and time to first token.

State correctness no longer depends on model prose

With open calls, deadlines, approvals, and artifact digests in a typed lane, changing summarizers or languages does not alter control state. A summary may become shorter or better suited to a model, but it cannot turn proposed into approved. Model migration is safer because a new model rebuilds derived summaries rather than migrating facts.

Audit becomes lineage rather than prompt inspection

A wrong decision can be traced through the context manifest to a summary node, then to source spans and generator version. A team can ask whether the fact was never retrieved, lost during compression, present in the summary but truncated during serialization, or visible to the model and misused. These defects belong to different owners and require different repairs.

User-controlled forgetting becomes possible

When a summary is a derived cache, deleting a source record can follow lineage to every derived node and invalidate it. If the summary is the only retained layer, the system cannot prove whether sensitive data was fully removed, nor accurately recompute remaining content after deleting one portion.

06

Trade-offs and failure modes

  • Rolling-summary drift: reading only the previous summary makes early errors durable. Periodically rebuild from source and cap generation depth.
  • Fluent but unfaithful: smooth prose erases proposed versus verified, before versus after, and not versus now. Structured fields and reference validation outrank readability.
  • Wrong segmentation: closing an episode between a tool call and its result leaves half a causal chain. State-machine events, not fixed token counts, determine episode closure.
  • Summary amplifies prompt injection: a summarizer may rewrite hostile external instructions as unattributed advice. Preserve trust labels; a summary never acquires instruction authority.
  • Stale parents: a leaf changes while its ancestor remains active and retrieves an obsolete conclusion. Dependency versions or Merkle-like child digests mark parents stale.
  • Source retained forever: reversibility does not mean infinite retention. Retention, legal hold, user deletion, and encryption operate on source; summaries invalidate through lineage.
  • Self-validating summaries: asking the same model whether its summary is correct creates correlated errors. Check invariants deterministically and use another model or sampled human review for factual consistency.
  • ROUGE-only evaluation: lexical overlap is not agent correctness. Test open-loop retention, constraint fidelity, temporal order, source attribution, and downstream decisions.
07

Reusable technical judgments

  • Raw history is the replayable fact layer; a summary is a disposable, recomputable derived cache. They are not interchangeable.
  • Hard constraints, authorization, open effects, and deadlines enter a typed invariant lane that bypasses lossy summarization.
  • Rolling summaries update at semantic episode boundaries. Hierarchical summaries navigate; source references rehydrate detail when required.
  • A summary carries coverage, generator version, source references, confidence, and omissions, and becomes invalid when source changes or is deleted.
  • Compression quality is not shortest text or ROUGE. It is invariant fidelity, lineage, downstream decisions, and risk-bounded token savings.

09

What is established and where we continue

Established today: lossless events and artifacts form the fact layer. Typed working state preserves invariants. Rolling and hierarchical summaries are derived navigation layers with source references, versions, and omissions. Compression occurs at episode boundaries, passes structural validation, and uses a manifest to trace each source span. High-risk decisions, conflict, or low confidence require rehydration.

Still unresolved: how should candidate memories be admitted, retrieved, merged, and forgotten? How do embeddings, BM25, metadata, and graphs compose? How are conflicting memories resolved by authority, scope, and time?
