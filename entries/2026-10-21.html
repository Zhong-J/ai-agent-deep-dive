检索 top-5 都很像，为什么 Agent 仍找不到正确证据？

从文档切块、倒排索引、向量召回与 ANN 近似出发，拆开候选召回、权限和新鲜度的工程边界。

2026-10-21约 20 分钟Retrieval / BM25 / Dense passage retrieval / HNSW / Hybrid search / RAG evidence
01

今日命题

Agent 回答一个产品故障问题，检索器返回五段语义都很像的旧排障文档，却漏掉含有精确错误码和新版本修复说明的段落。生成模型在五段文字里‘推理得很好’，结果仍错。失败并非单纯的 prompt 或上下文长度问题：证据根本没有进入候选集，后续 reranker 与 LLM 无法凭空补回。

今天开始 Retrieval & RAG Internals，先研究候选生成这一层。文档怎样变成可引用的 chunk？词项倒排与稠密向量分别找回什么？近似向量搜索在哪一步牺牲精确性？权限过滤和更新延迟如何让‘数据库里有文档’不等于‘这个请求可拿到正确证据’？本篇不把 RAG 当成‘加一个向量库’；它是一条有数据版本、索引、召回、排序、授权和生成边界的系统管线。

核心判断：top-k 相似度只描述当前索引与检索器选出的候选，不证明正确证据存在于其中，更不证明它有权、够新、可引用。
02

承接 Agent 与模型上下文，但不重复 memory

前面讨论的 Agent memory 关心运行过程中应保存、取回和遗忘什么状态；本系列面向外部知识库的证据入口。两者都可能使用 embedding，但语义近邻不是同一个产品合同：记忆可按用户与会话生命周期管理，外部文档还要尊重版本、来源、授权、删除和审计。长上下文能放下更多段落，也不能替代候选召回；没有被选中的正确文档不会因为窗口变大而出现。

模型处理的是被交付的文本。检索器处理的是一个持续变化的语料：文件可能晚到、修改、撤销权限或删除。Agent 的工具调用能向搜索服务发 query，但 query 字符串只是需求表达；检索系统要把它映射到词项、向量和过滤条件。把低质量结果直接塞进 prompt，会让 LLM 在‘高度相关的错误证据’上产生自信答案。因此候选生成要对 Agent 暴露证据 ID、版本、来源 span 与检索策略，而不只是一段自然语言摘要。

03

机制：从文档到可授权候选

1. 先解析，再切成有出处的单元

检索单位通常不是整本手册，也不是任意定长字符块。解析器要保留标题、表格、代码块、段落顺序和文件版本；切块可按语义边界与 token 预算选择长度，并保存 parent document ID、offset、版本时间和 ACL 引用。块太大，单条命中携带噪声且占 context；块太小，错误码与修复条件被拆开。重叠可缓解边界损失，却增加重复候选、索引成本与同一来源霸榜。内容改版时要能把旧 chunk 撤下，不能只追加新向量。

2. 词项倒排找精确锚点

倒排索引把 term 映射到含它的 chunk postings，并记录出现次数与长度等统计。BM25 类评分让罕见词、词频和文档长度共同作用，因此错误码、API 名、产品版本和否定词的字面形式很有价值。词法路线怕同义表达、缩写变体、拼写与跨语言差异，也可能被模板化高频词误导。文本分析器的分词、大小写、词干化和字段权重必须作为索引合同版本化；查询与建索引的 analyzer 不一致会静默漏召回。

3. 稠密向量找语义邻居

dual encoder 把 query 与 chunk 分别投射到向量空间，检索相近向量。DPR 论文证明了这一结构在其开放域问答实验中的价值；它不是‘向量必然优于 BM25’的定理。编码器训练与业务语料不匹配时，向量可能把‘新版本已修复’和‘旧版本仍受影响’放得很近；稀有标识符也未必被保留。query encoder、document encoder、向量归一化和索引维度属于一个版本化组合，单独换一端未必可互操作；即使 query encoder 针对固定 document encoder 训练，也必须验证兼容性与分数校准。

4. ANN 进一步近似向量 top-k

穷举每个向量能得到当前 embedding 空间的精确近邻，但大语料代价高。HNSW 等 ANN 结构用图导航减少搜索范围，换取索引内存、构建成本和可调的近邻召回率。这里的‘近似’只指相对穷举向量搜索；即使 ANN 找到了真正的向量 top-k，也不代表人类判断的相关证据在其中。缩小搜索预算会降延迟，也可能让边缘但关键的修复文档从候选中消失。

5. 合并两路，再处理安全与版本

词项分与向量相似度不能直接相加：尺度与含义不同。可先各自取足量候选，再按校准后的分数或排名融合，并去重到源文档与 span；保留每路命中原因供诊断。授权必须在文本进入 LLM 前执行，且与当前用户/租户权限一致。若先从全库取很小 ANN top-k 再做 post-filter，授权结果可能不足，即使有相关的允许文档；可用授权感知索引或扩大候选池，但要权衡泄漏面、延迟和可维护性。删除、ACL 更改、embedding 重建可能不同步，query 应在可解释的索引/权限快照上运行，旧结果不得借缓存重新暴露。

6. 候选不是最终上下文

本阶段输出的是带分数、路由、来源和版本的候选集，不是最终给 LLM 的五段话。下一篇才讨论 reranker、query rewrite、融合后的排序与证据打包。今天先要求候选召回足够高且安全边界完整；否则后续模块只是在错误集合里精挑细选。

04

必要数学：三种‘召回’不能混淆

BM25 的直觉可写成 score(q,d)≈Σₜ IDF(t)·tf(t,d)/(tf(t,d)+k₁·(1−b+b·|d|/avgdl))，对 query 中词项 t 求和。tf 是词在 chunk d 中的出现次数，IDF 表示语料稀有度，|d|/avgdl 是长度相对平均值，k₁ 控制词频饱和，b 控制长度归一化。不同实现的 IDF、字段与 query-term 因子会不同，这里是机制模型而非某产品逐行公式。它能奖励精确错误码，但不知道‘升级后已修复’与‘仍有故障’的逻辑关系。

若向量用 cosine，相似度 sim(q,d)=q·d/(||q||·||d||)；q、d 是编码器输出，点积衡量方向一致性，分母去掉长度影响。高 cosine 是训练得到的空间接近，不是事实正确概率。ANN 的 recall@k=|ANNₖ∩Exactₖ|/k 把图索引返回集合与同一向量空间穷举 top-k 比较；这是索引近似质量，不是问题答案质量。对同一用户/租户、同一语料与权限快照下有人工标注的相关且授权证据集合 R 的请求，候选覆盖可写 candidate recall@K=|C_K∩R|/|R|，C_K 为授权后候选。若 R 不完整，估计也会偏；应按错误码、版本、多语言和长文档等切片分析。

实际流水线的命中上限可以从条件事件理解：正确文档须先被解析并索引、在当前权限下可见、进入候选、再被后续重排与生成使用。某一关的召回为零，后面增加上下文或更强 LLM 都不能把该来源恢复。这里不把各关概率草率相乘；它们往往相关，且人工标注不完备。

05

对 Agent 系统的影响与验证

对模型可见的 retrieval tool 不应区分‘没有找到’与‘没有权限’，以免暴露禁用文档的存在；只有受授权运维诊断可记录 ACL 拒绝。索引可能未追上的通用新鲜度状态可单独标识，但不能透露具体禁用文档。工具结果至少携带来源 URI/ID、可引用 span、文档与索引版本、检索路由和取回时间；若只返回改写后的摘要，后续 verifier 难以定位事实来源。缓存键须包含租户与授权上下文，并在权限或文档版本变化时失效；否则昨天的允许结果可能成为今天的泄漏。

验收先量 corpus/index：解析成功率、最新版本覆盖、删除/ACL 传播时延、chunk 重复率。再在有证据标注的任务集上量 lexical、dense、ANN 与 hybrid 的候选 recall@K、授权后有效 K、延迟和成本；不要只用最容易的 FAQ。刻意加入精确编号、版本反转、跨语言同义、长表格、代码片段、权限边界和刚更新文档。与生成模型保持隔离，先确认正确证据进入候选，再评估后续 reranker 与回答。

Agent 终态仍要看事实支持率、引用可回链、权限违规和放弃/追问策略。候选不足时，系统可以扩检、改写 query 或明确‘没有足够证据’，但不能把低分命中包装成已验证结论。后续 LLM 的流畅度不会提高上游召回的观测值。

06

取舍与失败模式

  • 只上 dense：同义词召回好，也可能丢精确错误码、版本号与否定；保留词法路线并按切片比较。
  • 只上 BM25：精确术语稳，却容易漏跨语言和业务同义；用 dense 补充而非假定某一路统治。
  • 把 ANN recall@k 当证据召回：它只比较向量穷举，不衡量人类相关性。
  • 切块越小越好：条件被拆散且重复飙升；chunk 应带 parent 与 span，可恢复完整上下文。
  • 全库 ANN top-5 后再做 ACL：可能一个授权候选都不剩；过滤顺序和候选池大小需设计与测量。
  • 更新只追加新向量：旧版和撤权内容可能继续出现；删除、权限和索引快照必须协同。
  • 融合时直接加原始分：BM25 与 cosine 不同尺度；先校准或用排名融合。

没有一个固定 K 能同时最小化延迟、成本和证据漏失。候选池应按风险与任务切片设上限，并把下一层 reranker 的容量和预算一起纳入设计。

07

可复用的技术判断

  • RAG 的第一道质量上限是候选召回；正确证据没入池，重排与 LLM 无法可靠补救。
  • BM25 的词项锚点与 dense 的语义邻居互补，ANN 又在向量路线内加入近似误差。
  • chunk 是带 parent、span、版本和 ACL 的证据单元，不是任意长度文本。
  • 索引近邻召回、人工证据召回和最终答案正确率是不同指标。
  • 授权、删除、新鲜度与缓存属于检索正确性和安全边界，不是发布后的附属运营项。
08

The Top Five Look Relevant. Why Can the Agent Still Miss the Evidence?

Trace chunking, inverted indexes, dense retrieval, and approximate nearest neighbors to separate candidate recall from authorization and freshness.

2026-10-2120 min readRetrieval / BM25 / Dense passage retrieval / HNSW / Hybrid search / RAG evidence
01

Today's proposition

An agent answers a product-incident question. Its retriever returns five semantically similar older troubleshooting passages but misses the one passage containing the exact error code and the fix for the current release. The generator can reason fluently over those five and still be wrong. This is not merely a prompt or context-window failure: the evidence never entered the candidate set. A later reranker or LLM cannot reliably reconstruct an absent source.

Retrieval & RAG Internals therefore begins at candidate generation. How does a document become a citable chunk? What do term postings and dense vectors recover differently? Where does approximate vector search exchange exactness for cost? How can access control and update lag make 'the document exists in the database' different from 'this request can retrieve the right evidence'? RAG is not simply a vector database attached to a model. It is a pipeline with source versions, indexes, recall, ranking, authorization, and generation boundaries.

Core judgment: top-k similarity describes candidates selected by one index and retrieval policy. It does not prove that the right evidence is present, authorized, fresh, or citable.
02

Connecting agents and context without repeating memory

Earlier agent-memory lessons concerned which execution-state or user-specific observations to store, retrieve, and forget. This series concerns the evidence ingress from an external knowledge corpus. Both may use embeddings, but nearest-neighbor similarity is not the same product contract. Memory may follow user and session lifecycles; external documents also carry source versions, access rights, deletions, and audit obligations. A larger context window can hold more passages but cannot repair candidate recall. The correct document will not appear merely because the window grows.

The model sees only delivered text. Retrieval operates on a changing corpus: files arrive late, are revised, lose permissions, or are deleted. An agent's tool call can send a query to a search service, but its string is only an expression of need. The retrieval stack maps that need into terms, vectors, and filters. Feeding poor hits directly to a prompt invites a confident answer grounded in highly similar but wrong evidence. Candidate generation should expose an evidence ID, source version, span, and retrieval route to the agent, not just a prose summary.

03

Mechanism: from documents to authorized candidates

1. Parse and chunk with provenance

A retrieval unit is usually neither an entire manual nor an arbitrary fixed number of characters. A parser should retain headings, tables, code blocks, paragraph order, and file versions. Choose chunks around semantic boundaries and a token budget, preserving parent document ID, offsets, version time, and an ACL reference. Oversized chunks import noise and consume context; tiny ones separate an error code from its qualifying fix. Overlap can rescue boundary cases but increases duplicate hits, index cost, and domination by one source. When content changes, withdraw obsolete chunks rather than merely appending new vectors.

2. Inverted terms recover exact anchors

An inverted index maps each term to postings of chunks containing it, with occurrence and length statistics. A BM25-like score combines rarity, term frequency, and length, making literal error codes, API names, product versions, and negation valuable. The lexical route can miss synonyms, abbreviations, spelling variants, and cross-language paraphrases; templates with repeated common terms may also distract it. Tokenization, case handling, stemming, and field weights are part of the versioned index contract. A mismatch between query and indexing analyzers can silently remove candidates.

3. Dense vectors recover semantic neighbors

A dual encoder embeds queries and chunks into a shared vector space and retrieves nearby vectors. The DPR paper demonstrates its value in the authors' open-domain QA experiments, not a theorem that vectors always beat BM25. If encoder training differs from the deployment corpus, 'fixed in the new release' and 'still broken in the old release' may lie close together. Rare identifiers may not survive representation well. Query encoder, document encoder, normalization, and dimensionality form a versioned pair; a query encoder can be trained against a fixed document encoder, but any one-sided change still requires compatibility and score-calibration checks.

4. ANN approximates vector top-k

Exhaustively comparing every vector finds exact neighbors in the current embedding space but is costly at scale. An ANN structure such as HNSW navigates a graph to search fewer candidates, trading index memory and construction cost for adjustable nearest-neighbor recall. 'Approximate' here is relative to exhaustive vector search only. Even perfect vector top-k need not contain evidence judged relevant by a human. A smaller search budget reduces latency but may remove an edge-case fix document from the candidate pool.

5. Merge routes, then enforce security and versions

Term scores and vector similarities cannot be added naively; their scales and meanings differ. Retrieve a generous pool per route, then use calibrated scores or rank-based fusion and deduplicate by source and span, retaining which route found each hit. Authorization must occur before text reaches the LLM, under the current user and tenant context. If a tiny global ANN top-k is post-filtered, too few authorized hits may remain even when an allowed relevant document exists. Authorization-aware indexes or a larger pool may help, with latency, leakage, and maintenance trade-offs. Deletes, ACL changes, and embedding rebuilds can lag one another; queries should use an explainable index/permission snapshot, and old cache entries must not re-expose revoked content.

6. Candidates are not final context

This stage outputs scored, routed, sourced, and versioned candidates, not the five final passages shown to the model. The next part addresses reranking, query rewriting, ranking after fusion, and evidence packaging. First make candidate recall high enough and preserve security boundaries. Otherwise later components merely choose carefully from the wrong set.

04

Essential mathematics: three notions of retrieval success

A schematic BM25 score is score(q,d)≈Σₜ IDF(t)·tf(t,d)/(tf(t,d)+k₁·(1−b+b·|d|/avgdl)), summed over query terms t. Here tf counts term appearances in chunk d, IDF reflects corpus rarity, |d|/avgdl is length relative to average length, k₁ controls frequency saturation, and b controls length normalization. Implementations differ in IDF, field treatment, and query-term factors; this is a mechanism sketch, not a line-for-line formula for one product. It rewards an exact error code but does not understand the logic between 'fixed after upgrade' and 'still affected.'

For cosine similarity, sim(q,d)=q·d/(||q||·||d||). Query and document embeddings q and d are encoder outputs; the dot product measures directional alignment, and the denominator removes length. High cosine is proximity in a learned space, not a calibrated probability of factual correctness. ANN recall@k=|ANNₖ∩Exactₖ|/k compares graph-index results with exhaustive top-k in that same embedding space. It measures approximation quality, not answer quality. For a human-judged set R of relevant and authorized evidence under the same principal and corpus/permission snapshot, candidate coverage is candidate recall@K=|C_K∩R|/|R|, with C_K the authorized candidate pool. If R is incomplete, that estimate is biased. Slice it by error codes, versions, languages, and long documents.

The pipeline imposes a conditional upper bound: the correct source must first be parsed and indexed, visible under current permissions, selected as a candidate, then used by later ranking and generation. Zero recall at one gate cannot be repaired by a larger prompt or stronger LLM downstream. Do not casually multiply probabilities across these gates; they are correlated and human judgments may be incomplete.

05

Agent implications and verification

A model-visible retrieval tool should not distinguish 'no match' from 'not authorized,' because that can reveal a forbidden document's existence. ACL denials belong in privileged operator diagnostics. A generic index-freshness warning may be exposed without identifying forbidden content. Results need source URI or ID, citable span, document and index versions, retrieval route, and fetch time. A rewritten summary alone leaves a later verifier unable to trace factual claims. Cache keys must include tenant and authorization context and expire or invalidate on rights or version changes. Yesterday's allowed hit must not become today's leak.

Acceptance begins at corpus and index health: parsing success, latest-version coverage, deletion and ACL propagation lag, and chunk duplication. Then use evidence-judged tasks to measure candidate recall@K for lexical, dense, ANN, and hybrid routes, effective K after authorization, latency, and cost. Do not evaluate only easy FAQs. Include exact identifiers, reversed version conditions, cross-language paraphrases, long tables, code spans, authorization boundaries, and newly updated files. Keep the generator out of this measurement initially. First establish that the correct evidence enters candidates; only then assess reranking and answers.

Agent terminal outcomes still need factual support, traceable citations, permission-violation checks, and an abstain or clarification policy. When candidates are insufficient, the system may broaden retrieval, rewrite the query, or state that evidence is inadequate. It must not repackage a weak hit as a verified conclusion. Fluent generation cannot improve the observed upstream recall.

06

Trade-offs and failure modes

  • Dense only: paraphrase recall may improve while exact error codes, versions, and negations disappear. Keep a lexical route and compare by slice.
  • BM25 only: exact terminology is strong but cross-language and domain synonyms may be missed. Dense retrieval complements it rather than universally replacing it.
  • ANN recall@k equals evidence recall: it only compares against exhaustive vectors, not human relevance.
  • Smaller chunks are always better: conditions separate and duplicates explode. Preserve parent and span for context reconstruction.
  • Global ANN top five followed by ACL: filtering may leave no authorized hits. Design and measure filter order and pool size.
  • Append new vectors on every update: stale and deauthorized content may remain. Coordinate deletes, permissions, and index snapshots.
  • Add raw fusion scores: BM25 and cosine use different scales. Calibrate or use a rank-based method.

No fixed K simultaneously minimizes latency, cost, and missed evidence. Bound candidate pools by risk and task slice while accounting for downstream reranker capacity and budget.

07

Reusable technical judgments

  • Candidate recall is the first quality ceiling for RAG. Absent evidence cannot be reliably repaired by reranking or generation.
  • BM25's exact term anchors and dense semantic neighbors complement one another; ANN adds approximation within the vector route.
  • A chunk is an evidence unit with parent, span, version, and ACL, not just arbitrary-length text.
  • Index-neighbor recall, judged-evidence recall, and final answer correctness are distinct metrics.
  • Authorization, deletion, freshness, and caching are retrieval correctness and safety boundaries, not post-launch housekeeping.

  • Apache Lucene BM25Similarity API — official implementation documentation for k₁, b, and length statistics. The formula here is only a mechanism sketch.
  • Dense Passage Retrieval — the authors report dual-encoder retrieval results in open-domain QA, not a guarantee for every enterprise corpus.
  • HNSW — the authors introduce graph-based approximate nearest-neighbor search; performance depends on configuration and data.
  • Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks — the authors combine external retrieval and generation; it is not a product specification for one vector store.
  • BEIR — the authors study zero-shot retrieval across tasks, motivating distribution-sliced evaluation rather than a claim that one method always wins.

The ACL/cache contract, distinct candidate metrics, and agent acceptance protocol are editorial engineering implications of index mechanics. These sources are not presented as validation of a particular business system.

09

Established and next starting point

Established today: external documents need parsing, traceable chunks, and versioned indexes. Inverted terms and dense vectors have different blind spots; HNSW-like ANN only approximates vector neighbors. Candidates must be usable under current rights and versions. Index recall, evidence recall, and answer quality are not interchangeable.

Still unresolved: given a sufficiently broad authorized pool, how do reranking, query rewriting, fusion, and deduplication select passages that truly support an answer? What about multi-hop questions and conflicting evidence? How should spans be packed for the LLM without burying the decisive one?

Next starting point: Retrieval & RAG Internals Part 2/3 moves from candidates to ranking and evidence selection: cross-encoder and late interaction, query rewriting, fusion, context packing, and cost bounds, without repeating today's inverted-index or ANN mechanism.
