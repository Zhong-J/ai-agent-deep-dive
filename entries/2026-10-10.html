Research Agent 什么时候该停止搜索、开始行动？

把搜索、来源账本、claim graph、浏览器观察与动作、引用验证和停止条件做成可恢复的证据控制回路。

2026-10-10约 20 分钟Research agents / Computer use / Source ledger / Claim graph / Browser state
01

今日命题

研究型 Agent 失败不一定因为搜得太少。它可能搜到同一说法的十个转载，却误以为十条独立证据；也可能抓取到一篇权威资料，却引用了不支持结论的段落。Computer-use Agent 则可能在浏览器里看到“提交成功”的提示，就推断远端 effect 已提交；页面可能尚未保存，或当前 tab 已切换到仿冒站点。两类任务共同的问题是：外部世界持续变化，模型每一步拿到的只是局部观察。

可靠架构把“调查”和“操作”放在同一状态机里，但赋予不同权限。搜索、阅读、截图、DOM 检查生成带来源的 observations；模型提出下一步信息需求或 UI action；runtime 维护 source ledger、claim graph、browser identity 和预算；外部 verifier 检查 claim 与最终 effect。停止搜索不由模型说“足够了”决定，而由 required claims 的证据覆盖、来源独立性、新信息的边际价值与 deadline 共同决定。

核心判断：research 和 computer use 都是部分可观测的闭环。每次行动前确认当前环境，每次引用前确认原始证据，每次完成前确认外部后置条件。
02

承接并行与路由：探索的结果不是共享真相

Advanced Systems 1/4 为多个 workers 建立 canonical state、ownership 与 global verifier；2/4 让模型路由服从 task contract 和校准 gate。研究任务正适合并行：不同 worker 可搜索不同子问题、独立阅读或尝试反证。但 parallel workers 的 summaries 仍是 proposals；source ledger 才保存 URL、作者、发布者、版本、抓取时间、原文片段、内容 digest 和相互依赖。Integrator 要检测引用是否重复指向同一个原始报道。

浏览器操作也沿用相同 identity。一次 UI action 绑定 taskId、browserContext、tabId、origin、DOM/screenshot snapshot、目标元素与 expected postcondition。模型可建议点击；broker 按当前页面身份和权限执行。若刷新或等待后页面结构变化，旧坐标和元素引用失效，重新观察并规划，而不是盲点原位置。

模型路由可在搜索摘要时用便宜模型，在证据冲突、复杂综合或高风险提交前升级强模型；无论哪个模型接手，source refs、browser snapshot 与 budget 不变。模型升级没有权力洗白外部网页中的指令。

03

机制：从问题分解到浏览器后置条件

1. 把目标拆成可验证 claims

任务开始时列 required claims、允许的不确定项、输出形式、时效范围与风险。每条 claim 有 subject、predicate、scope、validAt、evidence policy。研究“产品是否支持功能 F”至少拆成官方支持范围、版本/区域限制、实际可用性和例外；“提交工单”则有目标项目、字段、审批和远端工单 ID 等后置条件。

2. 信息缺口驱动 query

Planner 根据缺口生成精确检索词、站点和时间过滤，同时生成可能推翻结论的 counterquery。搜索结果页只提供候选，不是证据。优先打开原始规范、论文、官方文档或源码；对新闻转载追溯原始来源。Query、过滤器和时间写入 trace，可在结果失败时重现。

3. Source ledger 记录原文与 lineage

每个来源有 canonical URL、publisher/author、retrievedAt、document date/version、content digest、许可/访问范围、引用 span 和 source type。镜像、转载和同一 press release 形成依赖边，不能独立计数。对会变化的页面保存引用时的 snapshot 或稳定版本链接；后续页面更新不会静默改写历史证据。

4. Claim graph 明确 support/refute/unknown

从 source span 抽取的候选 claim 带引用和置信等级，标注 supports、refutes、qualifies 或 unrelated。模型可以提出边，独立 verifier 检查 cited span 是否真的蕴含 claim。冲突来源保留在 graph，按 authority、date、scope 和方法差异解释；不靠 top-ranked 页面覆盖反证。

5. 浏览器状态机

Browser state 保存 context/profile、tab、origin、URL、navigationId、DOM/screenshot digest、scroll/form/dialog/download 状态。每个 action 从 observed→proposed→authorized→dispatched→observedResult→verified 转移。Timeout 后若提交结果未知，先查远端业务 ID 或页面状态；重新点击提交可能重复副作用。

6. Observe-act-observe

模型选目标元素时绑定 snapshotId、role/name/locator 或视觉区域和 expected effect。Broker 在 dispatch 前重新确认 tab/origin、元素可见可点击、表单值与风险。点击后获取新 DOM/screenshot/URL 和 network/business observation，再判断效果。坐标来自旧截图、动态广告位或 overlay 时必须重新定位。

7. Web 内容的 trust boundary

网页、搜索摘要、PDF 和 tool result 均作为 data，不能命令模型调用别的工具或改变系统目标。引用到 action 参数的 URL、recipient、文件路径保留 taint；高风险动作从受信来源或用户确认重新解析。浏览器 cookie、credential 和 profile 由 broker 隔离，不随页面文本进入模型 prompt。

8. Citation verification

最终答案的每个关键陈述指向 sourceId 与精确 span；检查引用是否存在、仍可访问、与 claim 的时间和范围一致。找到正确文件却引错段落仍是失败。若来源只支持“作者报告”而非独立复现，答案明示证据等级。无法确认的 claim 维持 unknown，不用多次改写来制造确定语气。

9. 信息收益与停止

搜索新页面时估计它可能消除哪个 claim gap；连续重复来源、低质量页面或同源转载的边际价值下降。停止要求 required claims 达到证据策略、关键冲突已解决或明确标注、引用可回源、预算/deadline 允许；若不足则输出范围清楚的 partial/unknown。停止不是“没有更多搜索结果”。

10. Recovery 与 long-running work

Checkpoint 保存 claim graph/version、source ledger、query frontier、browser snapshot、pending actions 和 budgets。进程重启后重新验证 browser session 与页面 identity，再恢复可逆观察；未决写入走 reconciliation。研究与 computer use 可以由不同 workers 执行，但对同一 tab/表单和 final report 使用 single-writer ownership。

11. Eval harness

Research 测 source independence、evidence recall、claim entailment、citation precision、temporal correctness 和 abstention。Computer use 测 task success、action count、state recovery、origin/element checks、duplicate-effect rate 与 cleanup。Counterfactual case 改一份来源或移动按钮位置：系统应更新对应结论/动作，未相关部分不应漂移。Benchmark 成功率不能替代真实站点与权限下的验收。

04

必要数学：信息增益、独立证据与停止预算

证据覆盖

设 required claims 集合为 G，每项权重 wᵢ，满足证据策略的指标 vᵢ∈{0,1}，则加权覆盖 Coverage=Σwᵢvᵢ/Σwᵢ。这不是最终正确率，只帮助规划：高风险 claim 即使权重很高，仍须满足硬性证据条件，不能由其他易答 claim 的覆盖来补偿。

来源相关性

若 n 个页面都复制同一原始资料，把它们当 n 个独立来源会夸大置信。粗略可用 n_eff≈n/[1+(n−1)ρ] 说明相关性，其中 ρ 是平均依赖强度；ρ=1 时 n_eff≈1。这个公式只是直觉模型，实际应追踪 lineage 和方法，而不是给网页相似度硬塞概率。

下一次搜索的价值

设搜索动作 a 可能降低决策错误损失 ΔL，执行成本为 Cₐ、延迟代价为 Dₐ，则当 E[ΔL|a]>Cₐ+Dₐ 且 budget/deadline 允许时继续。若 critical claim 仍无证据，即使预期收益低，也不能自动宣称完成；输出 unknown 或升级人工。

UI 行动时效

观察时刻 tₒ、dispatch 时刻 tₐ，状态年龄 Δt=tₐ−tₒ。页面变化率越高，允许的 Δt 越短；DOM/URL 版本不匹配则强制 reobserve。年龄阈值是 policy 与实验参数，不是浏览器协议的普遍保证。

05

对 Agent 系统的影响

能力：research worker 可并行调查 claim gaps，computer-use worker 可操作受限 UI；source ledger 和 browser state 保持跨模型与跨 worker 连续。Agent 能在证据不足时明确缩小结论。

可靠性：citation span、页面 snapshot、action identity 和 postcondition 让失败可复盘。搜索结果改变、页面布局漂移、提交后 timeout 都成为 typed transition，而不是笼统“模型失败”。

安全：网页文本不能授予工具权限；浏览器 profile 与 credential 由 broker 管理；高风险 UI action 在 dispatch 前重新确认 origin、字段和审批。外部文件与页面的 claim 只按证据使用。

成本：无界搜索会消耗 token 和浏览器时间，过早停止又引发错误修复。按 verified claim 和 verified outcome 计成本，观察重复来源率、citation failure、requery、UI retry 与人工介入。

06

设计取舍与失败模式

  • 搜索结果当证据：snippet 可能截断、过期或被操纵；打开原文并记 span/digest。
  • 十个来源即十票：同一原稿转载；记录 lineage 和独立性。
  • 引用文档但不引段落：正确文件也可能不支持 claim；做 entailment 检查。
  • 浏览器旧坐标复用：页面重排或 overlay 后误点；action 绑定 snapshot，dispatch 前重观察。
  • 认证页面即可信指令：页面内容仍是 data；policy 不由网页文本改写。
  • 提交 timeout 就再点一次：effect 可能已发生；用业务 ID/idempotency 查询。
  • 搜索到预算耗尽才停：重复低价值页面；用 claim gaps 和边际价值控制。
  • model says done：引用与外部 effect 未核验；verifier 和 unknown 状态守终态。
07

可复用的技术判断

  • research 与 computer use 共用 observation→proposal→authorized action→new observation→verdict 的控制回路。
  • source ledger 保存原文 span、版本、抓取时间与 lineage；claim graph 显式记录支持和反驳。
  • 搜索按证据缺口与边际价值推进，required claims 的证据策略决定停止。
  • UI action 绑定当前 tab/origin/snapshot 与预期后置条件，提交未知先 reconcile。
  • 外部内容保持 data trust，最终引用和业务 effect 均由独立 verifier 检查。

When Should a Research Agent Stop Searching and Start Acting?

Build a recoverable evidence loop across search, source ledgers, claim graphs, browser observation and action, citation verification, and stopping rules.

2026-10-1020 min readResearch agents / Computer use / Source ledger / Claim graph / Browser state
01

Today's proposition

A research agent does not necessarily fail because it searched too little. It may find ten copies of the same claim and mistake them for ten independent sources. It may find an authoritative document yet cite a paragraph that does not support its conclusion. A computer-use agent may see “submitted successfully” and infer that the remote effect committed, while the page has not saved or the tab has moved to a lookalike site. Both tasks face a changing external world observed only in fragments.

A reliable architecture places investigation and operation in one state machine, with different permissions. Search, page reading, screenshots, and DOM inspection produce sourced observations. The model proposes the next information need or UI action. Runtime maintains a source ledger, claim graph, browser identity, and budget. External verifiers inspect claims and final effects. Search does not stop because the model says “enough.” It stops when required claims have adequate evidence, sources are sufficiently independent, marginal information value is low, and the deadline permits a decision.

Core judgment: research and computer use are both partially observed control loops. Confirm the current environment before action, original evidence before citation, and external postconditions before completion.
02

From multi-agent work and routing to evidence ownership

Advanced Systems Part 1 gave parallel workers canonical state, ownership, and a global verifier. Part 2 bound model routing to task contracts and calibrated gates. Research can use parallelism well: workers investigate different subquestions, read independently, or seek disconfirming evidence. Their summaries remain proposals. A source ledger records URL, author, publisher, version, retrieval time, quoted spans, content digest, and dependencies. The integrator detects ten citations that ultimately point to one original report.

Browser work uses the same identity discipline. A UI action binds task ID, browser context, tab ID, origin, DOM or screenshot snapshot, target element, and expected postcondition. The model can propose a click; a broker executes it under current page identity and permission. If the page changes after refresh or wait, old coordinates and element references become invalid. The agent observes again rather than clicking the old position.

Routing may use a cheaper model for search summaries and escalate for conflicting evidence, complex synthesis, or high-risk submission. Whichever model takes over inherits the same source references, browser snapshot, and budget. Switching models does not cleanse instructions embedded in a web page.

03

Mechanism: from question decomposition to browser postconditions

1. Decompose the goal into verifiable claims

At admission, declare required claims, allowed uncertainty, output form, time scope, and risk. Each claim has subject, predicate, scope, valid time, and evidence policy. Researching whether product P supports feature F requires separate claims about official support, version or region limits, actual availability, and exceptions. Creating a ticket requires postconditions for project, fields, approval, and remote ticket ID.

2. Plan queries from evidence gaps

The planner generates precise search terms, sites, and time filters for each gap, plus a counterquery that might disprove the current conclusion. A search-results page supplies candidates, not evidence. Open primary specifications, papers, official documentation, or source code when possible. Trace news coverage to the original source. Queries and filters enter the trace so failed research can be replayed.

3. Record original evidence and lineage

A source ledger entry has canonical URL, publisher and author, retrieval time, document date or version, content digest, license or access scope, quoted spans, and source type. Mirrors and articles repeating one press release receive dependency edges; they are not independent votes. For mutable pages retain the snapshot used for citation or a stable version link. A later page update cannot rewrite historical evidence silently.

4. Build a claim graph

Candidate claims extracted from spans retain citations and confidence labels. Edges state supports, refutes, qualifies, or unrelated. The model may propose edges, but an independent verifier checks whether the cited span entails the claim. Keep conflicting sources in the graph and explain differences by authority, date, scope, or method. A top-ranked page cannot erase a counterexample.

5. Model the browser as a state machine

Browser state includes context or profile, tab, origin, URL, navigation ID, DOM and screenshot digest, scroll position, form state, dialogs, and downloads. Each action transitions from observed to proposed, authorized, dispatched, observed result, and verified. After a submit timeout, query the remote business ID or current page before retry; clicking submit again can duplicate an effect.

6. Observe, act, and observe again

A proposed target binds snapshot ID, role and name, locator or visual region, and expected effect. Immediately before dispatch, the broker rechecks tab and origin, element visibility and actionability, form values, and risk. After the action, it captures new DOM, screenshot, URL, and business observation. Coordinates from an old screenshot, a dynamic advert, or an overlay require fresh localization.

7. Maintain the web trust boundary

Pages, snippets, PDFs, and tool results remain data; they cannot direct a new tool call or replace the task goal. URLs, recipients, and paths copied into action arguments retain taint. High-risk actions resolve them again through trusted sources or user confirmation. The broker isolates cookies, credentials, and browser profiles so page text never receives them in the prompt.

8. Verify citations

Each consequential statement in the final answer cites a source ID and precise span. Check that the span exists, is accessible, and matches the claim's time and scope. Finding the right document while citing the wrong paragraph is still failure. If a source supports only an author-reported result rather than independent replication, label the evidence tier. An unverified claim stays unknown rather than gaining certainty through rewriting.

9. Decide when to stop researching

For each new page, estimate which claim gap it might close. Repeated articles, weak pages, and same-origin copies have declining marginal value. Stop when required claims meet their evidence policies, critical conflicts are resolved or clearly marked, citations lead to sources, and budget and deadline permit a decision. Otherwise deliver a scoped partial or unknown result. “No more search results” is not a stop rule.

10. Recover long-running work

A checkpoint stores claim-graph version, source ledger, query frontier, browser snapshot, pending actions, and budgets. After a restart, revalidate browser session and page identity before resuming reversible observation. Unresolved writes enter reconciliation. Different workers may research and use the browser, but one tab, form, and final report keep single-writer ownership.

11. Evaluate the loop

Research evaluation checks source independence, evidence recall, claim entailment, citation precision, temporal correctness, and abstention. Computer-use evaluation checks task success, action count, state recovery, origin and element checks, duplicate effects, and cleanup. Counterfactual cases change one source or move a button: the relevant conclusion or action should change, while unrelated output remains stable. Benchmark success is not a substitute for acceptance on live sites with real permissions.

04

Essential mathematics: information gain, independent evidence, and stopping budgets

Evidence coverage

Let G be required claims, each with weight wᵢ, and vᵢ∈{0,1} indicate that its evidence policy is satisfied. Weighted coverage is Coverage=Σwᵢvᵢ/Σwᵢ. It helps plan work rather than measuring final correctness. A high-risk claim still has a hard evidence condition; coverage of easier claims cannot compensate for its absence.

Correlated sources

If n pages copy one original report, counting them as n independent sources exaggerates confidence. The heuristic n_eff≈n/[1+(n−1)ρ] illustrates this, where ρ is average dependence; when ρ=1, n_eff≈1. This is intuition, not a calibrated web-evidence probability. Track source lineage and method rather than inventing precision from textual similarity.

Value of another search

Suppose research action a may reduce expected decision loss by ΔL, at execution cost Cₐ and delay penalty Dₐ. Continue when E[ΔL|a]>Cₐ+Dₐ and budget and deadline allow. If a critical claim remains unverified, low expected information value does not authorize completion. Report unknown or escalate instead.

Freshness of UI observations

For observation time tₒ and dispatch time tₐ, state age is Δt=tₐ−tₒ. Faster-changing pages require shorter accepted ages. A mismatch in DOM or URL version forces re-observation. The age threshold is an experimentally chosen policy, not a universal browser-protocol guarantee.

05

Implications for agent systems

Capability: research workers can investigate claim gaps in parallel, while computer-use workers operate constrained interfaces. Source ledgers and browser state preserve continuity across models and workers. The agent can narrow conclusions explicitly when evidence is insufficient.

Reliability: citation spans, page snapshots, action identity, and postconditions make failures replayable. Changing search results, layout drift, and submit timeouts become typed transitions rather than a generic “model failure.”

Security: page text grants no tool authority. Brokers manage browser profiles and credentials. A high-risk UI action rechecks origin, fields, and approval before dispatch. Claims from external files and pages remain evidence, not instructions.

Cost: unlimited search consumes tokens and browser time, while stopping too early creates repair cost. Attribute spend per verified claim and verified outcome, and monitor duplicate-source rate, citation failure, requery, UI retries, and human intervention.

06

Trade-offs and failure modes

  • Search result as evidence: snippets may be truncated, stale, or manipulated. Open the source and retain span and digest.
  • Ten pages equal ten votes: syndicated copies share one origin. Record lineage and independence.
  • Citing a document without a span: the right file may not support the claim. Verify entailment.
  • Reuse old browser coordinates: layout shifts and overlays cause misclicks. Bind actions to snapshots and reobserve before dispatch.
  • Authenticated page means trusted instruction: content remains data and cannot rewrite policy.
  • Retry submit after timeout: the effect may already exist. Query by business ID or idempotency key.
  • Search until budget exhaustion: repeated weak pages add little value. Use claim gaps and marginal value.
  • Model says done: citations and remote effects remain unverified. Verifiers and an unknown state guard completion.
07

Reusable technical judgments

  • Research and computer use share an observation, proposal, authorized action, new observation, and verdict loop.
  • A source ledger retains original spans, versions, retrieval times, and lineage; a claim graph records support and refutation.
  • Research follows evidence gaps and marginal value; required-claim evidence policies decide when to stop.
  • UI actions bind current tab, origin, snapshot, and expected postcondition; ambiguous submissions reconcile first.
  • External content remains data, and independent verifiers check citations and business effects.

09

What is established and where we continue

Established today: research and computer use share a partially observed control loop. The source ledger preserves original sources and dependencies, the claim graph marks support and refutation, and browser state binds every action to current page identity and a postcondition. Independent evidence governs both research stopping and UI completion.

Still unresolved: can a system improve its prompts, router, skills, or code using its own traces and evaluations? How are changes proposed and experiments isolated, test leakage and reward gaming prevented, and new versions proven rollback-ready?
