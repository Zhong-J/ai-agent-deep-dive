Agent 看见一张截图时，模型到底看见了什么？

从像素、patch、视觉编码器到 LLM 的桥接层，解释分辨率、视觉 token 成本与小字/空间定位的失真。

2026-10-24约 20 分钟Multimodal LLM / Vision Transformer / CLIP / Visual tokens / Resolution / Computer use
01

今日命题

一个 Agent 截取浏览器页面，把 PNG 交给多模态模型，然后模型说‘点击右上角的删除按钮’。人眼能清楚辨认的按钮，模型却可能读错标签或坐标。原因不是‘模型没有视觉’，而是它收到的不是原始像素的无损副本：图片要被缩放或切块、编码成向量，再通过投影或交叉注意力与语言模型连接。每一步都受分辨率、视觉 token 数、训练目标和计算预算约束。输入里有像素，不等于模型能可靠定位每个像素。

今天开始 Multimodal Agent Internals 1/3，不重讲 Agent loop。要拆开一张 screenshot 进入模型的路径：视觉编码器学了什么、语言模型如何接收视觉特征、为什么大图可能被压得看不清小字、为什么文字描述与空间坐标是不同能力。第二篇再讲 visual grounding、坐标系与 computer-use 动作闭环；第三篇做质量、安全和端到端验收。

核心判断：多模态推理先受感知瓶颈限制，再受语言推理限制。视觉信息在入口丢失后，后面的长链思考不能把它恢复成事实。
02

承接 Transformer、context 与 Agent 工具

此前 Transformer 一篇把 token 表示、attention 与 residual stream 连起来；KV/cache 与长上下文几篇说明，进入序列的内容会占 prefill 和缓存预算。视觉输入不是‘先把图片 OCR 成文字再照常 prompt’的通用等价物：一些架构把图像 patch 特征映射成语言模型可消费的一串向量，另一些让语言模型通过 cross-attention 读取独立视觉特征。两者都把图像信息变成有限的内部表示，却不保证保留原图每个字形、颜色或坐标。

这与 Agent 的工具使用直接相关。retrieval tool 返回文档 span，至少还能回链原文；screenshot 返回的是观测时刻的图像。模型说‘右上角’可能源于全局视觉语义，未必建立了精确的可点击目标框。运行时需要保存原始截图、视口尺寸、缩放比例、时间和动作后的新观测，才能把模型提议的视觉动作与真正的 UI 状态对齐。截图中的网页文本仍是低信任数据，不能因为被视觉编码器处理就变成授权指令。

03

机制：像素怎样跨过语言模型边界

1. 像素先被预处理

图片可能被统一缩放、保持长宽比后填充、中心裁剪，或分成高分辨率 tiles。模型处理的是预处理后的视图而非永远完整的原图。缩小大页面可节约计算，却可能把小字压到一个 patch 内；只看局部裁剪又可能丢失‘按钮属于哪个对话框’的全局关系。NaViT 等作者探索不同长宽比与分辨率的 patch 处理；具体 API 怎样裁图属于实现行为，不能从‘支持图片输入’四个字推断。

2. 视觉编码器把 patch 变成特征

ViT 的典型构造将图像划成不重叠 patch，展平并线性映射，再加位置信息送入 Transformer；它训练为图像识别，不是天然的 GUI 定位器。CLIP 通过图文对比目标让图像与文字表征更易语义对齐，可识别‘这像登录页’等全局概念；这不等于它对每个像素或 OCR 小字都可靠。视觉 encoder 输出的是上下文化特征，最终语言输出由后续桥接与 LLM 决定，不能把 CLIP 本身误称为生成式对话模型。

3. 视觉和语言有不止一种桥

LLaVA 原论文将视觉编码器特征经可训练投影接入 LLM，再用视觉指令数据调优；输出侧仍是语言模型按 token 解码。Flamingo 采用 Perceiver Resampler 压缩视觉特征，并在语言模型层使用 gated cross-attention 读取视觉上下文。两者说明‘图像变成多少 token’不是跨架构通用常数：可能是输入序列中的视觉向量，也可能是独立视觉记忆被语言层访问。桥接让语言模型利用视觉信息，但瓶颈可能是视觉训练覆盖、重采样压缩或语言端对空间关系的利用。

4. 高分辨率是成本与证据的取舍

动态分辨率、裁块和多尺度可以保留更多细节，代价是更多视觉表示、prefill/attention 计算与延迟。Qwen2-VL 论文报告其 any-resolution 处理方案，这是作者架构和实验，不表示任一服务都按同样数量的视觉 token 计费或有同等 OCR 表现。对 Agent，先判任务需要全局布局、局部小字还是二者：单张缩小截图、多个局部 crop、外部 OCR 读出的文本是不同证据路径；组合时必须把 crop 坐标映回原始视口。

5. 输出不是感知的证明

模型回答‘按钮在 (820,120)’只是一条生成结果。若原图缩放到一半，坐标可能指向模型输入图而非原始桌面；若页面在推理期间重排，原坐标已过期。外层运行时需要用可观察 UI 状态验证目标、权限与动作后结果。第二篇将细化这个 grounding 问题；今天先保留关键边界：语言的流畅描述不等于准确识别像素目标。

04

必要数学：patch 数为何影响成本与细节

对一个未裁切、未重叠 patch 的简化 ViT，宽 W、高 H、每 patch 边长 P，patch 数约为 N≈⌈W/P⌉·⌈H/P⌉。W、H、P 都用像素表示，⌈·⌉ 向上取整并假设边界做 padding。例：224×224 图、P=16，N=14×14=196；1024×1024 且 P=16，则 N=4096，是前者约 21 倍。实际模型可能缩图、分 tile、合并 patch 或 resample，不能把这个 N 当任意 API 的视觉 token 账单。

若架构把 N 个视觉向量接入 T 个文字 token 的同一个标准 full self-attention 序列，序列长 L=T+N，单层朴素 attention 的成对交互项随 O(L²) 增长；KV 驻留则随 L 近似线性增加。这里 O 表示随长度变化的量级，不是实际毫秒数。FlashAttention 改善访存，cross-attention/局部窗口/resampler 改变处理路径，因此不能把二次式直接套到每个多模态产品。工程意义是：‘再加十张图’可能同时影响 prefill、缓存和 p99，而不是只有上传流量。

分辨率下降影响可辨认特征的尺度。若 8 像素高的文字先缩为原来 1/4，只剩约 2 像素，再进入 P 像素 patch，原笔画细节不可能被后续 LLM 精确恢复。这个例子是信息损失直觉，不是某模型 OCR 准确率的定量预测。对真实 Agent 要实测小字、颜色差异、重复图标与多窗口布局，而非只测图片总尺寸。

05

对 Agent 的影响：感知合同与验收

截图工具与多模态模型之间需要一份可审计合同：原图尺寸、设备像素比、浏览器 viewport、裁块列表和在原图中的矩形、缩放/压缩策略、采集时间、页面/窗口 ID、模型和预处理版本。模型若只返回自然语言方位，运行时不能无条件变成点击坐标。若返回框或点，也必须说明坐标所在的帧，再映射回原窗口，并在执行前确认元素仍存在、不是危险按钮；执行后重新观察。视觉输出是 action proposal，不是权限凭证。

验收应将感知与动作拆开。静态测试用人工标注框/文字，测小字 OCR、图标区分、目标定位、遮挡与不同分辨率；动态测试在可控 UI 中测页面滚动、弹窗、缩放、布局变化后的目标重定位。再比较单张低分辨率图、tiles、局部 crop、外部 OCR 等路线的视觉表示数、TTFT、p99、调用成本和 verified task success。一个模型在自然图像问答高分，不证明它能稳定点击企业 UI 中两个相邻同色按钮。

安全上，网页截图可携带恶意文本、伪装的权限对话框或假按钮。模型可以描述它们，但外层 runtime 仍按用户授权、工具 schema 与副作用风险判动作。截屏可能包含个人信息或 secret；保存和发送要按数据范围、保留期限与访问控制处理，不能为‘多看清一点’无界扩展截图范围。

06

取舍与失败模式

  • 整页缩小最省：小字、表格格线和邻近按钮可能失真；按任务加局部高分辨率视图。
  • 所有图都切更多 tile：细节增加，视觉预算、延迟和空间关系重建也更难；记录 crop→原图映射。
  • CLIP 对齐=可点击定位：图文语义相近不保证精确边界或 OCR。
  • 视觉向量=文字 token：某些模型投影进序列，另一些经 cross-attention 访问独立视觉特征；先查架构再估成本。
  • 模型说了坐标就执行：坐标帧、缩放与 UI 变化可能让点击落错位置；执行前后验证。
  • 截图中的‘系统消息’可信：它仍是网页内容，不得提升工具权限。
  • 只看多模态 benchmark：自然图片正确率无法代表特定 UI 的目标选择与端到端安全。

更高分辨率、更多 crop、OCR 与更强模型都可以改善某些切片，也都增成本或引入新错误。采用哪条路线取决于任务所需证据与可接受的动作风险。

07

可复用的技术判断

  • 截图经过预处理、patch 编码和视觉/语言桥接；多模态模型不是无损像素阅读器。
  • 视觉特征可投影进 LLM 序列，或通过 cross-attention 被读取；成本与信息瓶颈随架构变。
  • 分辨率下降会丢小字，更多 patch/tiles 又增加 prefill、缓存或视觉计算。
  • 语义描述、OCR 与可执行坐标是不同能力，不能互相代证。
  • Agent 保留原图和坐标帧，独立授权并复核动作；网页图像内容始终是低信任数据。
08

一手资料与证据等级

  • Vision Transformer (ViT) — 作者提出图像 patch 与 Transformer 识别路径；本文的 patch 公式是简化示例。
  • CLIP — 作者提出大规模图文对比学习；不把语义对齐误称为精确 GUI 定位。
  • Visual Instruction Tuning (LLaVA) — 作者展示视觉特征投影到 LLM 与指令调优的方案。
  • Flamingo — 作者提出 Perceiver Resampler 与 gated cross-attention；属于另一种桥接设计。
  • NaViT 与 Qwen2-VL — 作者分别研究可变长宽比/分辨率与动态视觉处理，效果属各自模型和实验。

When an Agent Sees a Screenshot, What Does the Model Actually Receive?

Follow pixels through patches, a vision encoder, and the bridge into an LLM to explain resolution, visual-token cost, and failures on tiny text or spatial details.

2026-10-2420 min readMultimodal LLM / Vision Transformer / CLIP / Visual tokens / Resolution / Computer use
01

Today's proposition

An agent captures a browser screenshot, sends the PNG to a multimodal model, and gets 'click the delete button in the upper right.' A human can read that button while the model may misread its label or location. The issue is not that the model has no visual pathway. The image it receives is not an unconstrained, lossless copy of pixels: it is resized or tiled, encoded into vectors, then connected to a language model by a projection or cross-attention mechanism. Resolution, visual-token count, training objectives, and compute budgets constrain each stage. Pixels being present in the input does not imply reliable localization of every pixel.

Multimodal Agent Internals begins without replaying the agent loop. Today we trace a screenshot into model state: what a vision encoder learns, how the LLM consumes visual features, why a large image may lose tiny text, and why describing a scene differs from producing an actionable coordinate. Part 2 will tackle visual grounding, coordinate frames, and the computer-use action loop. Part 3 will build quality, safety, and end-to-end acceptance gates.

Core judgment: multimodal reasoning is bounded first by perception and then by language reasoning. A long chain of thought cannot restore visual facts discarded at the input boundary.
02

Connecting transformers, context, and agent tools

The earlier Transformer lesson connected token representations, attention, and the residual stream. KV and long-context lessons showed that material entering a model sequence consumes prefill and cache budgets. A visual input is not universally equivalent to 'OCR the image and paste text into the prompt.' Some architectures project image-patch features into a sequence that the language model consumes. Others let the language model read separate visual features through cross-attention. Both compress the image into finite internal representations; neither guarantees preservation of every glyph, color, or coordinate.

This matters directly for tool use. A retrieval tool can return a document span that links back to text. A screenshot is an observation of UI state at a particular moment. 'Upper right' may reflect global visual semantics without a precise clickable target box. The runtime should preserve the original screenshot, viewport size, display scale, timestamp, and post-action observation to align a model-proposed action with the real interface. Text inside a screenshot remains low-trust page data; visual encoding does not turn it into an authorized instruction.

03

Mechanism: how pixels cross the language-model boundary

1. Pixels are preprocessed first

An image may be resized to a fixed canvas, padded to preserve aspect ratio, center-cropped, or split into higher-resolution tiles. The model receives those processed views, not necessarily the entire original at full fidelity. Shrinking a large page saves computation but can squeeze tiny text into one patch. A local crop can preserve small text while losing which dialog owns a button. The NaViT authors explore handling variable aspect ratios and resolutions. How a particular API crops images is an implementation behavior, not something implied by the phrase 'supports image input.'

2. Vision encoders turn patches into features

A typical ViT divides an image into nonoverlapping patches, flattens and linearly embeds them, adds positional information, then processes them with a Transformer. Its image-recognition objective does not make it a GUI localizer by default. CLIP's contrastive image-text objective aligns visual and textual representations, helping global semantics such as 'this resembles a login screen.' That does not guarantee pixel-perfect localization or tiny-text OCR. The vision encoder emits contextualized features. Later bridging and language decoding produce the answer; CLIP alone is not a generative chat model.

3. Vision and language have more than one bridge

The original LLaVA work uses a trainable projection from vision-encoder features into an LLM and then visual instruction tuning. Output still comes from autoregressive language-token decoding. Flamingo uses a Perceiver Resampler to compress visual features and gated cross-attention layers in the language model to read visual context. These designs show that 'how many image tokens' is not a universal constant. Visual vectors may occupy a language input sequence or remain separate visual memory accessed by language layers. The bridge enables visual conditioning but cannot remove limitations from encoder training, resampling compression, or language-side use of spatial relations.

4. Higher resolution trades cost for evidence

Dynamic resolution, tiles, and multi-scale views can retain detail at the price of more visual representations, prefill or attention work, and latency. Qwen2-VL's authors report an any-resolution design and its experiments. That is not a claim that every service bills an identical number of visual tokens or achieves identical OCR quality. For an agent, ask whether the task needs global layout, tiny local text, or both. One shrunk screenshot, several crops, and externally extracted OCR text are different evidence paths. When combining them, map crop coordinates back to the original viewport.

5. An output is not proof of perception

'The button is at (820,120)' is a generated statement. If the source image was scaled by half, the coordinate may refer to the processed image rather than the desktop. If the page reflowed during inference, the coordinate may already be stale. The outer runtime must check observable UI state, authority, and the action result. Part 2 will develop grounding in detail. Today's boundary is that fluent language about an image is not proof that a pixel target was identified accurately.

04

Essential mathematics: patch count, cost, and detail

For a simplified ViT with nonoverlapping patches and no cropping, let W and H be image width and height in pixels and P the patch side length. Patch count is approximately N≈⌈W/P⌉·⌈H/P⌉. The ceiling rounds up under an assumed padded boundary. A 224×224 image at P=16 yields 14×14=196 patches. A 1024×1024 image at the same P yields 4096, about twenty-one times as many. Real models may resize, tile, merge patches, or resample features. This N is not a visual-token bill for every API.

If N visual vectors join T text tokens in one standard full-self-attention sequence, sequence length is L=T+N. Pairwise attention work per layer has naive O(L²) scaling, while KV residency grows approximately linearly with L. O denotes growth order, not milliseconds. FlashAttention changes memory traffic; cross-attention, local windows, and resamplers change the computational path. The quadratic expression is therefore not a universal performance model for multimodal products. The engineering point is that 'add ten screenshots' can alter prefill, cache, and p99, not only upload bytes.

Lower resolution also changes the scale of recognizable features. If an eight-pixel-high label is shrunk to one quarter of its size, it becomes roughly two pixels high before entering P-pixel patches. Its original stroke detail cannot be perfectly recovered by a downstream LLM. That is an information-loss illustration, not a quantitative OCR-accuracy prediction for a given model. Test real agent slices with tiny text, color differences, repeated icons, and multiwindow layouts rather than only total image dimensions.

05

Agent implications: a perception contract and acceptance

The screenshot-tool to multimodal-model boundary needs an auditable contract: original dimensions, device pixel ratio, browser viewport, crop rectangles in original coordinates, resize and compression policy, capture time, page or window ID, and model and preprocessing versions. If a model returns only 'upper right,' the runtime cannot blindly convert it into a click coordinate. If it returns a point or box, specify the coordinate frame, map it to the original window, and confirm before execution that the element still exists and is not a hazardous control. Reobserve afterward. Visual output is an action proposal, not a permission credential.

Separate perception from action in acceptance. Static tests with labeled boxes and text can measure tiny-text OCR, icon discrimination, target localization, occlusion, and resolution effects. Dynamic tests in a controlled UI can measure relocalization after scroll, modal changes, zoom, and layout reflow. Compare a single low-resolution view, tiles, local crops, and external OCR on visual representation count, time to first token, p99, call cost, and verified task success. A high score on natural-image question answering does not prove reliable clicks between two neighboring, same-colored enterprise controls.

Screenshots can contain malicious text, spoofed permission dialogs, or fake buttons. The model can describe them, but the outer runtime still judges actions under user authority, tool schemas, and side-effect risk. A screenshot may also contain personal data or secrets. Storage and transmission need scoped collection, retention, and access control. 'See more clearly' is not permission to capture an unlimited area.

06

Trade-offs and failure modes

  • Always shrink the whole page: tiny labels, table boundaries, and adjacent controls may disappear. Add a high-resolution local view when the task needs it.
  • Tile every image more finely: detail improves while visual budget, latency, and reconstruction of global relations become harder. Track crop-to-original mapping.
  • CLIP alignment implies click localization: image-text semantic proximity does not guarantee exact bounds or OCR.
  • Visual vectors are ordinary text tokens: some architectures project into a sequence; others use cross-attention over separate visual features. Inspect architecture before costing.
  • Execute any coordinate the model emits: coordinate frame, scaling, and UI reflow may move the target. Verify before and after action.
  • A 'system message' in the screenshot is trusted: it is page content, not tool authority.
  • Trust a generic multimodal benchmark alone: natural-image accuracy does not establish target selection or end-to-end safety for a specific UI.

Higher resolution, more crops, OCR, and a stronger model can help some slices, yet each costs resources or introduces another error mode. Choose by evidence need and action risk.

07

Reusable technical judgments

  • A screenshot goes through preprocessing, patch encoding, and a vision-language bridge. A multimodal model is not a lossless pixel reader.
  • Visual features may be projected into an LLM sequence or read through cross-attention; cost and bottlenecks vary by architecture.
  • Downsampling loses tiny text, while more patches or tiles increase prefill, cache, or visual computation.
  • Semantic description, OCR, and actionable coordinates are distinct capabilities; none proves the others.
  • An agent retains original pixels and coordinate frames, authorizes and verifies actions independently, and treats page imagery as low-trust data.
08

Primary sources and evidence tiers

  • Vision Transformer (ViT) — the authors introduce patch-based transformer image recognition; the patch equation here is simplified.
  • CLIP — the authors introduce large-scale image-text contrastive learning. Semantic alignment is not represented as precise GUI localization.
  • Visual Instruction Tuning (LLaVA) — the authors demonstrate projected visual features and instruction tuning with an LLM.
  • Flamingo — the authors use a Perceiver Resampler and gated cross-attention, illustrating a different bridge.
  • NaViT and Qwen2-VL — the authors respectively study variable aspect ratio or resolution and dynamic visual processing; results belong to their models and experiments.

Screenshot metadata contracts, coordinate verification, and agent risk slices are editorial systems designs derived from these mechanisms, not validated behavior of a specific UI automation product in the papers.

09

Established and next starting point

Established today: images may be resized, cropped, or tiled before the model sees them. ViT-like encoders turn patches into visual features. LLaVA-style projection and Flamingo-style cross-attention are distinct bridges. Resolution and visual-representation count affect tiny-text visibility and compute cost, but fluent output does not prove precise localization. The outer agent retains original pixels, viewport, and coordinate transforms while keeping page content at lower trust.

Still unresolved: how do visual features anchor to one concrete UI element? How are points, boxes, OCR characters, DOM nodes, and screen-pixel coordinates related? After occlusion, scrolling, or dynamic reflow, how can the agent avoid a misclick on a side-effectful control?
