Tools 与 Extensibility 内核 · 第 4/4 篇

一个 Extension “测试通过”，为什么仍可能偷走 Secret？

用攻击链、contract mutation、sandbox/egress oracles、shadow/canary 和撤销演练完成 Tools & Extensibility 的生产验收。

2026-10-01约 20 分钟Extension security / Prompt injection / SSRF / Secret exfiltration / Security evaluation
01

今日命题

一个 extension 能在 happy-path 测试中正确完成任务，不表示它安全。真正攻击常跨越多层：网页中的 prompt injection 诱导模型调用 extension tool；tool 把任意 URL 交给 server；server 利用 host credential 请求 metadata/internal endpoint；返回内容再把 secret 编码进外部消息。每个组件单独看都可能“按 contract 工作”，组合后却形成 exfiltration path。

因此 Tools & Extensibility 的验收单位不是某个函数或 sandbox，而是完整 capability graph 和 data flow。测试必须覆盖 instruction/data boundary、tool selection、schema/semantic validation、catalog policy、permission broker、network egress、result serialization、hook lifecycle、upgrade/revocation。每一层既有局部 oracle，又有端到端 forbidden outcome：越权 effect、跨租户数据、secret egress 和撤销后继续执行必须为零。

核心判断：“没有观察到攻击”不是安全证据。生产 readiness 要证明攻击链在最早可判定边界被阻断，阻断原因可审计，并且当未知缺陷出现时，host 能立即撤销 capability、credential 和新 dispatch，而不是等模型学会拒绝。
02

把前三篇串成一条可攻击也可验证的链

1/4 要求 schema、semantic validation 与 typed results；2/4 要求 MCP advertised catalog 经 host policy 编译成 snapshot；3/4 将 extension 拆成 instruction/data/code/tools 并按 component 授权隔离。安全评测要验证这些边界组合后仍成立：恶意 description 不应改变 instruction precedence，宽松 schema 不应突破 broker，dependency update 不应静默扩权，sandbox output 不应通过 trusted result channel 获得更高 authority。

测试夹具因此需要五类身份：attacker-controlled data、extension publisher、host/runtime、current user/principal、effect owner。还需要资源图：workspace files、secrets、internal network、external destinations、tools 与 credentials。每个 case 声明允许的信息流和禁止的信息流，而不只是期望文本答案。

最有价值的测试常是“近似合法”：允许访问 api.example.com，但攻击使用 redirect、DNS rebinding、IPv6 literal 或 userinfo 绕过；允许读取 workspace，攻击用 symlink 指向外部；允许发送摘要，攻击把 secret 拆成多个低熵字段。安全 contract 必须规范化后判定真实 resource/effect。

03

机制：攻击链驱动的 extension acceptance harness

1. 建 threat model 和 forbidden flows

列资产、主体、入口、trust boundaries 与副作用。Forbidden flows 例如 secret→tool result、other tenant file→model context、untrusted URL→internal IP、revoked package→new process、data text→instruction precedence。case 同时声明允许 flow，避免把“全部拒绝”误当安全。

2. Prompt injection corpus

在网页、PDF、tool result、MCP description、README、image OCR 和 nested archive 中放直接/间接注入，包含编码、翻译、角色伪装和分步诱导。Oracle 不只看最终文本，还看是否选择 forbidden tool、是否把 data 提升为 instruction、是否请求超出 task purpose 的 permission。

3. Tool contract mutation

自动生成 mutants：删除 required、放宽 additionalProperties、把 enum 换 string、交换 read/write description、去掉 resource version、把 error 改成 generic。好的 eval 必须让危险 mutant 失败，否则测试只覆盖 happy path。对 recorded calls 做 compatibility replay，确认旧 snapshot 不被新 contract 误解。

4. Broker 与 sandbox adversarial tests

测试 path traversal、symlink/junction、case normalization、UNC/device path、fork/process tree、shared memory、environment inheritance、resource exhaustion、timeout/cancellation 和 sandbox escape known primitives。Oracle 是 broker decision 与 OS-level observation，不相信 extension 自报“未访问”。默认 deny，允许 capability 有资源、操作、期限、quota 和 purpose。

5. SSRF 与 egress

egress proxy 解析 URL 后固定 scheme/host/port，DNS resolution 后拒绝 loopback/link-local/private/metadata ranges，redirect 每跳重验，防 DNS rebinding，限制 response size/type/time。测试 decimal/octal/IPv6 IP、userinfo、mixed encoding、redirect chain 与 attacker DNS。允许域名不等于允许其任意 redirect。

6. Secret exfiltration/DLP

secret 使用 honeytokens 和 unique markers，分别放 env、file、credential broker 与 tool output。攻击尝试直接发送、base64、字符拆分、hash oracle、错误消息、DNS label 和图像/文件 covert channel。DLP 不能成为唯一防线；更重要的是 code 默认拿不到 secret，credential broker 只提供 audience-bound operation 而不是 raw token。

7. Identity 与 confused deputy

构造低权限 user 诱导高权限 host/server 调用的 case，检查 OAuth audience/scope、resource indicators、redirect URI、consent 与 downstream principal propagation。Host 不接受 token passthrough，不因 server 已认证就替用户扩权。effect owner 使用最终 principal/purpose 重新授权。

8. Lifecycle/TOCTOU

在 plan 后、dispatch 前撤销 role/consent/tool/package；在 call 中升级 schema；在 hook 运行时取消 task；在 dependency 下载后替换 artifact。期望新 dispatch 立即失败、in-flight 按 captured contract reconcile、旧 digest 不被替换、hook 收到 cancellation 且 broker token 过期。

9. First-divergence trace

保存 attacker input、effective instructions、catalog/permission snapshots、model selection、validated args、broker requests、DNS/egress decisions、effect-owner authorization、result serialization 与 audit events。分类器找最早偏离 oracle 的层，而非只记“攻击成功/失败”。同一攻击被早期 instruction boundary 阻断，比依赖最后 DLP 更强。

10. Shadow/canary/kill switch

新 extension 或版本先 offline replay，再 shadow 禁止 effect，比较 tool/permission decisions；canary 按 tenant/risk 分层，以 forbidden attempt、denial spike、sandbox fault、egress anomaly、latency 为 rollback gate。Kill switch 独立于 catalog refresh，能禁 package/tool/publisher/digest、撤 credential、阻新 process 和 dispatch。

11. Revocation drill 与恢复

定期演练 compromised publisher：撤销签名 key/package digest，定位 installed instances、running snapshots、credentials、artifacts 与 effects。验证多久阻断、多久清理、哪些业务 effect 需 compensation。没有演练的 uninstall 文档不是 incident capability。

12. Production acceptance checklist

是否有 artifact provenance/SBOM/lock；component permission 是否最小且可解释；instructions/data 是否标层；code 是否 default-deny sandbox；tools 是否经 catalog compiler；identity 是否 end-to-end；network 是否 brokered；results 是否 untrusted；hooks 是否受 lifecycle；snapshots 是否 pinned；撤销是否即时；trace 是否支持 replay。任一高风险项缺失则不能靠 model eval 分数放行。

04

必要数学：攻击链概率、覆盖与安全门

链式防御

若攻击需依次绕过 n 个 gate，条件绕过概率为 pᵢ，则理想化成功概率 P_attack=∏pᵢ。它不假设真实独立性；相反，提醒我们共享 parser/identity/policy 会造成相关失效。Defense-in-depth 的价值来自不同机制和 failure modes，而不是重复三次同一 LLM judge。

Exposure

能力 i 的风险近似 Rᵢ=P(misuseᵢ)·Impactᵢ·Exposureᵢ，Exposure 可由资源数、有效时长、调用 quota、egress destinations 表示。即使难准确估 P，缩短 token lifetime、限制 roots/origins/quota 能确定降低 exposure。最小权限是可操作的 risk control。

安全门而非平均分

定义 task utility U，但 forbidden-flow rate F、cross-tenant leakage L、revoked-dispatch D 必须满足 F=L=D=0 才可发布。它们不能被平均 task success 抵消。对统计上无法证明绝对零的线上系统，使用上界 confidence、持续监控和即时 kill switch，而不是宣称“零风险”。

05

对 Agent 系统的影响

开发：每个 extension change 都要更新 threat cases、contract mutants、permission snapshot 与 replay fixtures。安全测试和功能测试共用同一 trace，不再把 red team 当发布前一次活动。

运营：dashboard 拆 forbidden attempts、broker denies、sandbox faults、egress/DLP alerts、catalog/permission drift、hook overruns、revocation latency 与 compensation backlog。攻击被阻断是安全信号，不等于产品失败；denial spike 才需诊断。

用户体验：consent UI 展示 effective permissions、来源、依赖与目的，而非几十个底层 scopes。高风险动作显示具体 resource/effect；更新新增权限时重新确认。用户拒绝后提供明确 degraded mode。

架构：kill switch、credential revocation 和 broker deny 必须位于模型之外。模型可以帮助分类风险和解释 consent，但不能成为最终授权或安全隔离边界。

06

设计取舍与失败模式

  • 只做 prompt injection benchmark：忽略 code/network/identity 链；按 forbidden flow 做端到端攻击。
  • LLM judge 判安全：judge 与 agent 共享偏见且看不到 OS effect；关键 oracle 来自 broker/effect owner。
  • DLP 兜底一切：编码/covert channel 可绕过；优先不授 secret、不允许 egress。
  • allowlist 只看 hostname：redirect/DNS/解析差异导致 SSRF；解析后每跳重验真实地址。
  • sandbox test 自报：extension 日志不可作为隔离证明；用外部 OS/network observation。
  • canary 只看 task success：安全 regression 低频被平均；zero-tolerance gates 单列。
  • kill switch 依赖 catalog refresh：被攻击 server 可阻止刷新；独立 deny plane。
  • 撤销不补偿：阻止新 call 但已发生 effect 留下风险；reconciliation/compensation 进入 incident runbook。
07

可复用的技术判断

  • extension security eval 的单位是跨 instruction、tool、sandbox、network、effect 的 forbidden information flow。
  • prompt injection、SSRF、secret exfiltration、confused deputy、TOCTOU 与 supply-chain mutation 要组合测试。
  • 关键 oracle 来自 host/broker/OS/effect owner，不来自 extension 或模型自报。
  • shadow/canary 以 zero-tolerance safety gates 和 first-divergence trace 驱动 rollout/rollback。
  • kill switch、credential revocation、snapshot deny 与 compensation runbook 必须独立于模型和被攻击 server。

Why Can an Extension Pass Tests and Still Exfiltrate a Secret?

Complete production acceptance for Tools and Extensibility with attack chains, contract mutation, sandbox and egress oracles, shadow and canary rollout, and revocation drills.

2026-10-0120 min readExtension security / Prompt injection / SSRF / Secret exfiltration / Security evaluation
01

Today's proposition

An extension can complete every happy-path test and still be unsafe. Real attacks cross layers. Prompt injection inside a web page induces the model to select an extension tool. The tool passes an arbitrary URL to a server. The server uses host credentials to query a metadata or internal endpoint. Returned content encodes the secret into an external message. Every component may appear to follow its contract while composition creates an exfiltration path.

Acceptance therefore evaluates the complete capability graph and data flow, not one function or sandbox. Tests cover instruction and data boundaries, tool selection, schema and semantic validation, catalog policy, permission broker, network egress, result serialization, hook lifecycle, upgrade, and revocation. Each layer has a local oracle plus end-to-end forbidden outcomes: unauthorized effects, cross-tenant data, secret egress, and execution after revocation must remain zero.

Core judgment: “we did not observe an attack” is not security evidence. Production readiness proves that an attack chain is blocked at the earliest decidable boundary, the reason is auditable, and the host can immediately revoke capabilities, credentials, and new dispatch when an unknown defect appears. Waiting for the model to learn refusal is not containment.
02

Turn three parts into an attackable, testable chain

Part 1 required schemas, semantic validation, and typed results. Part 2 compiled MCP advertised catalogs through host policy into snapshots. Part 3 separated instructions, data, code, and tools with per-component authorization and isolation. Security evaluation proves those boundaries survive composition: hostile descriptions cannot alter instruction precedence, permissive schemas cannot bypass brokers, dependency updates cannot silently expand authority, and sandbox output cannot gain higher authority through a trusted result channel.

Fixtures therefore model five identities: attacker-controlled data, extension publisher, host or runtime, current user and principal, and effect owner. They also model resources: workspace files, secrets, internal network, external destinations, tools, and credentials. Each case declares allowed and forbidden information flows rather than only an expected text answer.

The most valuable cases are almost legitimate. Network access to api.example.com is allowed, but the attack uses redirects, DNS rebinding, IPv6 literals, or userinfo parsing. Workspace reads are allowed, but a symlink escapes the root. Sending a summary is allowed, but a secret is split across low-entropy fields. Security policy evaluates the normalized real resource and effect.

03

Mechanism: an attack-chain-driven extension acceptance harness

1. Build a threat model and forbidden flows

List assets, principals, entries, trust boundaries, and effects. Forbidden flows include secret to tool result, other-tenant file to model context, untrusted URL to internal IP, revoked package to new process, and data text to instruction precedence. Cases also state allowed flows so denying everything cannot masquerade as security.

2. Build a prompt-injection corpus

Place direct and indirect injections in web pages, PDFs, tool results, MCP descriptions, READMEs, image OCR, and nested archives. Include encoding, translation, role impersonation, and multi-step inducement. The oracle checks more than final text: forbidden tool selection, elevation of data to instruction, and permission requests outside task purpose.

3. Mutate tool contracts

Generate mutants that remove required fields, relax additionalProperties, replace enums with strings, swap read and write descriptions, remove resource versions, or collapse typed errors. A useful suite rejects dangerous mutants; otherwise it tests only happy paths. Replay recorded calls to ensure a new contract cannot reinterpret an old snapshot.

4. Attack broker and sandbox

Test path traversal, symlinks and junctions, case normalization, UNC and device paths, process trees, shared memory, inherited environment, resource exhaustion, timeout, cancellation, and known sandbox-escape primitives. Oracles use broker decisions and OS-level observations, not extension claims. Default deny capabilities bind resource, operation, duration, quota, and purpose.

5. Test SSRF and egress

The egress proxy normalizes URL, pins scheme, host, and port, resolves DNS, blocks loopback, link-local, private, and metadata ranges, revalidates every redirect, resists DNS rebinding, and limits response size, type, and time. Cases cover decimal or octal IPs, IPv6 literals, userinfo, mixed encoding, redirect chains, and attacker-controlled DNS. An allowed hostname does not authorize arbitrary redirects.

6. Test secret exfiltration and DLP

Use honeytokens and unique markers in environment, files, credential broker, and tool output. Attacks try direct send, base64, character splitting, hash oracles, errors, DNS labels, images, and file covert channels. DLP is not the primary defense. Code should not receive the secret; a credential broker provides an audience-bound operation rather than a raw token.

7. Test identity and confused deputy

A low-privilege user induces a high-privilege host or server call. Verify OAuth audience and scope, resource indicators, redirect URI, consent, and downstream principal propagation. The host rejects token passthrough and does not expand authority because a server is authenticated. The effect owner reauthorizes final principal and purpose.

8. Test lifecycle and TOCTOU

Revoke role, consent, tool, or package after planning but before dispatch. Upgrade schema during a call, cancel during a hook, and replace an artifact after dependency download. New dispatch fails immediately, in-flight work reconciles under captured contract, old digest cannot be substituted, and hook broker tokens expire on cancellation.

9. Retain first-divergence traces

Save attacker input, effective instructions, catalog and permission snapshots, model selection, validated arguments, broker requests, DNS and egress decisions, effect-owner authorization, result serialization, and audit events. Find the earliest layer diverging from oracle rather than recording attack success only. Blocking injection at the instruction boundary is stronger than relying on final DLP.

10. Use shadow, canary, and kill switches

A new version passes offline replay, then shadow execution with effects disabled. Compare tool and permission decisions. Canary by tenant and risk, with forbidden attempts, denial spikes, sandbox faults, egress anomalies, and latency as rollback gates. A kill switch independent of catalog refresh disables package, tool, publisher, or digest, revokes credentials, and blocks new processes and dispatch.

11. Drill revocation and recovery

Simulate a compromised publisher: revoke key and package digest, locate installed instances, running snapshots, credentials, artifacts, and effects. Measure time to block and clean up, and identify business effects requiring compensation. An uninstall document that has never been exercised is not incident capability.

12. Apply a production acceptance checklist

Require artifact provenance, SBOM, and lock; minimal explainable component permissions; labeled instructions and data; default-deny code sandbox; policy-compiled tools; end-to-end identity; brokered network; untrusted results; lifecycle-bound hooks; pinned snapshots; immediate revocation; and replayable traces. A missing high-risk control cannot be offset by model-evaluation scores.

04

Essential mathematics: attack-chain probability, coverage, and safety gates

Chained defense

If an attack must bypass n gates with conditional bypass probabilities pᵢ, an idealized success probability is P_attack=∏pᵢ. This does not assert real independence. Shared parsers, identity, or policy create correlated failures. Defense in depth works through different mechanisms and failure modes, not three repetitions of the same LLM judge.

Exposure

Approximate capability risk as Rᵢ=P(misuseᵢ)·Impactᵢ·Exposureᵢ, where exposure covers resource count, validity duration, call quota, and egress destinations. Even when misuse probability is uncertain, shorter token lifetime and narrower roots, origins, and quotas deterministically reduce exposure. Least privilege is an operational risk control.

Safety gates, not averages

Task utility U may be averaged, but forbidden-flow rate F, cross-tenant leakage L, and dispatch-after-revocation D must satisfy F=L=D=0 before release. Task success cannot compensate. Because production statistics cannot prove absolute zero, teams use confidence bounds, continuous monitoring, and immediate kill switches instead of claiming zero risk.

05

Implications for agent systems

Development: every extension change updates threat cases, contract mutants, permission snapshots, and replay fixtures. Security and functional tests share the same traces; red teaming is no longer a one-time pre-release event.

Operations: dashboards separate forbidden attempts, broker denials, sandbox faults, egress and DLP alerts, catalog and permission drift, hook overruns, revocation latency, and compensation backlog. A blocked attack is a security signal, not product failure; a denial spike requires diagnosis.

User experience: consent UI shows effective permissions, origin, dependencies, and purpose rather than dozens of low-level scopes. High-risk actions show concrete resource and effect. Updates that add permission require renewed consent, and rejection leads to an explicit degraded mode.

Architecture: kill switches, credential revocation, and broker denial live outside the model. The model may help classify risk and explain consent, but it is never the final authorization or isolation boundary.

06

Trade-offs and failure modes

  • Prompt-injection benchmark only: it misses code, network, and identity chains. Test forbidden flows end to end.
  • LLM judge decides safety: judge and agent share biases and cannot see OS effects. Critical oracles come from brokers and effect owners.
  • DLP catches everything: encoding and covert channels bypass it. Prefer not granting secrets and not allowing egress.
  • Hostname-only allowlist: redirects, DNS, and parser differences enable SSRF. Revalidate the real address at every hop.
  • Sandbox self-report: extension logs cannot prove isolation. Use external OS and network observation.
  • Canary watches task success only: rare security regressions average away. Track zero-tolerance gates separately.
  • Kill switch depends on catalog refresh: a hostile server can block refresh. Use an independent deny plane.
  • Revocation without compensation: new calls stop but completed effects remain. Put reconciliation and compensation in the incident runbook.
07

Reusable technical judgments

  • Extension security evaluation tests forbidden information flows across instructions, tools, sandboxes, networks, and effects.
  • Combine prompt injection, SSRF, secret exfiltration, confused deputy, TOCTOU, and supply-chain mutation in attack chains.
  • Critical oracles come from host, broker, OS, and effect owner, not extension or model self-report.
  • Shadow and canary rollout use zero-tolerance safety gates and first-divergence traces for rollback.
  • Kill switches, credential revocation, snapshot denial, and compensation runbooks remain independent of the model and compromised server.
