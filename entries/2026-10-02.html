Reliability 与 Safety 内核 · 第 1/4 篇

有 Trace，不等于你证明了 Agent 做对了

统一 runtime trace、offline eval 与 terminal verification 的 identity、claim、evidence、verdict 和 provenance 模型。

2026-10-02约 20 分钟Tracing / Evaluation / Verification / Evidence / Provenance
01

今日命题

trace 可以显示模型生成了什么、选了哪个 tool、调用耗时多久，却不能自动回答“这个行动正确吗”。一条 deploy span 成功结束，只证明 client 收到了某种成功结果；不证明目标 commit 已在 production、health checks 正常、审批覆盖了该版本，也不证明没有后续 rollback。相反，一个最终任务成功也不告诉我们中间是否发生过越权读取或侥幸恢复。

可靠系统需要区分 observation、claim、evidence 和 verdict。Observation 是发生过的 event/span；claim 是可判定断言，例如“commit C 已在 region R 健康”；evidence 是由特定 observer 在特定时间通过 query/test 获得的带 provenance 结果；verdict 是版本化 verifier 根据 evidence 和 policy 对 claim 的判断。Eval 使用同一结构比较 expected 与 observed，terminal gate 使用同一结构决定完成。

核心判断：observability 提供可调查性，evaluation 提供可比较性，verification 提供完成证据。三者共享 identity 和 evidence schema 才能互相复用；任何一个都不能单独替代另外两个。
02

承接 Runtime、Memory 与 Tools：证据必须穿过所有边界

Runtime 系列已建立 workflow/run/operation/call/attempt identity；Memory 系列建立 record version、source 和 valid time；Tools 系列建立 server/tool/schema/catalog/package snapshot。Reliability 不能另造一套 requestId 后丢失关联。一个 decision trace 要能回答：模型看了哪些 context records、基于哪个 prompt/model/version、选择了哪个 catalog snapshot 下的 tool、哪次 attempt 产生了哪个 effect、最终 verifier 查询了哪个 artifact/version。

这不意味着把所有 payload 复制到每个 span。Identity graph 保存 stable IDs 和 digests，敏感 payload 留在受控 evidence store；trace 只保存 pointer、classification、size 和 retention class。这样既能 replay 和 join，又避免 telemetry 成为第二个未授权数据湖。

证据还要区分 producer 与 observer。Tool 自报“文件已上传”是 producer statement；独立读取 object store 并核对 digest 才是 observer evidence。二者都可记录，但 verifier 应按 claim risk 规定所需独立性和 freshness。

03

机制：event、claim、evidence、verdict 的统一数据流

1. 统一 identity envelope

每个 event/evidence 继承 traceId、workflowId、runId，并按层附 decisionId、modelCallId、toolCallId、attemptId、artifactId/version、recordId/version、catalogSnapshotId。identity 必须稳定且不可由模型任意填写；跨 service 通过 W3C trace context 或显式 baggage/payload 传播，但 authorization identity 不能只靠可伪造 baggage。

2. Event 是 append-only observation

event schema 包含 eventId、type、occurredAt、recordedAt、producer、subject IDs、payload digest/pointer、schemaVersion、security classification。occurredAt 与 recordedAt 支持迟到事件。event 不写“成功”这种未定义结论，而写 ToolResultReceived、ArtifactUploaded、HealthCheckObserved 等可还原事实。

3. Claim 明确主语、谓词与范围

claim 包含 claimId、subject/version、predicate、scope、validAt、requiredEvidencePolicy。例如 “deployment d42 healthy” 必须绑定 environment、region、commit、最低 observation window。自然语言 goal 在 workflow 开始时编译成 claims；后续 scope 变化创建新 version，不改写旧 claim。

4. Observer contract

observer 声明 query/test code version、所需权限、source system、freshness window、sampling strategy 和可能的 blind spots。执行结果生成 evidence：observed value、status、source revision、observedAt、artifact digest、raw output pointer、observer identity/version。Observer failure 与 claim failure 分开；查不到不能自动判 false。

5. Evidence provenance 与 custody

evidence store 对高价值 artifact 做 content digest、immutable storage、access log、retention 和 redaction。衍生 summary/metric 链回 raw evidence。敏感内容在 telemetry 中 tokenized/pointerized；删除请求遵循来源/派生 lineage。证据被重新解析时产生新 derived evidence，不覆盖原始 bytes。

6. Verifier 产生三值 verdict

verifier 输入 claim、evidence set、policy/version，输出 pass、fail 或 unknown，以及理由、usedEvidence、missingEvidence、thresholds 和 expiresAt。unknown 用于 observer unavailable、evidence stale、sources conflict；不能为了完成率合并到 fail 或 pass。高风险 claim 可要求独立 observers 或 quorum。

7. Terminal gate

workflow 只有 required claims 全 pass、verdict 未过期、无 unresolved effects 才完成。fail 触发 bounded repair 或 compensation；unknown 触发 retry observer、等待或 human review。模型可以提出 evidence plan，却不能自行签发 verdict。完成 event 保存 verifier/version 与 evidence-bundle digest。

8. Offline eval reuse

eval fixture 定义 expected events/claims/evidence/verdict 或 forbidden events。Replay 用历史 snapshots 重建 decision，比较 first divergence。Trace-based eval 可测 tool selection、policy denial、citation、state transitions；但必须处理 logging absence——未记录不等于未发生，关键 effect 要有 independent observer。

9. Sampling 与 tail retention

普通低风险 traces 可 head/tail sampling，高风险 writes、authorization denies、outcome_unknown、verifier fail/unknown 强制保留。采样决策记录在 trace，指标按 known inclusion probability 校正。不能只保存成功例或只保存错误例，否则无法估 denominator 和 selection bias。

10. Schema/version evolution

events、claims、evidence、verifiers 分别版本化。Reader 支持旧 schema 或 deterministic upcaster；verifier 升级不重写历史 verdict，而产生新 evaluation revision。Dashboard 明示 verifier version，避免同一“pass rate”跨规则变化直接比较。

11. 安全与最小化

prompt、tool args/results 可能含 secrets/PII。默认存 digest、长度、classification 与受控 pointer；debug payload 需短期加密权限。Trace access 与 production data access 同级授权，跨 tenant join 禁止。Telemetry exporter 是 egress component，也必须 allowlist 和 DLP。

12. Failure attribution

统一 graph 允许定位 first divergence：context missing、model decision、tool validation、attempt transport、effect commit、observer、verifier 或 dashboard aggregation。每类有 owner 和 runbook。没有 identity join 的“日志搜索”只能找到相似时间文本，无法证明因果链。

04

必要数学：采样、置信与三值判断

采样估计

若事件 i 以已知概率 πᵢ 被保留，可用 Horvitz–Thompson 估计总量 T̂=Σ sampled yᵢ/πᵢ。yᵢ 可表示错误/成本。工程直觉：不同 risk tier 采用不同采样率时，直接数 retained errors 会偏向高保留类别；必须带 sampling metadata 校正。安全零容忍事件则不采样。

Verifier confidence

若 observer 重复独立采样 n 次，成功 k 次，简单比例 k/n 不是完整证据；要结合置信区间和 claim threshold。例如要求健康率≥0.99，却只有 2/2 样本，不能高置信 pass。系统应把样本量、window、分布与 correlation 写入 evidence，而不是只存平均值。

三值逻辑

claim verdict 采用 {true,false,unknown}。AND 聚合中，只要一个 false 则 false；无 false 但存在 unknown 则 unknown；全部 true 才 true。这避免 observer outage 被当失败，也避免缺证据被当成功。业务 policy 再决定 unknown 是等待、人工还是 fail closed。

05

对 Agent 系统的影响

开发：新增 tool、memory record、extension 或 verifier 时先定义 identity、claim 和 evidence contract。代码评审不只看日志是否存在，还看能否从 goal join 到 effect 和 independent observation。

运营：dashboard 分开 event rate、trace completeness、observer availability、evidence freshness、verdict pass/fail/unknown、repair convergence 与 unsupported completion。unknown 激增可能是观察面故障，不应误报业务失败。

产品：用户看到“已完成”时可以展开关键 claims 和 evidence freshness；manual review 显示缺什么证据，而不是神秘“需要人工”。审计导出引用 digests/pointers，避免复制所有敏感内容。

成本：全量 payload tracing 昂贵且危险。identity/digest 全量、payload 分级留存、high-risk evidence 强保留、低风险采样。成本模型包含 ingestion、storage、query joins、observer execution 和 verifier compute，而非只看 spans 数。

06

设计取舍与失败模式

  • span success=业务成功：transport acknowledgement 被当终态；用 external claim verifier。
  • 日志就是证据：producer 自报缺独立性；按风险要求 observer/source。
  • 所有 payload 全量：成本与隐私爆炸；digest/pointer/classification 和受控 evidence store。
  • 只采错误：无 denominator 且看不到成功路径；记录 sampling probability。
  • unknown 合并为 fail：观察面故障制造业务告警；三值 verdict 与独立 SLO。
  • verifier 改规则重写历史：审计不可复现；保留 revision 和旧 verdict。
  • trace baggage 当身份：可伪造 propagation 影响授权；身份来自可信 session/token。
  • dashboard 聚合漂移：join/version/window 改变却沿用指标名；metric contract/version 同样可审计。
07

可复用的技术判断

  • trace 记录 observation，claim 定义要证明的断言，evidence 带 observer/source/time，verifier 产生三值 verdict。
  • workflow/run/decision/call/attempt/artifact/record/catalog identities 必须可 join，但 authorization identity 不靠 trace baggage。
  • terminal completion 需要 fresh required claims 全 pass 且无 unresolved effects；模型不能自签 verdict。
  • offline eval 与 online verification 共享 evidence graph、snapshots 和 first-divergence。
  • telemetry 是敏感数据系统：最小化 payload、分级 retention、采样可校正、exporter 受 egress policy。

Reliability and Safety Internals · Part 1 of 4

A Trace Does Not Prove the Agent Was Correct

Unify runtime traces, offline evaluations, and terminal verification through identities, claims, evidence, verdicts, and provenance.

2026-10-0220 min readTracing / Evaluation / Verification / Evidence / Provenance
01

Today's proposition

A trace can show what a model generated, which tool it selected, and how long a call took. It cannot automatically answer whether the action was correct. A successful deploy span proves only that the client received a success-shaped result. It does not prove that commit C reached production, health checks passed, approval covered that revision, or no rollback followed. Conversely, eventual task success does not reveal an unauthorized read or lucky recovery during execution.

A reliable system separates observations, claims, evidence, and verdicts. An observation is an event or span that happened. A claim is a decidable assertion such as “commit C is healthy in region R.” Evidence is a provenance-bearing result obtained by a particular observer at a particular time through a query or test. A verdict is a versioned verifier's judgment over evidence and policy. Evaluations compare expected and observed using the same structure, while terminal gates use it to decide completion.

Core judgment: observability provides investigability, evaluation provides comparability, and verification provides completion evidence. They become reusable only when they share identities and evidence schemas. None replaces the other two.
02

Evidence must cross runtime, memory, and tool boundaries

The Runtime series established workflow, run, operation, call, and attempt identities. Memory added record versions, sources, and valid time. Tools added server, tool, schema, catalog, and package snapshots. Reliability cannot invent a separate request ID and lose those links. A decision trace must answer which context records the model saw, under which prompt, model, and version; which tool from which catalog snapshot it selected; which attempt created which effect; and which artifact and version the final verifier queried.

This does not require copying every payload into every span. An identity graph stores stable IDs and digests, while sensitive payloads remain in a controlled evidence store. Traces retain pointers, classifications, sizes, and retention classes. The system remains joinable and replayable without turning telemetry into a second unauthorized data lake.

Evidence also distinguishes producer from observer. A tool saying “file uploaded” is a producer statement. Independently reading object storage and checking the digest is observer evidence. Both are recorded, but the verifier specifies the independence and freshness required for the claim's risk.

03

Mechanism: a unified event, claim, evidence, and verdict flow

1. Use one identity envelope

Every event and evidence item inherits trace ID, workflow ID, and run ID, then adds decision ID, model-call ID, tool-call ID, attempt ID, artifact ID and version, memory-record ID and version, and catalog snapshot ID as appropriate. Identity is stable and not freely supplied by the model. Cross-service propagation may use W3C trace context and explicit baggage or payload, but authorization identity cannot depend on forgeable baggage.

2. Events are append-only observations

An event contains ID, type, occurrence time, recording time, producer, subject IDs, payload digest or pointer, schema version, and security classification. Separate occurrence and recording time supports late events. The event does not say vague “success”; it records ToolResultReceived, ArtifactUploaded, or HealthCheckObserved so later reasoning can reconstruct the facts.

3. Claims specify subject, predicate, and scope

A claim includes ID, subject and version, predicate, scope, valid time, and required-evidence policy. “Deployment d42 is healthy” binds environment, region, commit, and minimum observation window. A natural-language goal compiles into claims at workflow start. A scope change creates a new claim version rather than rewriting history.

4. Define observer contracts

An observer declares query or test code version, required permission, source system, freshness window, sampling strategy, and blind spots. Its evidence includes observed value and status, source revision, observation time, artifact digest, raw-output pointer, and observer identity and version. Observer failure differs from claim failure. Unable to query does not mean false.

5. Preserve provenance and custody

The evidence store uses content digests, immutable storage, access logs, retention, and redaction for important artifacts. Derived summaries and metrics link to raw evidence. Sensitive values become tokens or pointers in telemetry. Deletion follows source and derivative lineage. Re-parsing creates new derived evidence and never overwrites original bytes.

6. Verifiers produce three-valued verdicts

A verifier consumes claim, evidence set, and policy version and returns pass, fail, or unknown, with rationale, used and missing evidence, thresholds, and expiration. Unknown covers unavailable observers, stale evidence, and conflicting sources. It cannot be collapsed into pass or fail to improve completion. High-risk claims may require independent observers or quorum.

7. Gate terminal completion

A workflow completes only when every required claim passes, verdicts remain fresh, and no effect is unresolved. Fail triggers bounded repair or compensation. Unknown triggers observer retry, waiting, or human review. The model may propose an evidence plan but cannot issue the verdict. Completion records verifier version and evidence-bundle digest.

8. Reuse evidence in offline evaluation

An evaluation fixture defines expected or forbidden events, claims, evidence, and verdicts. Replay uses historical snapshots and compares first divergence. Trace-based evaluations measure tool selection, policy denial, citations, and state transitions. They must account for logging absence: not recorded does not mean not performed, so critical effects require independent observers.

9. Sample without destroying denominators

Ordinary low-risk traces may use head or tail sampling. High-risk writes, authorization denials, outcome unknown, and verifier fail or unknown are retained. Sampling decisions are recorded, and metrics adjust for known inclusion probability. Retaining successes only or errors only destroys denominators and introduces selection bias.

10. Evolve schemas and rules explicitly

Events, claims, evidence, and verifiers version independently. Readers support old schemas or deterministic upcasters. A verifier upgrade does not rewrite a historical verdict; it creates a new evaluation revision. Dashboards expose verifier version so pass rates under different rules are not compared as if identical.

11. Minimize and secure telemetry

Prompts, tool arguments, and results may contain secrets or PII. Store digest, length, classification, and controlled pointer by default. Debug payload access is encrypted, short-lived, and audited. Trace access follows production-data authorization and forbids cross-tenant joins. A telemetry exporter is an egress component and requires allowlists and DLP.

12. Attribute failures through the graph

The unified graph locates first divergence at missing context, model decision, tool validation, attempt transport, effect commit, observer, verifier, or dashboard aggregation. Each class has an owner and runbook. Searching logs by similar timestamps cannot prove causality when identities do not join.

04

Essential mathematics: sampling, confidence, and three-valued judgment

Sampling estimators

If event i is retained with known probability πᵢ, the Horvitz-Thompson estimator for a total is T̂=Σ sampled yᵢ/πᵢ, where yᵢ may indicate error or cost. The engineering lesson is that different retention rates by risk tier bias raw retained counts toward high-retention classes. Sampling metadata is required for correction. Zero-tolerance safety events are not sampled.

Verifier confidence

If an observer takes n repeated samples with k successes, k/n alone is incomplete evidence. It needs a confidence interval and claim threshold. Requiring health rate at least 0.99 cannot be established with high confidence from two successes out of two. Evidence records sample size, window, distribution, and correlation instead of storing only an average.

Three-valued logic

Claim verdicts use true, false, and unknown. Under AND aggregation, any false yields false; if none is false but at least one is unknown, the result is unknown; only all true yields true. This prevents observer outages from becoming claim failures and prevents missing evidence from becoming success. Business policy decides whether unknown waits, escalates, or fails closed.

05

Implications for agent systems

Development: when adding a tool, memory record, extension, or verifier, define identity, claim, and evidence contracts first. Code review asks not only whether logs exist, but whether a goal can join to its effect and independent observation.

Operations: dashboards separate event rate, trace completeness, observer availability, evidence freshness, pass, fail, and unknown verdicts, repair convergence, and unsupported completion. A spike in unknown may indicate observation failure rather than business failure.

Product: when users see completed, they can expand critical claims and evidence freshness. Manual review states which evidence is missing instead of saying mysteriously “human needed.” Audit exports reference digests and pointers rather than copying every sensitive payload.

Cost: tracing every payload is expensive and dangerous. Retain identity and digests broadly, payloads by classification, high-risk evidence strongly, and low-risk traces through sampling. Cost includes ingestion, storage, query joins, observer execution, and verifier compute, not span count alone.

06

Trade-offs and failure modes

  • Span success equals business success: transport acknowledgement becomes terminal truth. Use an external claim verifier.
  • Logs are evidence: producer self-report lacks independence. Require observer and source according to risk.
  • Retain every payload: cost and privacy explode. Use digests, pointers, classifications, and controlled evidence stores.
  • Sample errors only: denominators disappear and successful paths are invisible. Record inclusion probability.
  • Merge unknown into fail: observation outages become business incidents. Use three-valued verdicts and separate SLOs.
  • Rewrite history after verifier change: audits cannot reproduce. Preserve revisions and historical verdicts.
  • Trace baggage as identity: forgeable propagation influences authorization. Identity comes from trusted sessions or tokens.
  • Dashboard aggregation drift: join, version, or window changes under one metric name. Version the metric contract too.
07

Reusable technical judgments

  • Traces record observations, claims define assertions, evidence binds observer, source, and time, and verifiers issue three-valued verdicts.
  • Workflow, run, decision, call, attempt, artifact, record, and catalog identities must join, but authorization identity does not rely on trace baggage.
  • Terminal completion requires every fresh required claim to pass with no unresolved effect. The model cannot sign its own verdict.
  • Offline evaluation and online verification share evidence graphs, snapshots, and first-divergence analysis.
  • Telemetry is a sensitive data system: minimize payloads, tier retention, correct sampling, and govern exporters through egress policy.

09

What is established and where we continue

Established today: runtime events are observations; goals compile into versioned claims; observers create provenance- and freshness-bearing evidence; verifiers return pass, fail, or unknown. Online terminal gates and offline evaluations share an identity and evidence graph and use first divergence for attribution.

Still unresolved: when prompt injection causes a model to misuse a legitimate tool, how does the evidence model combine with authorization and isolation? How do data and instruction boundaries, taint propagation, least privilege, human approval, and output handling become an executable defense?
