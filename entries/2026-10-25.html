模型看对了按钮，Agent 为什么仍可能点错？

把视觉 grounding 拆成目标识别、坐标变换、动作授权与再次观测，解释动态 UI 中的误点和恢复。

01

今日命题

Agent 从截图正确认出‘保存’按钮，并给出点坐标 (810, 124)。执行器照此点击，却触发了旁边的‘删除’。视觉模型未必看错：截图可能被缩放或裁成 tile，坐标在处理后图像里；浏览器 CSS 像素与设备像素不同；弹窗在推理时移动；一个透明遮罩截获了点击。认出目标、定位目标、命中目标、完成意图，是四个不同事件。在有副作用的 UI 中，把前一个事件当作后三个的证明会出事故。

昨天建立了输入边界：原图可被缩放/裁剪/切 tile，视觉 encoder 与 LLM 之间有不同桥接路径，流畅描述不证明像素级定位。今天进入 Multimodal Agent Internals 2/3：从点、框、OCR 字形和 DOM 元素锚点出发，追踪坐标系与 observation→proposal→authorization→action→verification 闭环。第三篇再以静态 grounding、动态任务、安全和成本把整个专题验收。

核心判断：坐标不是权限，模型的高置信度也不是 UI 状态锁。安全的 computer-use Agent 必须在动作前定位并授权，在动作后重新观测和核对结果。
02

承接视觉 token 与 Agent runtime 的状态机

上一篇讲 patch 数和预处理时，重点是信息能否进入模型。今天假设模型已经看到了足够清楚的目标，却仍不能直接执行。视觉语言模型输出的‘左侧蓝色按钮’是语义描述；一个像素点或 bounding box 是几何假设；浏览器里的 DOM locator 是结构化锚点；真正的 click 是外部状态变更。四者可能互相辅助，但不能未经核对地互相替代。DOM 更有语义与可访问性线索，却可能缺席于远程桌面、canvas、视频或图片；像素路线更通用，却要处理遮挡、缩放与相似图标。

Agent runtime 早已需要工具 schema、权限、幂等和恢复。Computer use 在这些边界上再加一个感知—动作 race：从截图采集到点击之间，UI 可以变化。重试也不能盲目。第一次点下‘提交’后网络超时，状态未知时再点一次可能提交两次。外层控制器必须把模型输出当 proposal，维护观测版本、目标候选、动作风险级别与后置条件，才能决定继续、重观测、请求确认或停止。

03

机制：目标定位到闭环执行

1. 把 observation 变成带版本的对象

采集截图时保存时间、窗口或 tab ID、viewport CSS 尺寸、设备像素比、scroll offset、原图像素尺寸、裁块矩形和缩放策略。若可用，也保存 accessibility tree 或 DOM 中候选元素的 role、name 与 bounding rect。目标不是囤更多数据，而是让后来任何坐标都有可追溯的原始帧。截图中的网页文本仍是低信任输入；结构化 DOM 也可能由不可信页面控制，不能提升为系统指令。

2. 生成 target proposal，而非裸坐标

模型可以输出‘文本为保存的按钮’、点 (x,y)、框 (x1,y1,x2,y2) 或一个元素描述。提案应声明所用 observation ID、坐标帧、目标语义、候选置信信号和预期动作。若有两个‘保存’，仅凭 OCR 标签不够；可利用附近对话框标题、父区域、DOM role/name、视觉形状或多候选比较。SeeClick 与 CogAgent 等论文研究 GUI grounding 和 GUI agent 能力；它们的基准结果是作者报告，不等于任意企业应用的命中保证。

3. 统一坐标，再验证可点击性

执行器把模型在处理后 crop 中的点反变换回原截图，再映射到 viewport CSS 坐标或桌面坐标。若模型只给框，可在框内选稳定的可点击点，但要避免边界、遮罩与邻近危险控件。若能读取 DOM，可优先根据 role/name 和当前元素几何重新定位；它应匹配用户意图，不是把模型描述随便拼成 CSS selector。检查元素是否可见、启用、未被遮挡、页面仍是相同版本。没有 DOM 的 canvas/远程桌面则使用新截图复核像素位置。任何不确定都不应被‘高置信度’自动覆盖。

4. 按风险授权，执行一次并观察结果

普通打开菜单与删除记录、付款、发送消息属于不同风险级。外层 broker 根据用户范围、工具许可、目标和动作后果决定是否需要确认；模型不能用网页中的文本改变规则。执行后读取新的截图/DOM/服务端状态，验证后置条件：菜单是否出现、文件是否真的删除、消息是否只发送一次。若点击超时，先查询真实状态；无法确定时停住并请求人工或更高权限流程，不盲目重复不可逆动作。只有可证明幂等的动作才可按其幂等键安全重试。

5. 动态 UI 需要重定位而不是沿用旧点

滚动、缩放、动画、弹窗、响应式断点和异步数据都能在截图后改变目标位置。可设置短暂的 observation 有效期，并在动作前检查窗口/元素几何或重新截图；这不是绝对的事务锁，race 仍可能发生。真正点击后还必须验证语义结果，而非只确认鼠标事件发出。Set-of-Mark 提示给可见元素叠编号可帮助某些模型指向候选，但编号仍依赖当时画面，不能代替新状态和授权检查。

04

必要数学：一个点跨过几套坐标系

设原始截图中一个 crop 的左上角为 (cₓ,cᵧ)，crop 宽高为 (C_w,C_h) 个截图像素；送入模型的处理后图宽高为 (P_w,P_h)。模型在处理后图上给点 (u,v)，且缩放是无旋转、无 padding 的线性缩放，则原截图像素位置为 x_s=cₓ+u·C_w/P_w，y_s=cᵧ+v·C_h/P_h。c 是 crop 偏移，比例把处理后坐标反投到原 crop。若预处理有 letterbox padding，应先减去 padding，再除真实内容区域的缩放；若旋转或透视变换则要完整变换矩阵。保存变换链比事后猜像素尺度可靠。

若原截图只覆盖浏览器 viewport，设备像素比为 d，且截图像素与 CSS viewport 左上角对齐、浏览器缩放已体现在 d 中，则 x_css=x_s/d，y_css=y_s/d。文档坐标再加 scrollX/scrollY。此处 d 是截图像素对 CSS 像素的实际比例，不应未经核验地等同操作系统 UI 缩放设置；浏览器 chrome、桌面窗口原点、远程桌面缩放还会引入偏移。执行器应以实际元数据/DOM 几何校准，而非把这些简化式套到所有环境。

如果目标框宽 w、高 h，点误差为 (δₓ,δᵧ)，安全落点至少要满足 |δₓ|<w/2−m，|δᵧ|<h/2−m，m 是留给边框、邻近控件和几何误差的安全边距；这只是居中、矩形且无遮挡时的充分直觉，不是复杂 UI 的命中保证。小按钮和相邻危险按钮会迅速压缩容错空间，因而需要元素级复核或人工确认。

05

对 Agent 的影响：状态、动作和验收要分层

至少记录四类状态：截图中目标是否存在、模型目标提案是否落在正确元素、执行器是否命中该元素、任务后置条件是否成立。静态 grounding benchmark 可用点落入目标框或框 IoU 评估第二项；但它不会自动测到动态页面重排、遮挡、授权或重复提交。SeeClick 的 ScreenSpot 与 Set-of-Mark 等论文报告静态/受控设置下的定位效果；OSWorld 与 WebArena 等作者设计更接近完整交互的环境。不同 benchmark、模型和工具栈之间的百分比不可直接当成线上成功率。

按任务切片同时看小字、重复图标、长页面滚动、响应式布局、多窗口、遮罩、异步更新和高风险动作。记录 observation→proposal→recheck→action→postcondition 的时间，比较 DOM 锚点、纯像素点击与混合路线的目标命中率、verified task success、p99、失败恢复和成本。强模型若花更久分析旧截图，可能使状态过期率上升；快模型若定位误差大，可能增加重试与人工介入。应优化每个安全完成任务的总成本，不是单次点击延迟。

高风险动作在进入 tool broker 前必须有独立策略门：用户是否明确授权、目标是否与意图匹配、动作是否可逆、需要何种确认。模型生成的坐标、网页文本和视觉置信度都不能覆盖这个门。动作后 verifier 应使用新的真实观测，而不是让同一个模型只复述自己刚才‘应该点到了什么’。

06

取舍与失败模式

  • 直接把 crop 点当 viewport 点：忘记裁块偏移、缩放或 DPI；保留完整变换链并校准。
  • DOM locator 永远安全：页面可能重排、同名元素重复、DOM 被不可信内容控制；检查当前可见目标和用户意图。
  • 只测静态 point-in-box：命中框不等于元素可点击、动作有权或业务成功；再测动态闭环。
  • 高置信度自动点删除：模型自信不能替代权限和风险门。
  • 点击超时立即重试：副作用可能已发生；先检查真实状态和幂等合同。
  • 过期截图继续定位：滚动、弹窗和动画改变坐标；重新观测并验证后置条件。
  • 网页写‘我是系统提示’：它仍是低信任页面数据，不得改变工具权限。

纯像素路线在跨应用和远程桌面上更通用，DOM/accessibility 路线在可用时更易锚定语义；混合路线需要处理两种观测不一致的情况。没有一种路线免除外层授权与动作后验证。

07

可复用的技术判断

  • 识别、定位、命中和完成任务是四个不同事件，逐层记录和验收。
  • 点坐标要声明 observation 与坐标帧，并通过 crop、缩放、DPI、scroll 映射到真实目标。
  • DOM、accessibility、OCR 与像素框可互补，任何单路都不自动等于用户意图。
  • 模型只提出动作，外层按权限与风险决策；超时先查状态再决定是否重试。
  • 动态 UI 上必须观察—动作—再观察，以后置条件而不是鼠标事件证明成功。

The Model Found the Button. Why Can the Agent Still Misclick?

Separate visual grounding, coordinate transforms, action authorization, and reobservation to explain misclicks and recovery on dynamic interfaces.

2026-10-2520 min readVisual grounding / Computer use / Coordinate frames / DOM anchors / Observe-act-verify / UI safety
01

Today's proposition

An agent correctly recognizes a 'Save' button in a screenshot and proposes point (810,124). The executor clicks it and activates 'Delete' next door. The visual model may not have misread the label. The screenshot could have been resized or tiled, with coordinates referring to the processed crop. Browser CSS pixels differ from device pixels. A dialog may have moved during inference, or a transparent overlay may intercept the click. Recognizing a target, localizing it, hitting it, and achieving the intended result are four different events. In a side-effectful interface, treating the first as proof of the other three is dangerous.

Yesterday established the input boundary: the original image can be resized, cropped, or tiled; vision and language connect through different bridge designs; and fluent description does not prove pixel-level localization. Multimodal Agent Internals Part 2 now follows points, boxes, OCR glyphs, and DOM element anchors through coordinate frames and an observation → proposal → authorization → action → verification loop. Part 3 will evaluate static grounding, dynamic tasks, safety, and cost across the series.

Core judgment: a coordinate is not permission, and model confidence is not a lock on UI state. A safe computer-use agent localizes and authorizes before acting, then reobserves and checks the result.
02

Connecting visual tokens to the agent runtime

Part 1's patch-count and preprocessing discussion asked whether information reached the model. Now assume the model saw a clear target; that still does not authorize execution. 'The blue button on the left' is a semantic description. A point or bounding box is a geometric hypothesis. A browser DOM locator is a structured anchor. A click is an external state transition. These can support one another but cannot be substituted without checking. DOM provides semantics and accessibility cues but may not exist for a remote desktop, canvas, video, or an image. Pixels are more general but face occlusion, scaling, and visually similar icons.

An agent runtime already needs tool schemas, permission, idempotency, and recovery. Computer use adds a perception-to-action race: the UI can change between capture and click. Retrying is not automatically safe. If the first click on 'Submit' succeeded but the network timed out, clicking again may duplicate the action. The outer controller treats model output as a proposal and retains observation version, target candidates, action risk, and postconditions. It can then choose to proceed, reobserve, request confirmation, or stop.

03

Mechanism: from target grounding to closed-loop execution

1. Make the observation a versioned object

At capture, retain time, window or tab ID, viewport CSS size, device pixel ratio, scroll offset, original image-pixel dimensions, crop rectangles, and resize policy. If available, retain candidate roles, accessible names, and bounding rectangles from a DOM or accessibility tree. The purpose is not to hoard data; it is to give every later coordinate a traceable source frame. Text inside a screenshot is lower-trust page data. Structured DOM content can also be controlled by an untrusted page and cannot become a system instruction.

2. Produce a target proposal, not a naked coordinate

The model may return 'button labeled Save,' point (x,y), box (x1,y1,x2,y2), or an element description. A proposal should name its observation ID, coordinate frame, target semantics, candidate confidence signal, and intended action. If two controls say Save, OCR text alone is insufficient. Compare the nearby dialog title, parent region, DOM role and name, visual appearance, or alternative candidates. SeeClick and CogAgent study GUI grounding and agent capabilities. Their benchmark results are author reports, not hit-rate guarantees for arbitrary enterprise applications.

3. Map coordinates and recheck clickability

The executor inverse-transforms a point from a processed crop into the original screenshot, then maps it to viewport CSS or desktop coordinates. If the model gives a box, choose a stable point inside it while avoiding borders, overlays, and adjacent hazardous controls. When DOM is available, re-find an element by role, name, and current geometry. The locator must match the user's intent; do not concatenate the model's prose into an arbitrary CSS selector. Check visibility, enabled state, occlusion, and whether the page is still the observed version. Canvas or remote desktop may lack DOM, so use a fresh screenshot to recheck the pixel target. A high model confidence cannot override unresolved ambiguity.

4. Authorize by risk, act once, and inspect the result

Opening a menu differs from deleting a record, paying, or sending a message. The outer broker uses user scope, allowed tools, target, and consequence to decide whether confirmation is required. Page text cannot rewrite those rules. After acting, obtain a new screenshot, DOM state, or server-side state and verify the postcondition: did the menu appear, was the file deleted, was the message sent exactly once? If a click times out, query real state first. If still uncertain, stop for human or higher-authority recovery instead of blindly replaying an irreversible action. Only provably idempotent actions may be retried under their idempotency key.

5. Dynamic UIs require relocalization

Scrolling, zoom, animation, modals, responsive breakpoints, and asynchronous data can move a target after capture. Set a short observation validity interval and recheck the window and element geometry, or capture again, before acting. This is not a transaction lock; a race remains possible. Verify the semantic result after clicking rather than only that a mouse event was dispatched. Set-of-Mark prompting overlays numbers on visible elements and can help some models identify candidates, but the marks refer to that particular view. They do not replace fresh state or authorization.

04

Essential mathematics: a point across coordinate frames

Let a crop's top-left corner in the original screenshot be (cₓ,cᵧ), with crop width and height (C_w,C_h) in screenshot pixels. The image sent to the model is (P_w,P_h) after processing. If the model proposes point (u,v) in the processed image and preprocessing is linear scaling without rotation or padding, its original screenshot coordinates are x_s=cₓ+u·C_w/P_w, y_s=cᵧ+v·C_h/P_h. c is crop offset; the ratios invert the scaling. For letterbox padding, first remove the padding and divide by the scale of the actual content area. Rotation or perspective needs a full transform matrix. Recording the transform chain beats reconstructing scales afterward.

If the screenshot covers only a browser viewport, device-pixel ratio is d, screenshot pixels align with the top-left of the CSS viewport, and browser zoom is represented in d, then x_css=x_s/d, y_css=y_s/d. Document coordinates add scrollX and scrollY. Here d is the measured screenshot-pixel to CSS-pixel ratio, not automatically the operating system's UI scale setting. Browser chrome, desktop window origin, and remote-desktop scaling introduce additional offsets. Calibrate with actual metadata or DOM geometry instead of applying these simplified formulas to every environment.

For a rectangular target of width w and height h, with point errors (δₓ,δᵧ), a central click has an intuitive safety condition |δₓ|<w/2−m, |δᵧ|<h/2−m. Margin m allows for borders, neighbors, and geometry uncertainty. This is only a sufficient intuition under a centered, axis-aligned, unobscured target, not a hit guarantee for a complex UI. Tiny buttons and nearby destructive controls quickly remove error tolerance, motivating element-level checks or human confirmation.

05

Agent implications: layer state, action, and acceptance

Track at least four states separately: was the target present in the screenshot; did the model proposal identify the right element; did the executor actually hit that element; and did the task postcondition hold? A static grounding benchmark can score point-in-box or box intersection-over-union for the second state. It does not automatically measure dynamic reflow, occlusion, authorization, or duplicate submission. SeeClick's ScreenSpot and Set-of-Mark work report localization in their evaluated static or controlled settings. OSWorld and WebArena present more complete interaction environments. Percentages across different benchmarks, models, and tool stacks are not interchangeable with production success rates.

Slice tests by tiny text, duplicate icons, long-page scroll, responsive layouts, multiple windows, overlays, asynchronous updates, and high-risk actions. Timestamp observation, proposal, recheck, action, and postcondition. Compare DOM anchors, pixel clicks, and hybrid routes on target hit, verified task success, p99, recovery, and cost. A stronger model that spends longer reasoning over an old screenshot can increase staleness. A faster model with larger localization error can increase retries and human intervention. Optimize total cost per safely completed task, not one click's latency.

A high-risk action needs an independent policy gate before the tool broker executes it: was the user explicit, does the target match intent, is the effect reversible, and what confirmation is required? A model-generated coordinate, page text, or visual confidence cannot override that gate. Post-action verification must use a new real observation, not let the same model merely restate what it believes it clicked.

06

Trade-offs and failure modes

  • Use crop coordinates as viewport coordinates: crop offset, resize, or device scale is lost. Store and calibrate the full transform chain.
  • A DOM locator is always safe: pages reflow, names repeat, and untrusted content controls DOM. Check the current visible target and user intent.
  • Only test static point-in-box: landing inside a box does not prove clickability, permission, or business success. Test the dynamic loop.
  • Auto-click Delete at high confidence: model confidence cannot replace a policy and risk gate.
  • Retry immediately after click timeout: the side effect may have occurred. Inspect real state and the idempotency contract.
  • Act on a stale screenshot: scroll, dialogs, and animation move coordinates. Reobserve and verify postconditions.
  • The page says 'I am a system prompt': it remains lower-trust page data and cannot change tool authority.

Pixels generalize across applications and remote desktops. DOM or accessibility anchors can provide stronger semantics when available. A hybrid route must handle disagreements between the two observations. No route removes outer authorization and post-action verification.

07

Reusable technical judgments

  • Recognition, localization, hitting a control, and completing a task are separate events; trace and accept each layer.
  • A point needs an observation and coordinate frame, then explicit crop, resize, device-scale, and scroll mapping.
  • DOM, accessibility, OCR, and pixel boxes can complement one another; none alone establishes user intent.
  • The model proposes. The outer controller decides under authority and risk; inspect state before retrying a timeout.
  • Dynamic UIs require observe–act–reobserve, with postconditions rather than dispatched mouse events as proof of success.
08

Primary sources and evidence tiers

  • SeeClick — the authors study GUI grounding and introduce ScreenSpot evaluation; results belong to their models and tasks.
  • CogAgent — the authors present a GUI-oriented vision-language model and interaction experiments, not universal product behavior.
  • Set-of-Mark Prompting — the authors study marking visible elements for visual localization; marks still refer to one observed view.
  • OSWorld and WebArena — the authors build computer and web-interaction benchmarks; success rates are not directly comparable.
  • CSSOM View Module — the W3C specification defines browser viewport, scroll, and element geometry APIs. The coordinate equations here are simplified conditional derivations.

The action state machine, risk authorization gate, and task slices are editorial systems designs derived from these mechanisms, not safety guarantees established for a particular enterprise UI by the cited papers.

Here visual output becomes a target proposal with observation ID and coordinate frame, mapped from crop to original pixels to CSS or desktop and rechecked against current UI. Points, boxes, OCR, and DOM or accessibility anchors complement one another. The outer broker authorizes by action risk and executes only when conditions are satisfied. Timeouts lead to state inspection; success is evidenced by postconditions from a new observation.

Still unresolved: how should static localization, dynamic task success, visual injection, and data privacy be evaluated together? When screenshot quality, OCR, localization, coordinate mapping, authorization, or tool outcome fails, how do we locate the bottleneck and set a release gate?

Next starting point: Multimodal Agent Internals Part 3/3 builds end-to-end evaluation and safety gates, from perception slices and interaction recovery to injection, privacy, verified outcomes, and cost, without repeating today's coordinate equations.
